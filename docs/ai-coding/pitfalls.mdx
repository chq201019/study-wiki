# 验证与快速排错

提示词写得再好，agent 的产出也永远要过一遍验证——好消息是这件事有固定套路，按本页清单走只需几分钟。**原则一句话：编译和测试让 agent 自己跑，手册核对和上机由你做。**

## 1. 十秒核对清单

每次验收 agent 的 diff，按这张表过一遍（最后一列是"它最常犯的错"）：

| 核对项 | 看哪里 | 常见问题 |
| --- | --- | --- |
| API 真的存在于当前版本？ | 编译输出 | 旧版本写法（如 arduino-esp32 2.x 的 `ledcSetup`） |
| 新增的 `#define` 有依据？ | diff 的宏定义段 | 为凑编译自己编寄存器值 |
| 寄存器名/命令字/地址对得上手册？ | 逐个对照数据手册 | 张冠李戴（把同类芯片参数安过来） |
| 电气参数（电阻/电压/时序）有出处？ | 手册 | "语料平均值"，看着像但不对 |
| 错误路径没被绕过？ | 错误处理分支 | 吞错误、改恒真、注释失败测试 |
| diff 范围没越界？ | `git diff` 文件列表 | 顺手改了任务书没提的文件 |

第一行和最后一行能机械核对——编译器和 `git diff` 会直接告诉你；中间四行必须你亲自看——这是整页里唯一没法再自动化的部分。

## 2. 三层闸门：谁验什么

```mermaid
flowchart LR
  A[agent 产出] --> B[① 编译/测试<br/>agent 自己跑]
  B --> C[② 手册核对<br/>你，几分钟]
  C --> D[③ 上机<br/>你，真实硬件]
  D --> E[读懂 diff 后提交]
```

- **① agent 自验**：任务书里写清验收命令（`pio run`、测试脚本），它会自己迭代到通过。你只抽查一件事：**它没有作弊**（对照上面清单第 5 行）
- **② 手册核对**：寄存器、命令字、电气数字——agent 能替你翻 PDF（[工作流页](./workflow)要求它标注出处），但你抽查几条关键值，成本几分钟
- **③ 上机**：编译和手册都管不了真实世界的波形、电流、传感器脾气

**上机安全顺序**（agent 代码出错概率比人手写高，别裸接真负载）：先**空载**量引脚波形 → 再串 100Ω **限流**试 → 最后正式连接。GPIO 反向、时钟配错这类问题在第一级零成本拦住。

## 3. 卡住了怎么排错

| 现象 | 下一步 |
| --- | --- |
| agent 反复"修好"但同个问题复发 | 它在错误假设上叠补丁——打断："先设计实验区分假设 A/B，再改" |
| 它的方案和本站教程/手册矛盾 | 手册为准；把矛盾点贴回去让它对照重答 |
| 连续三轮不收敛 | 喊停，`git reset` 回上一个提交，任务拆成更小的片重派 |
| 它说"应该可以了"但没给证据 | "把编译输出和测试结果贴出来"——要证据不要形容词 |

## 常见坑

| 坑 | 解法 |
| --- | --- |
| 只看 agent 总结不看 diff | diff 即事实，逐行过 |
| 数字参数直接采用 | 电阻/电压/时序数字一律对手册 |
| 学习期让它全包 | 任务书写"陪练条款"（[任务书页 §5](./prompting)） |
| 安全相关代码（电池保护、急停）也交给它 | 人工手写 + 冗余保护 |
| 出问题分不清谁的锅 | 提交信息注明"agent 起草，人工核对" |
