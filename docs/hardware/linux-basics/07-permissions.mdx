# 07 权限与属主

**本课目标**：彻底搞懂 `rwx`，会用 `chmod`、`chown`、`umask`。

## 权限的三组

```text
-rwxr-xr--
 │└┬┘└┬┘└┬┘
 │ │  │  └─ 其他人（other）权限
 │ │  └─ 所属组（group）权限
 │ └─ 所有者（user/owner）权限
 └─ 文件类型
```

**每组三个字符，顺序固定：`r` `w` `x`。**

| 字符 | 含义 | 对文件 | 对目录 |
| --- | --- | --- | --- |
| `r` | read | 读取内容 | **列出内容**（`ls`） |
| `w` | write | 修改内容 | **创建/删除文件** |
| `x` | execute | 作为程序执行 | **进入目录**（`cd`） |
| `-` | 无此权限 | —— | —— |

:::danger[`rwx` 对目录的含义和文件完全不同]
**这是最容易搞错的地方**：

| 对文件 | 对目录 |
| --- | --- |
| `r` = 读内容 | `r` = 能看到里面有哪些文件 |
| `w` = 改内容 | `w` = 能在里面创建/删除文件 |
| `x` = 能执行 | `x` = **能进入（`cd`）和访问里面的文件** |

**注意：删除文件看的是"目录的 w"，不是文件自己的权限。**
:::

## 实测：目录只有 `r` 没有 `x` 会怎样

本机实测（用 `nobody` 用户测试）：

```bash
chmod 600 d          # 有 r 无 x
```

结果：

```text
ls: 无法打开目录 '/tmp/lp2/d': 权限不够
cat: /tmp/lp2/d/inside: 权限不够
```

:::warning[有 `r` 没 `x`：能看名字，但进不去]
`r` 让你能**列出目录里有啥**，`x` 让你**能穿过目录去访问内部文件**。

**只有 `r`**：`ls` 理论上能列出名字，但 `ls` 默认还要读文件属性（需要 `x`），所以报错。

**只有 `x`（`chmod 100`）**：`ls` 失败（列不出名字），但**如果你知道文件名，可以访问它**。

实测验证了这个：

```text
chmod 100 d
ls /tmp/lp2/d          → 权限不足
cat /tmp/lp2/d/inside  → 权限不足（因为文件本身是 root 600）
```

（文件本身权限也要够。）
:::

## `chmod`：改权限

### 数字写法

**把 `rwx` 转成数字**：

| 权限 | 二进制 | 数字 |
| --- | --- | --- |
| `---` | 000 | **0** |
| `--x` | 001 | **1** |
| `-w-` | 010 | **2** |
| `-wx` | 011 | **3** |
| `r--` | 100 | **4** |
| `r-x` | 101 | **5** |
| `rw-` | 110 | **6** |
| `rwx` | 111 | **7** |

**三组各一个数字**：

```bash
chmod 644 file      # rw-r--r--
chmod 755 file      # rwxr-xr-x
chmod 600 file      # rw-------
chmod 777 file      # rwxrwxrwx
```

本机实测：

```bash
chmod 644 f  →  -rw-r--r-- 
chmod 755 f  →  -rwxr-xr-x
```

:::tip[三个常用值记牢]
| 值 | 权限 | 用于 |
| --- | --- | --- |
| **644** | `rw-r--r--` | **普通文件**（自己可写，别人只读） |
| **755** | `rwxr-xr-x` | **可执行文件、目录** |
| **600** | `rw-------` | **私密文件**（只有自己能看） |
:::

### 符号写法

```bash
chmod u+x file          # 给所有者加执行
chmod g-w file          # 去掉组的写
chmod o-r file          # 去掉其他人的读
chmod a+r file          # 所有人加读（a = all）
chmod u+x,g-w,o-r file  # 组合
chmod -R 755 dir        # 递归改整个目录
```

| 符号 | 含义 |
| --- | --- |
| `u` | 所有者（user） |
| `g` | 组（group） |
| `o` | 其他人（other） |
| `a` | 所有人（all） |
| `+` `-` `=` | 添加 / 移除 / 设为 |

本机实测：

```bash
chmod u+x,g-w,o-r f  →  -rwxr-x--x
```

## `chown`：改所有者

```bash
chown user file                 # 改所有者
chown user:group file           # 同时改组
chown -R user:group dir         # 递归
```

:::danger[改所有者通常要 root]
普通用户不能把自己的文件"送"给别人（防止恶意占空间）。

```bash
chown other file
# chown: changing ownership: 不允许的操作
```

**只有 root 能任意改所有者。**
:::

## `umask`：新建文件的默认权限

:::info[新建文件不是 777]
```bash
touch newfile       # 实际权限是 644，不是 777
mkdir newdir        # 实际是 755，不是 777
```

**因为 `umask` 会"扣掉"一部分权限。**
:::

:::tip[`umask` 的设置是"要屏蔽的位"]
```bash
umask 022           # 屏蔽 022
```

- 文件基础权限 `666` → `666 - 022 = 644`
- 目录基础权限 `777` → `777 - 022 = 755`

**注意是"按位与非"关系**：实际权限 = 基础权限 & ~umask。
:::

本机实测：

```bash
umask 022
touch u1  →  -rw-r--r--      (644)
mkdir ud1 →  drwxr-xr-x      (755)

umask 077
touch u2  →  -rw-------      (600)
mkdir ud2 →  drwx------      (700)
```

### 常用 umask

| umask | 文件 | 目录 | 场景 |
| --- | --- | --- | --- |
| `022` | 644 | 755 | **默认，共享环境** |
| `077` | 600 | 700 | **私有，安全** |
| `002` | 664 | 775 | 团队协作（同组可写） |

:::warning[`umask` 只影响"新建"的文件]
```bash
umask 077
touch a             # a 是 600
umask 022
touch b             # b 是 644
# a 的权限不会因为改 umask 而变化
```

（[Linux 进阶第 2 课](../linux/shell)也提过这点。）
:::

### 永久设置 umask

```bash
# 加到 ~/.bashrc
echo "umask 077" >> ~/.bashrc
```

## 特殊权限位

本机实测：

```bash
chmod 4755 s  →  -rwsr-xr-x        ← setuid（s 在所有者 x 位）
chmod 2755 s  →  -rwxr-sr-x        ← setgid（s 在组 x 位）
chmod 1777 d  →  drwxrwxrwt        ← sticky（t 在其他人 x 位）
```

| 位 | 数字 | 显示 | 作用 |
| --- | --- | --- | --- |
| **setuid** | 4000 | `s` | 执行时**以文件所有者身份**运行 |
| **setgid** | 2000 | `s` | 以文件所属组身份运行（目录：新文件继承该组） |
| **sticky** | 1000 | `t` | 目录里**只有文件主能删自己的文件** |

:::danger[setuid 是安全敏感点]
```bash
chmod 4755 /usr/bin/passwd
```

`passwd` 需要修改 `/etc/shadow`（只有 root 能写）。但它有 setuid 位，**普通用户执行时会以 root 身份运行**，所以能改密码。

**风险**：如果 setuid 程序有漏洞，攻击者可以借此提权。

**规矩**：

- 不要随便给程序加 setuid
- 定期检查系统里的 setuid 文件
:::

:::tip[`/tmp` 的 sticky 位]
```bash
ls -ld /tmp
# drwxrwxrwt  ... /tmp
```

`/tmp` 人人可写（`w`），但有 `t` 位——**你不能删别人的临时文件**。

没有 sticky 位的话，任何用户都能删掉别人的文件。
:::

## 完整示例

```bash
# 建一个练习目录
mkdir -p ~/permtest && cd ~/permtest

# 创建一个脚本
cat > hello.sh << 'EOF'
#!/bin/bash
echo "Hello from script"
EOF

# 默认没有执行权限
ls -l hello.sh          # -rw-r--r--

# 直接运行会失败
./hello.sh              # Permission denied

# 加执行权限
chmod u+x hello.sh
ls -l hello.sh          # -rwxr--r--

# 现在能跑了
./hello.sh

# 数字写法等价于
chmod 744 hello.sh
```

:::tip[为什么脚本需要 `x`]
`./hello.sh` 是"执行这个文件"，**必须有 `x` 权限**。

另一种跑法是 `bash hello.sh`——这是"用 bash 读这个文件"，只需要 `r` 权限。

**两者区别**：`./hello.sh` 看你写的 shebang（`#!/bin/bash`），`bash hello.sh` 强制用 bash。
:::

## 常见错误

| 错误 | 现象 | 原因 | 解决 |
| --- | --- | --- | --- |
| 脚本没 `x` | Permission denied | 没执行权限 | `chmod u+x` |
| 目录没 `x` | 无法 cd / 访问文件 | 缺穿越权限 | `chmod +x` |
| 用 `chmod 777` 图省事 | 安全问题 | 所有人都能改 | 按需最小权限 |
| 以为删文件看文件权限 | 删不掉/能删掉 | 看**目录**的 `w` | 检查目录权限 |
| `chmod 644` 用在目录上 | 进不去 | 目录要 `x` | 用 755 |
| 改 umask 后旧文件没变 | 权限没变 | 只影响新建 | 手动 `chmod` |

:::danger[`chmod -R 777` 是坏习惯]
```bash
chmod -R 777 /var/www        # ❌ 所有人都能改网站文件
```

**问题**：

1. 任何用户都能篡改（安全风险）
2. **可执行位被打开了**（任何文件变成可执行）
3. 掩盖了真正的权限问题

**正确做法**：搞清楚"谁需要什么权限"，给最小够用的。

网站目录常见配置：

```bash
chown -R www-data:www-data /var/www
chmod -R 755 /var/www
chmod -R 644 /var/www/*.html
```
:::
