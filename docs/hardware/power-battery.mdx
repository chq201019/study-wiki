# 供电、电池与低功耗

电池项目里 80% 的「程序跑飞」都是电源问题，而电源问题在万用表上看不出来 ——
平均电压正常，但示波器上一看，3.3V 轨上有 400mV 的凹陷。

## 锂电基础：能用的只有 3.0–4.2V

| 电池 | 标称 | 满电 | 截止 | 典型容量 |
|---|---|---|---|---|
| 18650（圆柱） | 3.7V | 4.2V | 3.0V | 2000–3500 mAh |
| 聚合物 602030（扁） | 3.7V | 4.2V | 3.0V | 500–1200 mAh |
| 锂聚合物 1S 航模 | 3.7V | 4.2V | 3.5V（大电流放电） | 300–2000 mAh |

四件事绝不能做：

1. **过充**超 4.25V —— 鼓包、起火。
2. **过放**低于 2.5V —— 容量永久损失，之后内阻变大。
3. **反接** —— 保护板来不及动作，直接烧模块。
4. **无保护板裸接** —— 短路电流能到几十安。

买 18650 认准带保护板的型号（正极一头多一小块 PCB，长度多 2–3mm，电池仓要留够）。

## TP4056：最常用的单节充电模块

| 参数 | 值 | 说明 |
|---|---|---|
| 输入 | 4.5–5.5V（USB 5V） | 模块自带的 Micro-USB / Type-C 口 |
| 充电电流 | 默认 1A | 由 R_prog 决定，I = 1200 / R_prog(kΩ) |
| 充满电压 | 4.2V ± 1% | 固定，不可调 |
| 充电模式 | 先恒流，到 4.2V 转恒压 | 恒压阶段电流指数衰减 |
| 指示灯 | 红=充电中，蓝=充满 | 部分模块是 CHRG / STDBY 两个丝印 |
| 过放保护 | **无** | 靠电池自带的保护板 |

两个必须知道的细节：

**改充电电流**：R_prog 是模块背面一颗 0805 电阻。换 2kΩ → 600mA，换 10kΩ → 120mA。
给 500mAh 的聚合物充电用 1A 是在虐待它，按 0.5C（250mA）配。

**TP4056 没有负载均衡。** 它只有一组 B+/B- 输出，同时接电池和负载时，充电电流会被负载分走，
芯片会误判「快充满了」并提前结束充电。正确做法是**充电时断开负载**（加拨动开关），
或者用带独立 LOAD 输出的模块（IP5306、TP5400）。

**TP4056 的 BAT 输出不能直接喂 ESP32。** 满电 4.2V 超过 ESP32 的 3.6V 绝对最大值，必须降压。

## 降压：LDO 还是 DC-DC

| | LDO（AMS1117-3.3 / ME6211） | DC-DC 降压（MP1584 / TPS63020） |
|---|---|---|
| 效率（4.2V→3.3V） | 约 65–75% | 85–92% |
| 静态电流 | 5mA（AMS1117）/ 40µA（ME6211） | 1–10mA（多数成品模块） |
| 输出纹波 | 极低（µV 级） | 20–50mV 开关纹波 |
| 外围元件 | 2 个电容 | 模块上 6–10 个元件 |
| 压差要求 | ≥ 1V（1117） | 无所谓 |
| 发热 | 压差 × 电流全部变热 | 很小 |

**算一下 AMS1117 的热**：电池 4.0V，输出 3.3V，负载 250mA（WiFi 发射时）：
(4.0 − 3.3) × 0.25 = 0.175W。SOT-223 的热阻约 60°C/W，温升 10°C —— 能接受。
换成 500mA 就是 0.35W、温升 21°C，夏天密闭外壳里已经烫手。

**选型规则**：

- 平均电流 < 100mA 且要 deep sleep → **ME6211** 这类低压差、低静态电流的 LDO。
  AMS1117 的 5mA 静态电流会把 10µA 的睡眠电流变成 5mA，续航直接崩掉几百倍。
- 平均电流 > 200mA 或需要长续航 → **DC-DC**，但要查它的静态电流。
  多数成品 MP1584 模块静态电流 2mA 以上，同样毁掉低功耗设计。
- 既要低功耗又要大电流 → TPS62840 / TPS63020，贵，静态电流只有几百 nA。

**电池电压检测**：别用固定分压直接接 ADC。100k+100k 分压会持续漏 21µA，
比 deep sleep 电流大一倍。在分压底部串一个 MOS 管，不测的时候断开。

## 电流账：ESP32 实测值

| 状态 | 电流 | 条件 |
|---|---|---|
| 运行 + WiFi 发射峰值 | 240 mA | TX 到 20dBm 的瞬间 |
| 运行 + WiFi 平均 | 100–130 mA | 持续联网，每秒一次 MQTT |
| 运行、WiFi 关闭、CPU 240MHz | 35–45 mA | |
| Modem sleep（WiFi 连着但不收发） | 20 mA | |
| Light sleep | 0.8 mA | RTC 外设仍在跑 |
| **Deep sleep** | **10 µA** | RTC 定时器 + RTC 内存保持 |
| Deep sleep，但板载还有 USB 芯片/电源灯 | 200µA–2mA | 开发板常见 |

最后一行是重点：**你测出来的数值大概率不是 10µA**。CH340/CP2102 的 VBUS 检测脚、
板载红色 PWR LED（约 1mA）、AMS1117 的反向漏电都会叠在上面。
做低功耗必须自己画板，或者至少能拆掉 LED 和稳压器。

## Deep sleep 的写法

```c
#include "esp_sleep.h"
#include "driver/gpio.h"
#include "esp_log.h"

#define WAKE_GPIO  GPIO_NUM_33
#define SLEEP_SEC  60

RTC_DATA_ATTR static uint32_t s_boot = 0;   /* 跨睡眠保留 */

void app_main(void)
{
    s_boot++;
    ESP_LOGI("app", "第 %lu 次唤醒", (unsigned long)s_boot);

    /* 收尾：保住引脚电平，关掉不用的 RTC 电源域 */
    gpio_hold_en(WAKE_GPIO);
    esp_sleep_pd_config(ESP_PD_DOMAIN_RTC_PERIPH, ESP_PD_OPTION_OFF);

    /* 配唤醒源：定时 + 外部引脚，任一触发即醒 */
    esp_sleep_enable_timer_wakeup((uint64_t)SLEEP_SEC * 1000000ULL);
    esp_sleep_enable_ext0_wakeup(WAKE_GPIO, 0);   /* 低电平唤醒 */

    ESP_LOGI("app", "sleep %d s", SLEEP_SEC);
    esp_deep_sleep_start();      /* 不会返回 */
}
```

**唤醒原因必须查**，否则定时唤醒和按钮唤醒走同一套逻辑，行为会很怪：

```c
esp_sleep_wakeup_cause_t cause = esp_sleep_get_wakeup_cause();
switch (cause) {
case ESP_SLEEP_WAKEUP_TIMER:     ESP_LOGI("app", "定时唤醒"); break;
case ESP_SLEEP_WAKEUP_EXT0:      ESP_LOGI("app", "按钮唤醒"); break;
case ESP_SLEEP_WAKEUP_UNDEFINED: ESP_LOGI("app", "首次上电"); break;
default: break;
}
```

### 唤醒源对比

| 唤醒源 | API | 附加电流 | 限制 |
|---|---|---|---|
| 定时器（RTC） | esp_sleep_enable_timer_wakeup | 极低（µA） | 精度 ±5%，随温度漂移 |
| 外部引脚 ext0 | esp_sleep_enable_ext0_wakeup | 低 | **只能用 1 个** RTC GPIO |
| 外部引脚 ext1 | esp_sleep_enable_ext1_wakeup | 低 | 多个 RTC GPIO，但只能统一 ALL/ANY 同一电平 |
| 触摸 | esp_sleep_enable_touchpad_wakeup | 需 RTC 外设供电（~50µA） | 仅特定 GPIO |
| UART | esp_sleep_enable_uart_wakeup | 中 | 需要连续 3 个上升沿 |

RTC GPIO 只有这些：**0, 2, 4, 12–15, 25–27, 32–39**。
把唤醒按钮接到 GPIO18，esp_sleep_enable_ext0_wakeup 返回 ESP_ERR_INVALID_ARG，
而如果你没查返回值，板子就再也醒不过来。

## 续航怎么估

```text
平均电流(mA) = (各阶段电流 × 各阶段时长) 之和 / 总周期(s)
续航(小时)  = 电池容量(mAh) × 可用比例 / 平均电流(mA)
```

真实例子：18650 容量 3000mAh，每 10 分钟醒一次，醒着 3 秒（联网发一条数据），
其余时间 deep sleep。

| 阶段 | 电流 | 时长 |
|---|---|---|
| 启动 + WiFi 连接 | 120 mA | 2.0 s |
| 采样 + 发送 | 100 mA | 1.0 s |
| deep sleep | 0.01 mA | 597 s |

```text
平均 = (120×2 + 100×1 + 0.01×597) / 600
     = (240 + 100 + 6) / 600
     = 0.577 mA

续航 = 3000 × 0.8 / 0.577 ≈ 4160 小时 ≈ 173 天
```

**但实测往往只有 1/3。** 三个系统性偏差：

- 可用比例不是 1.0。锂电放到 3.3V 以下时 LDO 已经稳不住输出，实际能用 70–80%；
  低温再衰减，**按 0.6 估才安全**。
- 电池容量是 0.2C 放电测出来的。你的脉冲负载（WiFi 峰值 240mA ≈ 0.5C）
  会让实际容量再掉 10–20%。
- 联网建链时间比你以为的长。从 esp_wifi_start 到拿到 IP 通常 1.5–3 秒，
  路由器差的时候能到 8 秒。这一项就是平均电流的大头。

**优化顺序（收益从大到小）**：拉长睡眠周期 → 缩短联网时间（静态 IP 跳过 DHCP）
→ 换低静态电流稳压器 → 降 WiFi 发射功率 → 拆掉板载 LED。

## 坑

1. **舵机/电机一启动就复位。** SG90 堵转瞬间 700mA，直流电机启动电流是额定的 5–8 倍。
   和 ESP32 共用一条 3.3V/5V 轨时，电池内阻 + 导线电阻造成的压降会把
   ESP32 拉到 2.6V 以下，触发 brownout detector 复位，串口打印
   `Brownout detector was triggered`。修法三选一：
   - 电机电源**独立走线**，从电池直接取，只在电源入口处与主控共地（星形接地）；
   - 电机两端并 0.1µF 陶瓷电容抑制换向火花，电源并 470–1000µF 电解补瞬时电流；
   - 换内阻更低的高倍率电池，电容加到 2200µF。

   软件上可以关掉 CONFIG_ESP_BROWNOUT_DET，但那只是把复位换成随机死机，**生产里别这么干**。

2. **USB 供电和电池同时接会互相灌电流。** 5V 从 USB 进 LDO，电池也接在 LDO 输出端，
   等于在给锂电池反向充电（TP4056 不防这个）。加理想二极管（SS34 + 比较器）、
   用充放电互斥的模块，或者物理上用开关切换。

3. **deep sleep 会断掉几乎所有外设。** 醒来之后 SPI/I2C/UART 全部要重新初始化，
   传感器要重新上电、重新配寄存器。放在普通全局变量里的 I2C 句柄醒来就是野指针。

4. **只有 RTC 内存能跨睡眠保数据。** 用 `RTC_DATA_ATTR` 修饰的变量保留，
   普通全局变量被重新初始化：

```c
RTC_DATA_ATTR static uint32_t s_boot_count = 0;   /* 跨睡眠保留 */
RTC_DATA_ATTR static float    s_last_temp  = 0;   /* 跨睡眠保留 */
static uint32_t s_ram_count = 0;                  /* 每次醒来归零 */

void app_main(void) {
    s_boot_count++;
    ESP_LOGI("app", "第 %lu 次唤醒（本次 RAM 计数 %lu）",
             (unsigned long)s_boot_count, (unsigned long)s_ram_count);
}
```

   RTC 慢速内存只有 8KB，而且里面的指针不能指向普通 RAM ——
   那块内存的内容已经丢失，但地址看起来还"有效"，解引用就是脏数据。存标量和数组，别存 char *。

5. **gpio_hold_en 不配对会漏电。** 睡前拉住的引脚，下次醒来要用 gpio_hold_dis 解除，
   否则那个脚不能再用 gpio_set_level 改电平。更常见的是反过来：忘了 hold，
   睡后引脚悬空，外部上拉把电流灌进芯片。

6. **USB 转串口的 TX 悬空会漏电。** 睡眠时 CH340 的 TX 若为高，会通过 ESP32 的
   RX 内部保护二极管灌进 VDD，几个 mA 就没了。低功耗项目里串口线是要拔的。

7. **esp_deep_sleep_start() 之后代码不会继续。** 写在它后面的清理代码不执行，
   fclose / nvs_commit 都必须放在它之前。

8. **电池低于 3.5V 时 AMS1117 已经失效。** 1117 压差 1V，电池到 4.3V 以下就开始掉出稳压区。
   要榨干电池就换低压差 LDO（ME6211 压差约 100mV @100mA），
   或者接受「电池到 3.5V 就关机」。

9. **TP4056 的指示灯不能当电量指示。** 它只反映充电状态。要百分比就得 ADC 测分压
   再查放电曲线，而锂电曲线在 3.7V 附近极平（平台区），纯靠电压估 SOC 误差能到 ±20%。

## 排错对照表

| 现象 | 原因 | 处理 |
|---|---|---|
| 串口打 Brownout detector was triggered | 负载瞬态压降 | 加大电容、电机独立供电 |
| 电池供电正常，插 USB 就重启 | 两个电源打架 | 加理想二极管或改互斥方案 |
| 睡眠电流 1mA 而不是 10µA | 板载 LED / USB 芯片 / LDO 静态电流 | 拆 LED、换 ME6211、拔串口线 |
| 睡下去醒不来 | 唤醒脚不是 RTC GPIO | 换到 0/2/4/12–15/25–27/32–39 |
| 醒来后数据全丢 | 用了普通全局变量 | 改 RTC_DATA_ATTR |
| 天天充电还是掉电快 | 联网时间长 | 静态 IP、缩短重连、拉长周期 |
| 电池鼓包 | 过充 / 过放 / 高温 | 换带保护板的电池，检查 TP4056 |
| 充电永远充不满 | 充电时负载还在耗电 | 充电时断开负载 |
