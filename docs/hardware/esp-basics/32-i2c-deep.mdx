# 19 I2C 深入

**本课目标**：能算出正确的上拉电阻，能解开死锁的总线。

## 电气基础

:::info[I2C 是"开漏 + 上拉"]
```text
每个设备只能把线拉低（开漏），不能主动拉高。
高电平完全靠上拉电阻。
```

**这带来两个重要结论**：

1. **任何设备拉低，总线就是低** —— 这实现了"线与"，也是仲裁和多主的基础
2. **上升沿是 RC 充电** —— 上升时间由 R x C 决定，**电阻太大边沿就变慢**
:::

## 上拉电阻怎么算

:::danger[两个约束把它夹在中间]
**下限（不能太小）**：低电平时灌电流不能超过器件能力

```text
R_min = (VDD - VOL) / IOL_max

典型：VOL = 0.4V，IOL_max = 3mA，VDD = 3.3V
R_min = (3.3 - 0.4) / 0.003 = 970 欧
```

**上限（不能太大）**：上升时间必须满足规范

```text
t_r = 0.847 x R x C_bus     （从 30% 到 70%，近似）
标准模式（100kHz）：t_r <= 1000 ns
快速模式（400kHz）：t_r <= 300 ns
```
:::

**举例**：总线电容 100pF，快速模式要求 t_r 不大于 300ns

```text
300ns = 0.847 x R x 100pF
R = 3540 欧
故选 2.2k 或 3.3k，留余量
```

:::warning[为什么开发板上常见 4.7k]
**因为大多数小板子总线电容很小（小于 50pF），4.7k 就够。**

**但设备多、线长时 4.7k 会导致边沿太慢，通信失败。**

**症状**："单独接一个设备正常，接三四个就出错"。
:::

:::danger[**不要用芯片内部弱上拉**]
**STM32 的内部上拉约 30~50k** —— 对 I2C 来说太大，边沿极慢。

**必须外接 2.2k~10k 的电阻。**
:::

## 7 位地址的两种写法

:::danger[这是 I2C 最经典的混乱来源]
```text
器件手册写的 0x68（7 位）
实际总线上发送的字节：
  写 = 0x68 << 1 | 0 = 0xD0
  读 = 0x68 << 1 | 1 = 0xD1
```

**不同代码库的要求不同**：

| 平台 | 传什么 |
| --- | --- |
| **STM32 HAL** | **7 位地址左移一位后的值**（即 0xD0） |
| Linux i2c-dev | 7 位原值（0x68） |
| Python smbus2 | 7 位原值（0x68） |
| 部分 Arduino 库 | 7 位原值 |
:::

**扫描法判断**：用"扫 0x00~0x7F"和"扫 0x00~0xFF"各试一次，看哪个能扫到设备。

## 时钟延展（Clock Stretching）

:::info[从机可以拉住 SCL 让主机等]
**从机来不及处理时，把 SCL 保持低** —— 主机发下一个时钟脉冲时发现 SCL 没释放，就等着。

**用途**：ADC 转换、EEPROM 写周期。
:::

:::warning[不是所有主机都支持]
**很多硬件 I2C 外设（包括某些 STM32 型号）不支持时钟延展** —— 会导致数据错乱。

**症状**：某些器件（尤其慢速 ADC/EEPROM）偶发读错。

**对策**：降速（100kHz 甚至 50kHz）、或改用软件 I2C。
:::

## 总线死锁与解卡

:::danger[死锁是怎么发生的]
```text
1. 主机读数据，从机正在输出 0（把 SDA 拉低）
2. 主机中途复位或异常，停止发时钟
3. 从机还在等下一个时钟，继续拉低 SDA
4. 主机重新初始化，想发 START —— 但 SDA 被拉低，START 条件发不出来
导致永久死锁
```
:::

**解卡的标准手法：手动补 9 个时钟**

```c
/* 在初始化 I2C 之前调用 */
void i2c_bus_recover(void)
{
    /* 把引脚切成 GPIO 开漏输出 */
    gpio_set_mode_open_drain(SCL_PIN);
    gpio_set_mode_open_drain(SDA_PIN);

    gpio_write(SCL_PIN, 1);
    gpio_write(SDA_PIN, 1);
    delay_us(10);

    /* 补最多 9 个时钟 */
    for (int i = 0; i < 9; i++) {
        if (gpio_read(SDA_PIN)) break;      /* SDA 已经释放 */
        gpio_write(SCL_PIN, 0); delay_us(5);
        gpio_write(SCL_PIN, 1); delay_us(5);
    }

    /* 补一个 STOP 条件：SCL 高时 SDA 由低变高 */
    gpio_write(SCL_PIN, 0); delay_us(5);
    gpio_write(SDA_PIN, 0); delay_us(5);
    gpio_write(SCL_PIN, 1); delay_us(5);
    gpio_write(SDA_PIN, 1); delay_us(5);
}
```

:::tip[为什么是 9 个时钟]
**一个字节 8 位 + 1 个 ACK 位 = 9 个时钟。**

**补够 9 个，任何"半途卡住的字节传输"都能被推完**，从机释放 SDA。
:::

:::warning[预防比解卡更重要]
- **加上拉电阻**（很多人省掉，导致边沿异常）
- **通信失败时先发 STOP 再重试**
- **超时要短**（别在死锁时无限等）
- **复位后先做总线恢复**
:::

## 调试手段

| 手段 | 能看到什么 |
| --- | --- |
| **逻辑分析仪** | 完整时序、地址、ACK/NAK |
| 万用表 | 只有静态电平（**看不到通信**） |
| 示波器 | 边沿质量、上升时间、毛刺 |
| 软件扫描 | 哪些地址有响应 |

```c
/* 地址扫描 */
for (uint8_t addr = 0x08; addr < 0x78; addr++) {
    if (i2c_ping(addr << 1) == 0) {
        printf("found 0x%02X\n", addr);
    }
}
```

:::danger[万用表看不出 I2C 是否在工作]
**I2C 空闲时 SDA/SCL 都是高电平** —— 用万用表量永远是 3.3V，看不出任何信息。

**必须用逻辑分析仪或示波器。**
:::

## 常见坑

| 现象 | 原因 | 解决 |
| --- | --- | --- |
| 扫不到设备 | 地址没左移 / 上拉缺失 | 两种地址都试、加上拉 |
| 接一个设备正常，多个出错 | 上拉太大、电容太大 | 减小电阻到 2.2k |
| 偶发 NAK | 时钟延展不支持 | 降速 |
| 总线卡死 | 从机拉住 SDA | 补 9 个时钟 + STOP |
| 读到全 0xFF | SDA 一直高（没接上拉） | 加上拉 |
| 读到全 0x00 | SDA 一直被拉低 | 解卡 |
| 长距离失败 | 电容过大 | 降速或用 I2C 缓冲器 |
| 多主冲突 | 仲裁失败处理缺失 | 检查 START 重发逻辑 |

:::warning[I2C 不适合长距离]
**标准规定总线电容上限 400pF** —— 大约对应 1~2 米普通线缆。

**要长距离**：降速、用 I2C 缓冲器（PCA9515）、或改用 RS485/CAN。
:::
