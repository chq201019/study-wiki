# 20 UART 深入

**本课目标**：知道为什么串口会乱码，会用 DMA 收发不丢数据。

## 波特率误差：乱码的头号原因

:::danger[UART 是异步的，靠双方时钟对齐]
**一帧 10 位（1 起始 + 8 数据 + 1 停止），接收方在第 1.5 位采样**。

**误差累积到半个位宽就采错** —— 所以总误差要控制在 **2% 以内**（经验值，10 位帧）。
:::

```text
实际波特率 = 外设时钟 / (16 x USARTDIV)   （STM32 有 16 倍过采样）

误差 = (实际 - 目标) / 目标 x 100%
```

:::warning[有些波特率天生算不准]
**经典问题**：72MHz 时钟下要 115200

```text
72,000,000 / (16 x 115200) = 39.0625
39.0625 不是整数，必须取整，误差约 0.16%
```

**0.16% 可以接受。但某些组合误差会超过 2%。**

**排查方法**：用 CubeMX 看它算出的实际波特率，或用示波器量一位的宽度。
:::

```text
校验：量一个位宽
115200 bps，一位 = 8.68 us
示波器上量到 8.9 us，误差 2.5%，会偶发乱码
```

:::tip[外部晶振 vs 内部 RC]
| 时钟源 | 精度 | 适合串口 |
| --- | --- | --- |
| **外部晶振（HSE）** | +-20~50 ppm | **必须用** |
| 内部 RC（HSI） | **+-1%（随温度漂）** | 容易乱码 |

**内部 RC 的 +-1% 已经吃掉一半的误差预算** —— 两端都用 HSI 时很容易失败。
:::

## 数据格式

```c
/* 常见配置：115200 8N1 = 8 数据位、无校验、1 停止位 */
huart.Init.BaudRate = 115200;
huart.Init.WordLength = UART_WORDLENGTH_8B;
huart.Init.StopBits   = UART_STOPBITS_1;
huart.Init.Parity     = UART_PARITY_NONE;
```

:::danger[两端格式必须完全一致]
**不一致的症状**：能收到数据但全是乱码，或只能收到第一个字节。

**最常见的错配**：

- 一端 8N1，另一端 8E1（有校验）
- 一端 115200，另一端 9600
- 一端 1 停止位，另一端 2 停止位
:::

## 9 位数据：多机通信的老办法

:::info[用第 9 位区分地址帧和数据帧]
```text
第 9 位 = 1，地址帧（唤醒所有从机）
第 9 位 = 0，数据帧（只有被寻址的从机处理）
```

**这是 RS485 多机通信的经典方案**（也叫 Multi-Processor Communication）。

**现代替代**：用 Modbus RTU（也有地址字段，但走软件解析）。
:::

## 流控

| 类型 | 线 | 作用 |
| --- | --- | --- |
| **硬件（RTS/CTS）** | 2 根 | 对方缓冲满时拉高 RTS 让我暂停 |
| 软件（XON/XOFF） | 0 根 | 用特殊字符控制（0x11/0x13） |

:::warning[不接流控时高速传输会丢数据]
**接收方来不及处理时，数据就丢了** —— UART 没有重传机制。

**三种对策**：

1. **降速**（最简单）
2. **接硬件流控**（可靠但要 2 根线）
3. **用 DMA + 大缓冲**（嵌入式常用，见下）
:::

## DMA 收发的中断设计

:::danger[接收是最麻烦的部分]
**你不知道对方什么时候发、发多长** —— 所以收到完整一帧需要额外机制。
:::

**方案一：空闲中断（IDLE）+ DMA（推荐）**

```c
/* 启动 DMA 接收，长度设成最大 */
HAL_UART_Receive_DMA(&huart1, rxbuf, sizeof(rxbuf));
__HAL_UART_ENABLE_IT(&huart1, UART_IT_IDLE);

/* 空闲中断：一帧结束（线路空闲超过 1 个字符时间） */
void USART1_IRQHandler(void)
{
    if (__HAL_UART_GET_FLAG(&huart1, UART_FLAG_IDLE)) {
        __HAL_UART_CLEAR_IDLEFLAG(&huart1);

        /* 读剩余计数，反推收到多少字节 */
        uint16_t remain = __HAL_DMA_GET_COUNTER(&hdma_usart1_rx);
        uint16_t len = sizeof(rxbuf) - remain;

        /* 交给主循环处理 */
        on_frame(rxbuf, len);

        /* 重新启动接收 */
        HAL_UART_AbortReceive(&huart1);
        HAL_UART_Receive_DMA(&huart1, rxbuf, sizeof(rxbuf));
    }
}
```

:::tip[为什么空闲中断是最优解]
**它利用帧之间必有空闲这个物理事实** —— 不需要知道帧长度、不需要超时定时器。

**代价**：要求协议里帧之间有间隔（绝大多数协议满足）。
:::

**方案二：定长 + 传输完成中断**

```c
/* 适合长度固定的协议 */
void HAL_UART_RxCpltCallback(UART_HandleTypeDef *h)
{
    on_frame(rxbuf, sizeof(rxbuf));
    HAL_UART_Receive_DMA(h, rxbuf, sizeof(rxbuf));     /* 必须重启 */
}
```

:::danger[忘记重启接收，只收到第一帧]
**Normal 模式的 DMA 传完就停** —— 必须在回调里重新调用 HAL_UART_Receive_DMA。
:::

## 帧错误怎么排查

| 错误标志 | 含义 | 常见原因 |
| --- | --- | --- |
| **FE（Framing Error）** | 停止位不对 | **波特率不匹配** |
| NE（Noise） | 采到噪声 | 干扰、线太长 |
| ORE（Overrun） | 数据覆盖 | **来不及读**（没开 DMA/中断） |
| PE（Parity） | 校验错 | 格式不一致或干扰 |

```c
if (huart1.ErrorCode != HAL_UART_ERROR_NONE) {
    printf("err=0x%X\n", huart1.ErrorCode);
}
```

:::danger[ORE 是最常见也最隐蔽的]
**收到数据但没人读（或读太慢），新数据把旧数据覆盖，导致 ORE**

**症状**：偶发丢字节，而且丢的位置不固定。

**解决**：用 DMA 接收，或提高中断优先级、缩短中断处理时间。
:::

## 常见坑

| 现象 | 原因 | 解决 |
| --- | --- | --- |
| 全乱码 | 波特率/格式不一致 | 核对两端配置 |
| 偶发乱码 | 时钟误差大 | 用外部晶振 |
| 只收到第一个字节 | 没重启 DMA 接收 | 回调里重启 |
| 丢字节 | ORE 溢出 | DMA + 大缓冲 |
| 收不到任何数据 | TX/RX 接反 | 交叉连接 |
| 收到自己的数据 | TX 接到 RX | 检查接线 |
| 高速时丢包 | 无流控 | 降速或加 RTS/CTS |
| 长线不稳定 | 干扰/电平 | 加 120 欧终端或用 RS485 |

:::warning[TX/RX 要交叉，不是直连]
```text
设备 A 的 TX 接到设备 B 的 RX
设备 A 的 RX 接到设备 B 的 TX
```

**直连（TX 接 TX）会收到自己发的数据** —— 看起来能通，实际是回环。
:::
