# 05 三种开发方式怎么选

**本课目标**：知道三种方式各自适合谁，选定自己的路线，不再纠结。

## 三种方式一览

| 方式 | 写什么 | 难度 | 适合 |
| --- | --- | --- | --- |
| **米思齐 Mixly** | 拖积木 | ⭐ | 零基础、快速验证想法 |
| **Arduino IDE** | C++ 简化版 | ⭐⭐ | 爱好者、成熟生态 |
| **ESP-IDF** | 标准 C | ⭐⭐⭐ | 产品开发、要用全部功能 |

:::tip[它们最终都在做同一件事]
**都是把编译好的固件烧进芯片。**

区别只是"你写代码的方式"和"框架提供的功能多少"。

**所以可以混着用**：先用米思齐点灯，再换 Arduino，最后上 ESP-IDF——**板子不用换**。
:::

## 米思齐（Mixly）

**图形化编程**，拖积木生成代码。

```text
[当启动时] → [设置引脚 4 为 高电平] → [等待 1 秒]
           → [设置引脚 4 为 低电平] → [等待 1 秒]
```

| 优点 | 缺点 |
| --- | --- |
| **零语法门槛**，当天能出成果 | 复杂逻辑很难表达 |
| 可视化，适合教学 | 生成代码冗长、效率低 |
| 内置很多传感器积木 | 出问题不好排查 |
| 适合比赛/演示 | 学不到真正的编程 |

:::tip[米思齐的真正价值：建立信心]
**第一天就能让灯闪起来**，这个正反馈非常重要。

很多人一上手就装 ESP-IDF，配环境配三天，热情耗尽就放弃了。

**但别停在米思齐**——它教不了你内存、任务、协议。
:::

:::warning[Mind+ 的路径问题]
早期 Mind+ / Mixly 版本在**中文用户名**或**深层目录**下会报错：

```text
路径过长 / 找不到文件 / 编译失败
```

**规避办法**：

1. 安装到**纯英文短路径**，比如 `D:\MindPlus`
2. 项目文件也放浅目录，比如 `D:\esp\proj1`
3. 用户名含中文的话，把项目放在 `D:\` 下而不是桌面

**遇到这类报错先怀疑路径，而不是代码。**
:::

## Arduino IDE

**用简化版 C++ 写**，生态极其庞大。

```cpp
void setup() {
    pinMode(4, OUTPUT);
}

void loop() {
    digitalWrite(4, HIGH);
    delay(1000);
    digitalWrite(4, LOW);
    delay(1000);
}
```

| 优点 | 缺点 |
| --- | --- |
| **上手快**，代码短 | 隐藏了很多细节 |
| **库极多**（几乎每个传感器都有库） | 抽象层厚，出问题难查 |
| 社区巨大，搜得到答案 | 不能用 ESP32 的全部功能 |
| 同一套代码能跑很多板子 | 不如 ESP-IDF 灵活 |

:::tip[Arduino 的 `setup`/`loop` 背后是什么]
```cpp
void setup() { }     // 相当于 app_main 的开头
void loop()  { }     // 相当于 while(1) 里的内容
```

**Arduino 帮你藏起了 `app_main` 和主循环。**

好处是简单，坏处是**你不知道 FreeRTOS 在背后怎么调度**。
:::

## ESP-IDF

**乐鑫官方框架，用标准 C 开发。**

本机 ESP-IDF v5.3.5 的真实结构：

```text
hello_world/
├── CMakeLists.txt          ← 顶层构建配置
├── main/
│   ├── CMakeLists.txt      ← 组件注册
│   └── hello_world_main.c  ← 你的代码
└── sdkconfig               ← 配置（menuconfig 生成）
```

| 优点 | 缺点 |
| --- | --- |
| **能用芯片 100% 功能** | 环境配置复杂 |
| **官方支持、文档最全** | 概念多（组件、Kconfig、分区表） |
| 自带 FreeRTOS / WiFi / BLE | 编译慢 |
| 适合做**产品** | 报错信息不友好 |

:::info[ESP-IDF 自带 20 类官方示例]
本地实测目录：

```text
bluetooth  build_system  common_components  custom_bootloader
cxx  ethernet  get-started  ieee802154  mesh  network
openthread  peripherals  phy  protocols  provisioning
security  storage  system  wifi  zigbee
```

**每个外设、每种协议都有可运行示例**——这是学 ESP-IDF 最快的方式。

```bash
# 从示例复制一份开始改（最推荐的做法）
cp -r $IDF_PATH/examples/get-started/blink ~/my_blink
cd ~/my_blink
idf.py set-target esp32s3
idf.py build flash monitor
```
:::

## 三条路线怎么选

:::tip[我的建议：三步走]
```
① 米思齐（1~3 天）
   目标：确认板子、驱动、烧录都通了
   ↓
② Arduino IDE（1~2 周）
   目标：学会写逻辑，做出几个能演示的东西
   ↓
③ ESP-IDF（长期）
   目标：理解任务、内存、协议，能做产品
```

**不要跳过第 ① 步**——它排除的是硬件和环境问题，不是编程问题。

**也别停在 ②**——Arduino 会让你误以为单片机很简单。
:::

| 你的目标 | 直接选 |
| --- | --- |
| 只是想做个东西交作业 | 米思齐 |
| 想玩各种传感器、快速出效果 | Arduino |
| 想深入、想做产品、想找工作 | ESP-IDF |
| 想学嵌入式的**原理** | ESP-IDF |

## 三种方式的能力对比

| 能力 | 米思齐 | Arduino | ESP-IDF |
| --- | --- | --- | --- |
| 点灯/读按键 | ✅ | ✅ | ✅ |
| 接常见传感器 | ✅ | ✅✅ | ✅ |
| WiFi 联网 | ✅ 基础 | ✅ | ✅✅ |
| BLE 自定义协议 | ❌ | ⚠️ | ✅ |
| FreeRTOS 多任务 | ❌ | ⚠️ 能用但抽象 | ✅✅ |
| 精细控制内存 | ❌ | ❌ | ✅ |
| OTA 升级 | ⚠️ | ⚠️ | ✅ |
| 低功耗深度睡眠 | ⚠️ | ✅ | ✅✅ |

（✅✅ = 完整支持且可控；⚠️ = 能做但不推荐/受限；❌ = 很难）

## 本线怎么走

:::warning[这条零基础线的内容安排]
| 阶段 | 用什么 |
| --- | --- |
| 第 1~6 课（准备+点灯） | 三种都可，**推荐先用米思齐跑通** |
| 第 7~13 课（外设） | 代码以 **ESP-IDF** 给出，Arduino 对照 |
| 第 14~19 课（联网） | **ESP-IDF**（WiFi/MQTT/BLE 用它最简单） |
| 第 20~30 课（系统） | **ESP-IDF**（FreeRTOS、NVS、OTA 是它专属） |

**所以：前几课随便用哪个跑通，从第 7 课开始建议转 ESP-IDF。**
:::

## 装 ESP-IDF 的最简路径

不想折腾的话，用**乐鑫官方的安装器**：

1. 到乐鑫官网找 **ESP-IDF Tools Installer**（Windows）
2. 下载运行，一路下一步（会装 Python、工具链、IDF 本体）
3. 装完在开始菜单找到 **ESP-IDF Command Prompt**，打开

验证：

```bash
idf.py --version
```

能看到版本号就成功了（本机是 v5.3.5）。

:::danger[ESP-IDF 装完必须用它的专用命令行]
**不要在普通 cmd/PowerShell 里敲 `idf.py`** ——会报 `command not found`。

因为工具链的路径要靠那个启动脚本注入环境变量。

**每次开发都从「ESP-IDF Command Prompt」进。**
:::

## 常见错误

| 错误 | 现象 | 原因 | 解决 |
| --- | --- | --- | --- |
| 一上手就装 ESP-IDF | 配三天放弃 | 门槛太高 | 先用米思齐跑通 |
| 停在米思齐 | 学不到原理 | 图形化抽象太厚 | 及时转 Arduino/IDF |
| 项目放在中文路径 | 编译报错 | 工具链不支持 | 放纯英文浅目录 |
| 普通 cmd 里敲 idf.py | command not found | 环境没注入 | 用 IDF 专用命令行 |
| 混用两套框架的库 | 编译/链接错误 | 库不兼容 | 一个项目只用一套 |
