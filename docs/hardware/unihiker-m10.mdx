# 行空板 M10 开发指南

> 资料依据：DFRobot 官方 Wiki 整页归档（`unihiker.com.cn/wiki/m10/*`，抓取于 2026-11-19），
> 共 32 篇。只写官方原文有依据的内容。

## 一、它到底是什么

M10 不是单片机，是**单板计算机 + 协处理器的双处理器架构**：

| 部分 | 芯片 | 职责 |
|---|---|---|
| 主处理器 | **RK3308** Arm 64 位 4 核 1.2GHz | 跑 Debian Linux、Python、AI |
| 内存 / 存储 | 512MB DDR3 / 16GB eMMC | — |
| 协处理器 | **GD32VF103C8T6** RISC-V 108MHz，64KB Flash / 32KB SRAM | 实时 IO、板载元件 |
| 无线 | RTL8723DS | 2.4G WiFi + BT 4.0 |

**关键理解**：所有 GPIO 操作都不是 Linux 直接点寄存器，而是 Linux 通过串口命令
让协处理器去执行。所以**有毫秒级延迟**，做不了微秒级时序（WS2812 长灯带、红外解码、
DHT22 单总线这类要靠专用库或换单片机）。

## 二、连接：三个固定事实

| 项 | 值 |
|---|---|
| USB 直连 IP | **`10.1.2.3`**（固定，USB 虚拟成 RNDIS 网卡） |
| 用户名 | `root` |
| 密码 | `dfrobot` |

这些在 `networking.md` / `ssh.md` / `get-started.md` 三处一致。

### 2.1 四种编程入口

| 方式 | 适用 |
|---|---|
| **SSH**（MobaXterm 等） | 终端操作、文件拖拽 |
| **VSCode Remote-SSH** | 推荐做正经工程，有补全和调试 |
| **Jupyter** | 浏览器开 `10.1.2.3`，交互式学 Python |
| **Thonny** | 图形化 IDE，注意**必须用 3.3.13**（4.x 不兼容板上 Python 3.8） |

> Thonny 版本这条是硬约束，装最新版反而连不上。

## 三、两个专用库

### 3.1 `pinpong` —— 硬件控制

```python
from pinpong.board import Board, Pin
from pinpong.extension.unihiker import *

Board().begin()
led = Pin(Pin.P25, Pin.OUT)     # P25 = 板载 L 灯
led.write_digital(1)
```

板载元件对应的引脚（官方原文，直接背下来能省很多查文档时间）：

| 元件 | 引脚 |
|---|---|
| L 灯（蓝色 LED） | **P25** |
| 光线传感器 | **P29**（也可当 ADC 读） |
| Home 键 / A / B 键 | Home、A、B |

### 3.2 `unihiker` —— 屏幕 GUI 与音频

基于 tkinter 封装的 GUI 类（屏幕、控件、鼠标键盘、多线程）和 Audio 类（录音、播放、
环境音强度）。在板上 `pip install unihiker` 安装或更新。

## 四、ADC 与 PWM：8 路，但 PWM 分组互斥

这两张表是 M10 最实用的信息，官方原文明确列出：

### 4.1 ADC（8 路 12 位，0-4095）

```
P0 P1 P2 P3 P4 P10 P21 P22
```

**只有这 8 个脚能读模拟量。** P5-P9、P11-P16 完全没有模拟输入能力，
把电位器接到 P6 再读 ADC 只会得到常量，**不报错**。

### 4.2 PWM（8 路 10 位）

```
P0 P2 P3 P10 P16 P21 P22 P23
```

**分组互斥规则**（官方原文，最容易踩）：

- **P8 与 P2 共用一路 PWM**
- **P9 与 P10 共用一路 PWM**
- **P8/P9 为一组，P2/P10 为一组，同一时刻只能用其中一组**

也就是说：P8 或 P9 输出了 PWM，P2 和 P10 就不能再用。
表现为"第二个舵机不动"，而且**不报错**。

## 五、接口与供电（官方明确警告）

| 项 | 说明 |
|---|---|
| 供电 | **只能从 Type-C 5V**。不可从金手指给主板供电 |
| 工作电压 | 3.3V |
| 最大工作电流 | **2000mA** |
| Type-C 超压 | 输入 **超过 5.5V 可能烧坏主板芯片**——不要用会协商出 9V/12V 的快充头 |
| 金手指 | 19 路独立 I/O，兼容 micro:bit 编号；**背面金手指无电气连接** |
| 3Pin I/O | 3 路 10 位 PWM + 2 路 12 位 ADC |
| 4Pin I2C | **独立 I2C 通道，不与板载 I2C 元件共用** |

**4Pin I2C 是独立的**这条很重要：外接 I2C 模块优先走 4Pin 口，
不要去挤金手指的 P19/P20（那里已被板载 OLED 和六轴占用）。

## 六、板载元件型号

| 元件 | 型号/参数 |
|---|---|
| 屏幕 | 2.8" 240×320 **可触控**彩屏 |
| 六轴 | **ICM20689 / QMI8658C**（两种批次，三轴加速度+三轴陀螺仪） |
| 光线 | **PT0603** 光敏三极管 |
| 麦克风 | 电容硅麦克风 |
| 蜂鸣器 | 无源蜂鸣器 |
| 按键 | Home + A + B |

> 六轴有两种型号（ICM20689 与 QMI8658C），这是批次差异。写底层驱动时要先探测。
> 但用 `pinpong` 的封装则不用管。

## 七、AI 应用路线

官方把 AI 应用分了几类，**关键前提是 M10 没有 NPU**：

| 方向 | 可行做法 |
|---|---|
| 视觉识别 | OpenCV + 百度 API；接二哈识图（K210 模块）；图像分类本地训练 |
| 语音交互 | 板载麦克风录音；离线关键词识别（Maix-Speech）；**语音合成需外接 USB 喇叭或蓝牙音箱** |
| AIGC | 大语言模型对话、文生图（走云端 API） |
| 机器学习 | 图像分类、CNN 原理与板上实践 |

**硬件前提**（容易买了板才发现）：

- **无板载摄像头** → 需要 USB-A 接免驱摄像头
- **语音合成需要外接音箱** → 板载只有麦克风没有喇叭

**能力边界**：官方自己写明"无 AI 加速芯片，复杂高算力模型（本地大模型、重型 CNN）
不流畅"，AI 任务优先走云端 API 或板端轻量模型。

## 八、踩坑清单

1. **GPIO 编号不是树莓派的 BCM**。M10 用 micro:bit 风格的 P 编号（P0…P29），
   底层还要经 pinpong 映射到协处理器。照树莓派教程写 `Pin(17)` 会接错脚或抛异常。
2. **ADC 只有 8 个脚**（P0/P1/P2/P3/P4/P10/P21/P22），接错脚读常量且不报错。
3. **PWM 分组互斥**：P8/P9 与 P2/P10 两组不能同时用，表现为"第二个舵机不动"。
4. **只能 Type-C 供电**，金手指 3V3 带大电流负载会把协处理器侧稳压拉垮，导致整板重启。
5. **Type-C 不能超 5.5V**，快充头可能烧板。
6. **背面金手指无电气连接**，只有正面触点可用。
7. **外接 I2C 优先用 4Pin 独立口**，别挤 P19/P20（板载 OLED + 六轴已占用）。
8. **关机要走 Home 菜单或 `shutdown`**，直接拔线会损坏 eMMC 文件系统，下次起不来。
9. **Thonny 必须 3.3.13**，4.x 连不上（板上还是 Python 3.8）。
10. **实时性不够**：所有 IO 经协处理器，做不了微秒级时序（WS2812 长灯带、红外解码）。

## 九、M10 vs K10 怎么选

两块板都叫"行空板"，但**架构完全不同**，选错会浪费工期。

| 维度 | M10 | K10 |
|---|---|---|
| 本质 | Linux 单板机 + 协处理器 | ESP32-S3 单片机 |
| 编程 | 完整 Python 3（可 pip 装库） | MicroPython / Arduino / PIO |
| 模拟输入 | **8 路**（P0/P1/P2/P3/P4/P10/P21/P22） | **仅 2 路**（P0/P1） |
| PWM | 8 路（分组互斥） | 仅 P0/P1 硬件 PWM |
| 摄像头 | ❌ 需 USB 外接 | ✅ 板载 200 万像素 GC2145 |
| 麦克风+喇叭 | 麦克风 ✅ / 喇叭 ❌ | 双麦 + 2W 喇叭 ✅ |
| 端侧 AI | ❌ 无 NPU，走云端或轻量模型 | ✅ 内置离线人脸/语音/二维码模型 |
| 实时性 | 毫秒级（经协处理器） | 微秒级（芯片直连，但仅 P0/P1） |
| 启动速度 | 约 30 秒（完整 Linux） | 瞬间 |
| 适合 | 数据处理、网络请求、复杂 Python 工程、AI 云端对接 | 端侧 AI 体验、物联网节点、传感器控制 |

**一句话选型**：

- 要**跑完整 Python / 接云端大模型 / 做数据处理** → M10
- 要**开箱即用的端侧 AI / 语音助手 / 物联网节点** → K10
- 要**多路模拟采集** → M10（K10 只有 2 路）
- 要**摄像头视觉** → K10（M10 得外接 USB 摄像头）
