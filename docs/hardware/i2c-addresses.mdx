# I2C 地址与总线冲突速查

I2C 是"两根线挂一堆设备"的总线，协议上允许，**但地址不能撞**。
地址撞了的典型现象：单独接都能用，一起接就有一个没反应，或者两个都时好时坏。

## 固定/可选地址

| 模块 | 地址 | 备注 |
|---|---|---|
| bh1750 | 0x23（ADDR 低）/ 0x5C（ADDR 高） | 3.3V |
| bmp280 | 0x76（SDO 低）/ 0x77（SDO 高） | 也可走 SPI |
| mpu6050 | 0x68（AD0 低）/ 0x69（AD0 高） | — |
| rtc-ds3231 | 0x68 | **与 MPU6050 默认冲突！** |
| ssd1306-oled | 0x3C / 0x3D | 常见 0x3C |
| sh1106-oled | 0x3C | 常见固定 |
| lcd1602-i2c | 0x27 / 0x3F | PCF8574 背板 |
| **huskylens（1 代）** | **0x32** | 协议 V1 |
| **huskylens-2（2 代）** | **0x50** | 协议 V2，**与一代不同** |
| 24C32（DS3231 模块附带） | 0x57 | 常被忽略，但它占了一个地址 |
| rc522 | SPI，无 I2C 地址 | 用 CS 片选 |

> **两代 HuskyLens 地址不同，这点最容易踩**：一代 0x32、二代 0x50。
> 把一代代码改个类名去跑二代，会因为地址写死而完全无数据。
> 二代地址来自官方库 `DFRobot_HuskylensV2/ProtocolV2.h` 的 `const uint8_t addr = 0x50;`。

## 地址冲突处理

1. **先扫描**：Arduino 跑 I2C Scanner（`Wire.begin()` 后逐个地址探测）；
   Linux（树莓派/行空板）跑 `i2cdetect -y 1`。
   扫描结果就是事实，比查表可靠——尤其兼容模块常被厂家改了地址。
2. **优先改硬件地址脚**（AD0 / SDO / ADDR），不要靠软件硬顶。
   地址脚接 GND 或 VCC 就切换地址，这是设计意图。
3. 实在改不了，才考虑换模块或用 TCA9548A 这类 I2C 多路复用器。
   教学场景不建议一上来就用复用器，学生理解不了。

**典型冲突**：DS3231 与 MPU6050 默认都挂 0x68。
解法是把 MPU6050 的 AD0 接 VCC → 变成 0x69。

## I2C 电气要点

- **上拉电阻是必须的**。总线上必须有 4.7k-10k 上拉到 **3.3V**（不是 5V）。
  很多模块板自带 4.7k 上拉在 5V 侧，接 3.3V 主控时要拆掉或改到 3.3V。
- 上拉阻值怎么选：总线电容小（短线、少设备）用 4.7k 更快；长线（>50cm）
  或设备多用 10k 更稳，但要降速到 100kHz。
- 速度：标准模式 100kHz，快速模式 400kHz。面包板+杜邦线跑 400kHz 容易出错，
  教学项目一律先用 100kHz。
- 线长限制：面包板上 20cm 以内没问题，超过 50cm 就要考虑降速或加缓冲器。
- 多个设备挂同一条总线时，**SDA/SCL 必须接到主控的同一个引脚**——
  这是总线，不是点对点。这一点在 `set_modules` 里有校验。

## 常见故障对照

| 现象 | 最可能的原因 |
|---|---|
| 单独接能用，一起接就有一个失灵 | 地址冲突 |
| 扫描不到任何设备 | 没接上拉 / SDA-SCL 接反 / 模块没供电 |
| 扫描到了但读数据全是 0 或 0xFF | 上拉太弱、线太长、或设备内部还没初始化完 |
| 时好时坏 | 接触不良 / 上拉阻值不对 / 电源不稳 |
| 偶发 NACK | 多设备时总线负载太重，降速到 100kHz |
