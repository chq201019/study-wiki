# 网络编程：Socket

**本课目标**：会写正确的 TCP 客户端/服务端，知道粘包和短读怎么处理。

## 最小 TCP 服务端

```c
#include <sys/socket.h>
#include <netinet/in.h>
#include <arpa/inet.h>
#include <unistd.h>

int main(void)
{
    int srv = socket(AF_INET, SOCK_STREAM, 0);

    int on = 1;
    setsockopt(srv, SOL_SOCKET, SO_REUSEADDR, &on, sizeof(on));   /* ← 重要 */

    struct sockaddr_in addr = {
        .sin_family = AF_INET,
        .sin_port   = htons(8080),
        .sin_addr   = { .s_addr = htonl(INADDR_ANY) },
    };
    bind(srv, (struct sockaddr *)&addr, sizeof(addr));
    listen(srv, 128);

    for (;;) {
        int cli = accept(srv, NULL, NULL);
        if (cli < 0) continue;
        /* 处理 cli */
        write(cli, "hello\n", 6);
        close(cli);
    }
}
```

:::danger[`SO_REUSEADDR` 不加会"地址已被占用"]
程序退出后，TCP 连接进入 `TIME_WAIT` 状态（等 2MSL，通常 60 秒）。

**重启动服务时会报 `Address already in use`** —— 即使没有其他进程在监听。

```c
int on = 1;
setsockopt(srv, SOL_SOCKET, SO_REUSEADDR, &on, sizeof(on));
```

**这一行应该写在所有服务端代码里。**
:::

:::warning[`htons` / `htonl` 不能漏]
网络字节序是大端，x86 是小端。

```c
.sin_port = 8080;                  // ❌ 端口会变成 0x1F90 → 实际 0x901F
.sin_port = htons(8080);           // ✅
```

**漏了的表现**：服务端起来了，但客户端连不上（连到了错误的端口）。
:::

## 最小 TCP 客户端

```c
int cli = socket(AF_INET, SOCK_STREAM, 0);

struct sockaddr_in addr = {
    .sin_family = AF_INET,
    .sin_port   = htons(8080),
};
inet_pton(AF_INET, "127.0.0.1", &addr.sin_addr);

if (connect(cli, (struct sockaddr *)&addr, sizeof(addr)) < 0) {
    perror("connect");
    return 1;
}
```

## 短读与短写：最容易被忽略的坑

:::danger[`read` / `write` 不保证一次传完]
```c
int n = write(cli, buf, 1000);      /* 可能只写了 300 字节！ */
```

**`write` 返回的是"实际写入的字节数"**，可能小于请求量（发送缓冲区满、被信号打断）。

**`read` 同理**：返回值可能小于请求量，也可能因为对端关闭而返回 0。
:::

```c
/* 正确的写循环 */
ssize_t write_all(int fd, const void *buf, size_t len)
{
    const char *p = buf;
    size_t left = len;

    while (left > 0) {
        ssize_t n = write(fd, p, left);
        if (n < 0) {
            if (errno == EINTR) continue;       /* 被信号打断 → 重试 */
            return -1;
        }
        p    += n;
        left -= n;
    }
    return (ssize_t)len;
}

/* 正确的读循环：读到"读满 len"或"对端关闭"为止 */
ssize_t read_all(int fd, void *buf, size_t len)
{
    char *p = buf;
    size_t left = len;

    while (left > 0) {
        ssize_t n = read(fd, p, left);
        if (n == 0) break;                       /* 对端关闭 */
        if (n < 0) {
            if (errno == EINTR) continue;
            return -1;
        }
        p    += n;
        left -= n;
    }
    return (ssize_t)(len - left);
}
```

:::warning[返回值必须用 `ssize_t` 不是 `int`]
**在 64 位上 `size_t` 是 64 位**，用 `int` 接 `n` 会有截断风险（虽然实际不会传 2GB）。

**但更重要的是**：`n < 0` 的判断必须在"转换为无符号"之前做 ——

```c
size_t n = read(fd, buf, len);      // ❌ 负数变成巨大正数，n < 0 永远不成立
if (n < 0) { ... }                  // 永远为假！
```

**这是经典 bug。凡是返回值可能是 -1 的函数，都要先存进有符号类型。**
:::

## TCP 粘包：协议设计的核心问题

:::info[TCP 是字节流，没有"消息边界"]
```text
发送方 write 三次："abc" "de" "f"
接收方可能一次 read 到 "ab"，又一次 read 到 "cdef"
```

**完全合法**。TCP 不保留 write 的边界。
:::

:::tip[三种定界方式]
| 方式 | 做法 | 适合 |
| --- | --- | --- |
| **定长** | 每条消息固定 N 字节 | 二进制协议（简单但浪费） |
| **长度前缀** | 先 4 字节长度，再跟内容 | **最常用** |
| **分隔符** | 用 `\n` / `\0` 分隔 | 文本协议（HTTP 头、Redis） |

**长度前缀的实现**：

```c
/* 发送 */
uint32_t be_len = htonl(len);          /* 统一网络字节序 */
write_all(fd, &be_len, 4);
write_all(fd, payload, len);

/* 接收 */
uint32_t be_len;
if (read_all(fd, &be_len, 4) != 4) return -1;
uint32_t len = ntohl(be_len);

if (len > MAX_MSG) return -1;          /* ← 必须校验！防恶意长度 */
char *buf = malloc(len);
read_all(fd, buf, len);
```

:::

:::danger[不校验长度就是远程崩溃漏洞]
```c
uint32_t len = ntohl(be_len);
char *buf = malloc(len);               /* len 可能是 4GB → malloc 失败 */
read_all(fd, buf, len);                /* buf 是 NULL → 段错误 */
```

**攻击者发一个 `0xFFFFFFFF` 的长度就能让服务端崩。**

**规矩：长度必须校验上限**，且要在分配内存之前。
:::

## 阻塞 vs 非阻塞

:::info[三种模型]
| 模型 | 特点 | 适合 |
| --- | --- | --- |
| **阻塞** | `accept`/`read` 会挂住 | 简单工具、单连接 |
| **非阻塞 + 轮询** | 立刻返回 `EAGAIN` | 需要自己管理状态机 |
| **非阻塞 + epoll** | 内核告诉你哪些就绪 | **高并发服务端** |
:::

```c
/* 设置非阻塞 */
int flags = fcntl(fd, F_GETFL, 0);
fcntl(fd, F_SETFL, flags | O_NONBLOCK);
```

:::warning[非阻塞下 `EAGAIN` 不是错误]
```c
ssize_t n = read(fd, buf, len);
if (n < 0) {
    if (errno == EAGAIN || errno == EWOULDBLOCK) {
        /* 数据还没到，等下次 epoll 通知 */
        return 0;
    }
    /* 真正的错误 */
    return -1;
}
```

**`EAGAIN` 和 `EWOULDBLOCK` 在 Linux 上是同一个值**，但为可移植性两个都要判。
:::

## epoll 的基本用法

```c
int ep = epoll_create1(0);

struct epoll_event ev = { .events = EPOLLIN, .data.fd = srv };
epoll_ctl(ep, EPOLL_CTL_ADD, srv, &ev);

struct epoll_event events[64];
for (;;) {
    int n = epoll_wait(ep, events, 64, -1);     /* -1 = 永久等 */
    for (int i = 0; i < n; i++) {
        int fd = events[i].data.fd;
        if (fd == srv) {
            int cli = accept(srv, NULL, NULL);
            set_nonblocking(cli);
            struct epoll_event e = { .events = EPOLLIN, .data.fd = cli };
            epoll_ctl(ep, EPOLL_CTL_ADD, cli, &e);
        } else {
            /* 可读事件，处理 fd */
        }
    }
}
```

:::danger[`accept` 出来的 socket 默认是阻塞的]
**即使监听 socket 设了非阻塞，`accept` 返回的新 socket 仍然是阻塞的。**

**必须对每个新连接单独设非阻塞**，否则一个慢客户端会卡住整个事件循环。

**这是 epoll 服务端最常见的 bug。**
:::

:::warning[水平触发 vs 边缘触发]
| 模式 | 行为 |
| --- | --- |
| **LT（默认）** | 只要还有数据就持续通知 |
| **ET（`EPOLLET`）** | 只在状态变化时通知一次 |

**ET 必须配非阻塞 + 循环读到 `EAGAIN`**，否则剩下的数据永远不会被通知。

**新手先用 LT** —— 性能差距在连接数不多时很小。
:::

## 常见坑

| 现象 | 原因 | 解决 |
| --- | --- | --- |
| `Address already in use` | 没设 `SO_REUSEADDR` | 加上 |
| 客户端连不上 | 端口没 `htons` | 用 `htons` |
| 收到乱码 | 字节序没转换 | `htonl/ntohl` |
| 只收到部分数据 | `read` 返回小于请求量 | 写读循环 |
| 偶尔丢数据 | `write` 返回值没检查 | 写循环 |
| 消息边界错乱 | 没处理粘包 | 长度前缀或分隔符 |
| 服务端崩溃 | 没校验长度就 `malloc` | 校验上限 |
| 一个慢客户端拖垮全部 | 新连接没设非阻塞 | 每个连接单独设 |
| `read` 返回巨大正数 | 用 `size_t` 接负返回值 | 用 `ssize_t` |
| 端口扫描发现服务 | 绑了 `INADDR_ANY` | 绑具体网卡地址 |

:::tip[排查工具]
```bash
ss -tanp                        # 看所有 TCP 连接与状态
ss -tlnp                        # 只看监听
strace -f -e trace=network ./server    # 跟踪所有网络系统调用
tcpdump -i any -nn port 8080    # 抓包
```
:::
