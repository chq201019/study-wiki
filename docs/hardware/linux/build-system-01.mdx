# 01 本页学什么
写 Hello World 时 `gcc main.c -o app` 就够了。但当一个项目有几十个源文件、依赖第三方库、还要**交叉编译到 ARM 板子**时，手工敲命令就完全不可行了。

这一页解决：

- **Makefile 的核心机制**：目标/依赖/命令 + 时间戳比较
- `:=` 和 `=` 的区别（递归展开的坑）
- 自动变量 `$@`、`$<`、`$^` 到底指什么
- **头文件依赖自动生成**（`-MMD -MP`）——为什么改了 `.h` 也要重编
- **CMake** 的定位与 toolchain file
- **pkg-config** 的原理与交叉编译陷阱
- 构建脚本自动化

:::info[实测环境]
Debian 13 (trixie) / GNU Make **4.4.1** / gcc 14.2 / pkg-config **1.8.1**。
**注意：本服务器没有安装 `cmake`**，所以 CMake 部分只提供**示例代码**，不提供运行输出（我不会给你编造命令输出）。
:::

## 1. 为什么需要构建系统

### 1.1 手工命令的三个致命问题

```bash
gcc -c src/main.c -o build/main.o
gcc -c src/util.c -o build/util.o
gcc -o app build/main.o build/util.o
```

问题：

1. **重复劳动**：每次改代码都要重敲一遍
2. **全量重编**：改一个文件也要重编所有（大型项目要几十分钟）
3. **依赖不可见**：改了 `include/util.h`，哪些 `.c` 需要重编？人脑记不住

构建系统解决的核心问题是：**根据依赖关系和时间戳，只重编译真正需要重编的部分**。

### 1.2 增量编译的判断依据

Make 的逻辑极其简单：

```
目标文件不存在       → 必须构建
目标的任一依赖比目标新 → 必须重建
否则                 → 跳过
```

**"新"的比较依据是文件的 mtime（修改时间）**。这就是为什么 `touch` 一个文件能触发重新编译——它只改时间戳不改内容。

:::warning[时间戳的坑]
- 在**不同机器间拷贝文件**（如 NFS、U 盘）时，若时钟不一致会出现"目标比依赖新"的误判，导致该重编的没重编
- 解决：先 `make clean` 再全量构建
- 或者用内容哈希型构建系统（如 `ccache` 配合，或 Bazel/Ninja 的部分模式）
:::

## 2. Makefile 核心语法

### 2.1 规则的三段式

```makefile
目标(target): 依赖(prerequisites)
	命令(recipe)
```

**铁律：命令行必须以 TAB 字符开头。**

:::danger[最常见的 Makefile 错误]
```
Makefile:5: *** missing separator.  Stop.
```

这个错误**最常见的原因**就是命令行前用了**空格**而不是 **TAB**。

很多编辑器会自动把 TAB 转成空格（尤其是 VS Code 的默认设置）。解决办法：

- 在编辑器里显式设置 Makefile 用 TAB
- 或用 `.editorconfig`：`[Makefile] indent_style = tab`
- 检查方法：`cat -A Makefile | head`，TAB 显示为 `^I`
:::

### 2.2 一个完整可运行的实例

下面是一个**在本服务器上实测跑通**的完整 Makefile 示例。

项目结构：

```
项目根/
├── Makefile
├── include/
│   └── util.h
└── src/
    ├── main.c
    └── util.c
```

源码文件：

```c
/* include/util.h */
#ifndef UTIL_H
#define UTIL_H
int add(int a, int b);
#endif
```

```c
/* src/util.c */
#include "util.h"
int add(int a, int b) { return a + b; }
```

```c
/* src/main.c */
#include <stdio.h>
#include "util.h"
int main(void) { printf("add(2,3)=%d\n", add(2, 3)); return 0; }
```

Makefile：

```makefile
CC      := gcc
CFLAGS  := -Wall -Wextra -O2 -Iinclude
LDFLAGS :=
SRCDIR  := src
OBJDIR  := build
TARGET  := app
SRCS := $(wildcard $(SRCDIR)/*.c)
OBJS := $(patsubst $(SRCDIR)/%.c,$(OBJDIR)/%.o,$(SRCS))
DEPS := $(OBJS:.o=.d)

.PHONY: all clean
all: $(TARGET)

$(TARGET): $(OBJS)
	$(CC) $(CFLAGS) -o $@ $^ $(LDFLAGS)

$(OBJDIR)/%.o: $(SRCDIR)/%.c | $(OBJDIR)
	$(CC) $(CFLAGS) -MMD -MP -c $< -o $@

$(OBJDIR):
	mkdir -p $(OBJDIR)

-include $(DEPS)

clean:
	rm -rf $(OBJDIR) $(TARGET)
```

### 2.3 实测：`make -n`（干跑）

`-n` 只打印将要执行的命令，**不真正执行**。调试 Makefile 的首选。

```bash
$ make -n
mkdir -p build
gcc -Wall -Wextra -O2 -Iinclude -MMD -MP -c src/main.c -o build/main.o
gcc -Wall -Wextra -O2 -Iinclude -MMD -MP -c src/util.c -o build/util.o
gcc -Wall -Wextra -O2 -Iinclude -o app build/main.o build/util.o 
```

### 2.4 实测：真实构建

```bash
$ make
mkdir -p build
gcc -Wall -Wextra -O2 -Iinclude -MMD -MP -c src/main.c -o build/main.o
gcc -Wall -Wextra -O2 -Iinclude -MMD -MP -c src/util.c -o build/util.o
gcc -Wall -Wextra -O2 -Iinclude -o app build/main.o build/util.o 
```

### 2.5 实测：自动生成的依赖文件

```bash
$ cat build/main.d
build/main.o: src/main.c include/util.h
include/util.h:
```

**这就是 `-MMD` 的产物**。它记录了 `build/main.o` 依赖 `src/main.c` **和** `include/util.h`。

第二行 `include/util.h:` 是 `-MP` 生成的**伪目标**——作用是：万一 `util.h` 被删除了，make 不会因为"找不到生成 `util.h` 的规则"而报错退出。

:::tip[-MMD 与 -MP 各自的作用]
| 选项 | 作用 |
| --- | --- |
| `-MMD` | 编译时**顺便**生成一个 `.d` 文件，内容是该 `.o` 依赖哪些源文件（含头文件） |
| `-MP` | 为每个头文件额外生成一条**空的伪目标**，防止头文件被删时 make 报错 |

**为什么必须做这件事**：`gcc` 默认只知道 `.c` 依赖啥，不知道 `.c` 里 `#include` 了哪些 `.h`。如果你不加 `-MMD`，**改了头文件不会触发重编译**——这是最隐蔽的构建 bug 之一：你改了 `util.h` 里的结构体，重新 make，什么都没发生，程序行为却是旧的。
:::

### 2.6 实测：增量编译

只改动 `util.c`，看 make 重编了什么：

```bash
$ touch src/util.c && make
gcc -Wall -Wextra -O2 -Iinclude -MMD -MP -c src/util.c -o build/util.o
gcc -Wall -Wextra -O2 -Iinclude -o app build/main.o build/util.o 
```

**只重编了 `util.o`，`main.o 没动**，然后重新链接。这正是增量编译的价值。

再跑一次（无变化）：

```bash
$ make
make: Nothing to be done for 'all'.
```

### 2.7 实测：clean

```bash
$ make clean
rm -rf build app
$ ls -1
Makefile
include
src
```
