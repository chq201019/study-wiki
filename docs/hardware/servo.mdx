# 舵机控制 SG90 / MG996R

舵机只有三根线：电源、地、信号。看起来比直流电机简单，但它是整个创客项目里**最容易把主控搞复位**的器件。

## 规格对比

| 参数 | SG90（蓝色 9 g） | MG90S（金属齿 9 g） | MG996R（蓝色 55 g） |
|---|---|---|---|
| 重量 | 9 g | 13 g | 55 g |
| 工作电压 | 4.8 ~ 6.0 V | 4.8 ~ 6.0 V | 4.8 ~ 7.2 V |
| 堵转扭矩 @4.8 V | 1.2 ~ 1.8 kg·cm | 1.8 kg·cm | 9.4 kg·cm |
| 堵转扭矩 @6.0 V | 1.6 ~ 2.2 kg·cm | 2.2 kg·cm | 11 kg·cm |
| 速度 | 0.1 s / 60° | 0.1 s / 60° | 0.17 s / 60° @4.8 V |
| 空载电流 | 5 ~ 10 mA | 10 mA | 20 ~ 30 mA |
| 转动电流 | 100 ~ 250 mA | 150 ~ 300 mA | 500 ~ 900 mA |
| **堵转/启动电流** | **700 mA ~ 1 A** | 1 ~ 1.5 A | **2.5 A 以上，峰值到 3 A** |
| 齿轮 | 塑料 | 金属 | 金属 |
| 参考价 | ¥6 ~ 9 | ¥12 ~ 18 | ¥25 ~ 40 |
| 典型用途 | 教学、指针、小爪子 | 需要耐磨的小关节 | 机械臂、大扭矩云台 |

塑料齿的 SG90 在堵转几秒后齿轮就会"咔"一声扫齿，从此变成 360° 乱转的废物。**做机械臂、做夹爪，直接用 MG996R；做指针、做小旗子，SG90 够。**

## 50 Hz PWM 与脉宽的对应关系

舵机不用占空比调速，它看的是**每 20 ms 一个正脉冲的宽度**：

```text
周期 20 ms (50 Hz)
┌──────────────────────────────────────┐
│                                      │
│  ┌──┐                                │   0.5 ms → 0°
│  │  │                                │
│  └──┘                                │
│                                      │
│  ┌─────┐                             │   1.5 ms → 90°（中位）
│  │     │                             │
│  └─────┘                             │
│                                      │
│  ┌─────────┐                         │   2.5 ms → 180°
│  │         │                         │
│  └─────────┘                         │
└──────────────────────────────────────┘
```

标准对应表：

| 角度 | 脉宽 | 占空比 @20 ms |
|---|---|---|
| 0° | 0.5 ms | 2.5 % |
| 45° | 1.0 ms | 5.0 % |
| 90° | 1.5 ms | 7.5 % |
| 135° | 2.0 ms | 10.0 % |
| 180° | 2.5 ms | 12.5 % |

线性公式：

```text
pulse_us = 500 + angle * (2000 / 180)     // = 500 + angle * 11.111
duty     = pulse_us / 20000 * (1 << resolution)
```

不同型号的行程不完全一样：很多数字舵机支持 0.4 ~ 2.6 ms 甚至更宽，也有老型号只认 1.0 ~ 2.0 ms。
**新舵机第一次使用，先给 1.5 ms 让它回中位，再小步试边界。**

## LEDC 分辨率与频率的相互限制

这是 ESP32 上舵机代码最容易写错的地方。硬约束只有一条：

```text
频率 × 2^分辨率 ≤ LEDC 时钟源频率 (APB = 80 MHz)
等价于：2^分辨率 ≤ 80 MHz / 频率
```

50 Hz 时 80 MHz / 50 Hz = 1 600 000，所以**分辨率上限是 20 位**（2^20 = 1 048 576 ≤ 1 600 000）。
也就是说 50 Hz 下 LEDC 最高能配到 20 位，而不是很多教程说的 10 位。

重点是**实际该用几位**。一个计数值对应的时间 = 20 ms / 2^分辨率：

| 分辨率 | 一个计数值 | 角度分辨率 | 结论 |
|---|---|---|---|
| 8 位（256） | 78.1 µs | 7.0° | 肉眼可见卡顿，不能用 |
| 10 位（1024） | 19.5 µs | 1.76° | 勉强，指针类项目能看出抖动 |
| 12 位（4096） | 4.88 µs | 0.44° | 够用，最省事的选择 |
| **14 位（16384）** | **1.22 µs** | **0.11°** | **推荐默认值** |
| 16 位（65536） | 0.31 µs | 0.03° | 远超舵机死区（5~10 µs），没有意义 |

结论：**50 Hz + 14 位是甜点**。再高只是浪费，舵机内部电位器的精度和齿轮间隙都远大于 0.1°。

:::danger[这是被传错最多的一条]
网上流传"ESP32 舵机只能用 10 位分辨率，因为 50 Hz 时最多 14 位"——这个说法把 **"14 位分辨率下最高频率是 4.88 kHz"** 记反了。
真实约束是 `频率 × 2^分辨率 ≤ 80 MHz`，50 Hz 时用 14 位只需要 50 × 16384 = 819 200，只用掉时钟的 1 %。
把 `ledc_timer_config` 的 `duty_resolution` 设成 `LEDC_TIMER_14_BIT`、`freq_hz` 设成 50，会正常配成功；如果配失败，`esp_err_t` 会返回 `ESP_ERR_INVALID_ARG`，用 `ESP_ERROR_CHECK` 包起来立刻就能看出来。
:::

14 位下三个关键角度的计数值（可以直接抄）：

| 角度 | 脉宽 | duty（14 位） |
|---|---|---|
| 0° | 500 µs | 410 |
| 45° | 1000 µs | 819 |
| 90° | 1500 µs | 1229 |
| 135° | 2000 µs | 1638 |
| 180° | 2500 µs | 2048 |

16384 × 0.025 = 409.6，四舍五入 410；16384 × 0.125 = 2048。其余按 `pulse_us × 16384 / 20000` 算。

## 为什么舵机绝不能从主控 3.3 V 取电

三个数字叠起来就明白了：

1. SG90 启动瞬间要 700 mA ~ 1 A，MG996R 要 2.5 A。
2. ESP32 开发板的 3.3 V 由一颗 AMS1117 之类的 LDO 提供，额定 800 mA，**而且这 800 mA 还要分给 ESP32 自己（WiFi 发射峰值 240 mA）、OLED、传感器**。
3. 开发板的 5 V 来自 USB，USB 2.0 口限流 500 mA，超了主机直接切断或电压塌陷。

结果：

- **舵机不动**：电流不够，舵机内部电路反复复位。
- **ESP32 重启**：电压跌到 2.5 V 以下，brownout 触发，串口刷 `Brownout detector was triggered`。
- **最坑的一种**：不重启，但 WiFi 连不上、ADC 读数乱跳、I2C 偶发 NAK——因为电源已经脏了，但没有崩到复位。
- **烧 LDO**：长期过流，AMS1117 过热保护甚至烧毁，板子从此只能靠外部 3.3 V 供电。

:::warning[一个反直觉的现象]
把舵机接到开发板的 5V 脚，静态测试（舵机不动）一切正常，代码跑得好好的。一旦让它连续扫动，ESP32 就开始随机重启。
原因是静态时舵机只吃 10 mA，动态时才暴露电流缺口。**别用静态测试的结论判断供电够不够。**
:::

## 供电方案

### 方案 A：单舵机，临时验证

```text
USB 5V ──┬────────────── ESP32 5V 脚（开发板）
         │
         └── 舵机 VCC        ← 不行！USB 只有 500 mA
```

必须改成独立电源。

### 方案 B：独立 5 V 电源（推荐，2 ~ 4 个舵机）

```text
  5V / 3A 开关电源 或 UBEC（航模用的 5V 5A 降压）
        │
        +┼────────┬──────────┬──────────┬───── 舵机1 VCC
         │        │          │          └───── 舵机2 VCC
        === 1000µF 电解（耐压 10V 以上）
         │
        GND ──────┬──────────┬──────────┬───── 舵机1 GND
                  │          │          └───── 舵机2 GND
                  └──────────┴──── ESP32 GND   ← 共地，必须
        ESP32 GPIO18 ──────── 舵机1 信号（橙线）
        ESP32 GPIO19 ──────── 舵机2 信号
```

三个要素缺一不可：

1. **独立 5 V 电源**：电流按"舵机数量 × 单舵机堵转电流"估，2 个 SG90 至少 2 A，2 个 MG996R 至少 5 A。
2. **共地**：信号是相对 GND 的电压，不共地舵机会乱抖甚至完全不动。
3. **大电容**：1000 µF 电解并在电源入口，作用是吸收舵机换向瞬间的电流尖峰。**没有这个电容，多舵机系统一定会出现"一个动、另一个跟着抽一下"。**

### 关于 1000 µF 为什么必须加

舵机内部是直流电机 + 减速箱 + 电位器。启动瞬间线圈近似短路，电流阶跃上升。电源线上的等效电感（哪怕是 20 cm 的杜邦线，约 0.2 µH）会把这个电流阶跃变成电压跌落：

```text
ΔV = L × di/dt = 0.2µH × (2A / 1µs) = 0.4 V
```

再加上电源内阻和线阻，实际跌落能到 1 V 以上。电容的作用就是在这个微秒级的窗口里就近供电。
**电容要装在舵机附近，不是装在电源附近**——装在电源那头，线路电感还在。

### 方案 C：MOSFET 开关 + 分时供电（省电场景）

多个 MG996R 同时动作是不可能靠小电源撑住的。做法是**分时**：同一时刻只让一个舵机动，其余断电（用 PMOS 或负载开关切 VCC）。
代价是舵机会失去保持力矩，机械臂会垮下来，所以只适合"动作完就断电保持位置不重要"的场景。

## 代码一：Arduino（ESP32 core 3.x，LEDC 直接驱动）

```cpp
// 单舵机，14 位分辨率，50 Hz
constexpr int PIN_SERVO = 18;
constexpr int SERVO_FREQ = 50;
constexpr int SERVO_RES  = 14;
constexpr int SERVO_MAXD = (1 << SERVO_RES) - 1;   // 16383

void servoInit()
{
    ledcAttach(PIN_SERVO, SERVO_FREQ, SERVO_RES);    // core 3.x
    servoWriteUs(1500);                              // 先回中位，别从上电位置猛甩
    delay(500);
}

void servoWriteUs(int pulse_us)
{
    if (pulse_us < 500)  pulse_us = 500;    // 限位，防止机械顶死堵转
    if (pulse_us > 2500) pulse_us = 2500;
    // duty = pulse/20000 * 16384
    uint32_t duty = (uint32_t)pulse_us * (1u << SERVO_RES) / 20000u;
    if (duty > SERVO_MAXD) duty = SERVO_MAXD;
    ledcWrite(PIN_SERVO, duty);
}

void servoWriteDeg(int deg)
{
    if (deg < 0)   deg = 0;
    if (deg > 180) deg = 180;
    servoWriteUs(500 + deg * 2000 / 180);
}

// 平滑转动：别一步跳过去，机械冲击大、电流冲击也大
void servoSweepTo(int target_deg, int step_ms)
{
    static int cur = 90;
    int target = constrain(target_deg, 0, 180);
    while (cur != target) {
        cur += (target > cur) ? 1 : -1;
        servoWriteDeg(cur);
        delay(step_ms);
    }
}

void setup() { servoInit(); }

void loop()
{
    servoSweepTo(0,   15);
    delay(800);
    servoSweepTo(180, 15);
    delay(800);
}
```

用 `Servo` 库也可以（`ESP32Servo`，Arduino IDE 里搜这个名字，不要用官方 `Servo` 库，它不支持 ESP32）：

```cpp
#include <ESP32Servo.h>
Servo s;
void setup() {
    s.setPeriodHertz(50);            // 必须显式设 50Hz
    s.attach(18, 500, 2500);         // 引脚, 最小脉宽, 最大脉宽
}
void loop() { s.write(90); }
```

:::warning[attach 的三个参数]
`s.attach(pin, min_us, max_us)` 不给后两个参数时，库用的是默认行程，不同版本默认值不同，容易出现"写 0° 但舵机只转到 20°"。
显式给 500 / 2500，行为和裸写 LEDC 完全一致，出问题好排查。
:::

## 代码二：ESP-IDF

```c
#include "driver/ledc.h"
#include "freertos/FreeRTOS.h"
#include "freertos/task.h"
#include "esp_err.h"

#define SERVO_GPIO    GPIO_NUM_18
#define SERVO_CH      LEDC_CHANNEL_0
#define SERVO_RES     LEDC_TIMER_14_BIT      // 16384 级，50Hz 下完全合法
#define SERVO_MAXD    16383

static void servo_init(void)
{
    ledc_timer_config_t t = {
        .speed_mode      = LEDC_LOW_SPEED_MODE,
        .duty_resolution = SERVO_RES,
        .timer_num       = LEDC_TIMER_1,
        .freq_hz         = 50,
        .clk_cfg         = LEDC_AUTO_CLK,
    };
    ESP_ERROR_CHECK(ledc_timer_config(&t));   // 配不上会在这里直接打印行号并 abort

    ledc_channel_config_t c = {
        .gpio_num   = SERVO_GPIO,
        .speed_mode = LEDC_LOW_SPEED_MODE,
        .channel    = SERVO_CH,
        .timer_sel  = LEDC_TIMER_1,
        .duty       = 0,
        .hpoint     = 0,
    };
    ESP_ERROR_CHECK(ledc_channel_config(&c));
}

static void servo_us(int pulse_us)
{
    if (pulse_us < 500)  pulse_us = 500;
    if (pulse_us > 2500) pulse_us = 2500;
    uint32_t duty = (uint32_t)pulse_us * 16384u / 20000u;
    if (duty > SERVO_MAXD) duty = SERVO_MAXD;
    ledc_set_duty(LEDC_LOW_SPEED_MODE, SERVO_CH, duty);
    ledc_update_duty(LEDC_LOW_SPEED_MODE, SERVO_CH);
}

static void servo_deg(int deg)
{
    if (deg < 0)   deg = 0;
    if (deg > 180) deg = 180;
    servo_us(500 + deg * 2000 / 180);
}

void app_main(void)
{
    servo_init();
    servo_us(1500);                       // 上电先回中位
    vTaskDelay(pdMS_TO_TICKS(500));

    while (1) {
        for (int d = 0; d <= 180; d += 5) {
            servo_deg(d);
            vTaskDelay(pdMS_TO_TICKS(30));
        }
        for (int d = 180; d >= 0; d -= 5) {
            servo_deg(d);
            vTaskDelay(pdMS_TO_TICKS(30));
        }
    }
}
```

## 坑 1：抖动是电源问题，不是代码问题

舵机"抽动""嗡嗡抖""慢慢飘走"，90 % 是电源。可以用下面的方法二分：

| 测试 | 结果 | 结论 |
|---|---|---|
| 舵机接独立 5V 电源，只给信号，不连 ESP32 的地 | 完全不动 | 正常，说明必须共地 |
| 接上地，独立电源 3 A | 完全稳定 | 之前是供电不足 |
| 接上地，独立电源 3 A，仍抖 | 换一根更短更粗的线 | 线阻/线感太大 |
| 换线还抖 | 信号线受干扰 | 信号线远离电机线；PWM 频率确认是 50 Hz |
| 频率跑到 60 Hz 或 300 Hz | 抖动、发热 | 有些舵机对频率敏感，**必须是 50 Hz** |

还有一种"假抖动"：**代码里每次循环都重写 duty 且 duty 有 ±1 的量化跳动**。如果 `pulse_us` 是从浮点算出来的，先取整再写：

```c
uint32_t duty = (uint32_t)(pulse_us * 16384.0f / 20000.0f + 0.5f);   // +0.5 是四舍五入
```

## 坑 2：连续旋转舵机 ≠ 角度舵机

商品名里带 **"360°"、"连续旋转"、"continuous rotation"** 的舵机，内部电位器已经被拆掉或换成固定电阻，**没有位置反馈**。它的控制逻辑完全不同：

| 脉宽 | 角度舵机 | 连续旋转舵机 |
|---|---|---|
| 0.5 ms | 转到 0° | **全速反转** |
| 1.0 ms | 转到 45° | 中速反转 |
| **1.5 ms** | 转到 90° | **停转** |
| 2.0 ms | 转到 135° | 中速正转 |
| 2.5 ms | 转到 180° | **全速正转** |

所以：

- 给连续旋转舵机写 `servo.write(0)`，它不是"转到 0 度"，而是**一直朝一个方向全速转，转到底继续顶着堵转，几分钟后烧掉**。
- 想让它当轮子用，正确写法是 `writeMicroseconds(1500)` 停车，`1200` / `1800` 前后走。
- **买的时候一定要看清楚**。蓝色外壳、标签写着 "SG90" 的是角度舵机；写着 "SG90 360°" 或 "continuous" 的是旋转版。二者外观几乎一样。

## 坑 3：上电瞬间乱甩 / 一直顶着限位

- **上电乱甩**：很多舵机上电时会先冲向某个极端位置，因为内部没有绝对位置记忆。解决：`setup()` 里第一件事就写 1.5 ms 回中位，再 `delay(300)` 等它稳定，之后才开始业务逻辑。
- **一直顶着限位**：给 0° 或 180° 时，如果机械结构本身只允许 20° ~ 160°，舵机会持续输出扭矩对抗机械限位 → 电流拉满 → 发热 → 扫齿。
  **代码里把范围限死成 10° ~ 170°**，机械上也留 5° 余量：

```cpp
constexpr int DEG_MIN = 10, DEG_MAX = 170;
void servoSafe(int deg) {
    servoWriteDeg(constrain(deg, DEG_MIN, DEG_MAX));
}
```

- **别用手掰舵机盘**：会磨损塑料齿或让电位器错位。需要复位就断电再掰。

## 坑 4：多舵机同时动作 = 电流叠加

两个 MG996R 同时从静止启动，峰值 5 A。这时哪怕电源标称 5 V 5 A，线材和接插件也顶不住：

- 杜邦线单根载流约 1 A，超过就发热变色。
- 面包板每条簧片约 1 A。
- 建议：**舵机电源走独立的粗线（20 AWG 以上）直接到电源端子**，不要经过面包板；信号线可以走杜邦线。

多舵机还要注意**错峰启动**：给每个舵机的动作加 20 ~ 50 ms 的偏移，避免所有舵机在同一毫秒一起拉电流。

```c
servo_deg(0, ch1);                       // 立刻开始
vTaskDelay(pdMS_TO_TICKS(30));
servo_deg(0, ch2);                       // 30ms 后
vTaskDelay(pdMS_TO_TICKS(30));
servo_deg(0, ch3);
```

## 坑 5：3.3 V 信号驱动 5 V 舵机

舵机信号脚是 5 V 逻辑的输入，阈值一般是 0.3 × VCC ≈ 1.8 V，所以 **3.3 V 的 ESP32 信号绝大多数舵机能识别**，直接接就行。

例外：

- 部分大扭矩数字舵机（尤其是标 "HV" 高压舵机，工作在 7.4 V 时）阈值提高到 2.5 V 以上，3.3 V 勉强能用但抗干扰差 → 加一级 74HCT125 或 74HC14 做电平缓冲。
- 信号线超过 30 cm 时，3.3 V 摆幅 + 长线电容会让边沿变缓，表现为"偶尔不动"。解决：缩短信号线，或在信号线上串联 100 Ω 电阻抑制振铃，**不要**加上拉（有些舵机信号是双向的）。

## 快速排查表

| 现象 | 最可能原因 | 处理 |
|---|---|---|
| 完全不动、不发热 | 没共地 / 信号脚错 / 电源没接 | 量 VCC 对 GND、量信号脚有没有 PWM |
| 完全不动、发烫 | 脉宽超出范围顶着限位 | 先写 1.5 ms，量信号 |
| 抖动、抽搐 | 供电不足或线太长 | 独立电源 + 1000 µF |
| ESP32 反复重启 | 舵机从板子取电 | 独立电源，共地 |
