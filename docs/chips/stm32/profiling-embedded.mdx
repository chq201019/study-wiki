# 嵌入式功耗与性能测量

**本课目标**：能测出真实的电流曲线和代码耗时。

## 测电流：万用表为什么不够

:::danger[万用表测不准的三个原因]
1. **电流档内阻大**（几百欧），在 µA 级会产生明显压降，改变电路工作状态
2. **采样率低**（几 Hz），跟不上 mA 与 µA 的毫秒级切换
3. **只显示平均值**，看不到峰值和占空比

**你要知道的是"每次唤醒持续多久、峰值多少、平均多少"** —— 这些都是万用表给不了的。
:::

:::tip[正确做法：采样电阻 + 示波器]
```text
电源 ──[R 10Ω]── 板子
            |
         示波器探头（差分或两个通道相减）
```

**电流 = 电阻两端压降 / R**

**10Ω 电阻在 100mA 时压降 1V** —— 可测且不影响工作。

**测 µA 级要用更大电阻（1kΩ）**，但要确认压降在可接受范围。
:::

## 读功耗曲线

:::info[一条功耗曲线包含三段信息]
```text
电流
 |    ┌──┐
 |    │  │
 |────┘  └──────────────
 +----+--+--------------> 时间
      A  B
```

- **峰值 A**：唤醒瞬间（射频发射、外设启动）
- **持续段**：工作时间
- **平台段**：休眠电流

**平均电流 = 曲线下的面积 / 总时间** —— 不是峰值和休眠值的简单平均。
:::

:::warning[常见误算]
```text
每小时醒一次，醒时 100mA 持续 1 秒，其余 20µA

正确：(100mA x 1s + 0.02mA x 3599s) / 3600s = 0.0478mA
错误：(100 + 0.02) / 2 = 50mA          ← 差 1000 倍
```
:::

## 测代码耗时：DWT

```c
void dwt_init(void)
{
    CoreDebug->DEMCR |= CoreDebug_DEMCR_TRCENA_Msk;
    DWT->CYCCNT = 0;
    DWT->CTRL |= DWT_CTRL_CYCCNTENA_Msk;
}

uint32_t t0 = DWT->CYCCNT;
do_work();
uint32_t cycles = DWT->CYCCNT - t0;      /* 无符号减法自动处理回绕 */
```

:::danger[三个必须注意的点]
**① 溢出**：32 位在 72MHz 下约 59 秒回绕一次，用无符号减法可自动处理

**② 中断干扰**：测量期间被中断打断，结果包含中断时间 —— **取多次最小值最能反映真实耗时**

**③ 代码被优化掉**：空循环会被删，函数可能被内联 —— 用 volatile 或 noinline
:::

## GPIO 翻转 + 示波器

```c
GPIOC->BSRR = GPIO_BSRR_BS13;      /* 拉高 */
do_work();
GPIOC->BSRR = GPIO_BSRR_BR13;      /* 拉低 */
```

:::tip[这是嵌入式最经典的测量手段]
**优点**：几乎不影响被测代码、能看到抖动分布、能同时测多段（用不同引脚）、不需要改代码逻辑

**缺点**：需要示波器

**用 BSRR 而不是 ODR** —— ODR 是读改写，多几个周期。
:::

## 三个"测不准"的常见原因

:::danger[① 测的不是芯片，是整块板]
**开发板的 USB 转串口芯片、LDO 静态电流、电源指示灯 LED** 可能吃掉 1~5mA。

**测芯片功耗必须用裸模块，或断开板上稳压器改外部供电。**
:::

:::danger[② 示波器探头本身的影响]
**普通探头的接地夹会引入额外电感**，测快速电流跳变时波形失真。

**测微小电流建议用电流探头或专用功耗分析仪**（Nordic PPK2、Joulescope）。
:::

:::danger[③ 测试条件与真实场景不一致]
**温度、供电电压、WiFi 信号强度、外设负载** 都会显著影响功耗。

**要测"真实场景"就得在真实条件下测** —— 实验室的室温空载数据往往偏乐观。
:::

## 常见坑

| 现象 | 原因 | 解决 |
| --- | --- | --- |
| 电流比预期大 100 倍 | 板上的 LED 或串口芯片 | 用裸模块 |
| 测不出 µA 级 | 万用表内阻与采样率 | 用采样电阻加示波器 |
| 平均电流算错 | 用了"峰谷平均"而非面积 | 按时长加权 |
| 代码耗时测出 0 | 被优化掉了 | volatile 或 noinline |
| 耗时忽大忽小 | 中断打断 | 取最小值 |
| DWT 结果乱跳 | 溢出了 | 用无符号减法 |
| WiFi 功耗波动大 | 信号强度不同 | 固定测试环境 |

:::warning[测功耗前先确认"真的睡了"]
**如果串口还在打日志，说明它根本没睡下去。**

**在进入低功耗前打一行日志，睡下去之后应该完全没有输出。**
:::
