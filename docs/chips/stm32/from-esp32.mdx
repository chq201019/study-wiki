# ESP32 ↔ STM32 迁移对照

前几页的方言都散在各处，这一页做**总对账**：把两个体系逐个概念摆在一起。看完这张表，"换芯片"就从"重学"降级成"查表"。前半是概念对照（永久有用），后半是换边翻车清单（上手时用）。

## 1. 芯片架构概念对照

| 概念 | ESP32-S3 | STM32F1/F4 | 谁更"看得见" |
| --- | --- | --- | --- |
| 内核 | Xtensa LX7（私有指令集）+ RISC-V 协核 | Arm Cortex-M（行业标准指令集） | STM32——Cortex 生态（CMSIS）跨厂通用 |
| 主频来源 | 固件启动时配 PLL（menuconfig 配好） | **你的代码**跑 `SystemClock_Config` 现场倍频 | STM32——时钟树是必修课 |
| 程序放哪 | 外挂 QSPI Flash，经 cache 执行 | **片内 Flash 原地执行**（零等待） | 各有取舍（见下） |
| RAM | 512KB 片内 + 8MB 外挂 PSRAM | 20~192KB 片内，无 PSRAM（H7 有大 RAM 变体） | —— |
| 外设到引脚 | GPIO 矩阵，**几乎任意映射** | 复用表（AF 表），每信号固定候选集 | ESP32 自由得多 |
| 外设时钟 | 默认开，驱动按需门控 | **默认关**，用前必须 `__HAL_RCC_XXX_CLK_ENABLE` | STM32 显式 |
| 中断控制器 | INTC（乐鑫自研） | NVIC（Arm 内核件，全行业一致） | Cortex 通用知识 |
| 启动方式 | ROM bootloader → 读分区表 → 加载 app | BOOT 引脚选启动区 → 启动文件 → main | 两种哲学，都该懂 |
| 无线 | 芯片自带 WiFi/BLE | 无（外挂模块或选 WB/WL 家族） | —— |

### 两个值得展开的"哲学差异"

**程序执行位置**。ESP32 把大 Flash 放片外，靠 cache 把"慢 Flash"跑出"快代码"的体感，代价是 cache miss 抖动 + 分区表复杂性；STM32 把 Flash 放片内，取指零等待、行为可预测（实时性好），代价是 Flash 大小限制了程序规模（64KB 的 F103 跑不了大中间件）。**IoT 场景（ESP32）看重"程序大、功能多"，控制场景（STM32）看重"确定性强、延迟稳定"**——很多"为什么用它不用它"的争论根源在这。

**引脚自由度**。ESP32 的 GPIO 矩阵（[L4 讲过](../../course/l4-peripherals/gpio)）允许"串口想去哪个脚去哪个脚"；STM32 的复用表是"USART1_TX 只能落 PA9/PA6 等固定候选"。设计电路时 STM32 必须先定引脚再画板，ESP32 可以先画板再定引脚。反过来看：STM32 引脚功能固定意味着**PCB 走线短、外设间干扰可控**——自由度的代价是布线随意性，工业设计反而喜欢约束。

## 2. 工具与开发流对照

| 环节 | ESP32 流 | STM32 流 | 迁移提示 |
| --- | --- | --- | --- |
| 配置外设 | menuconfig + 代码传参 | **CubeMX 画图生成** | 接受"图形化"不是退步，是 ST 生态的标准姿势 |
| 写代码 | VSCode + IDF | CubeIDE/Keil + HAL | `USER CODE` 区纪律要养成 |
| 编译 | `idf.py build`（CMake） | IDE 内置构建 | 独立工具链 `arm-none-eabi-gcc` 与 IDF 的 gcc 同宗 |
| 烧录 | `idf.py flash`（串口 esptool） | **ST-Link SWD**（CubeProgrammer） | SWD 多了断点调试能力，是升级不是降级 |
| 调试 | 串口日志 + `idf.py monitor` | **断点/单步/看变量**（SWD）+ 串口 | 先学断点调试，效率翻倍 |
| OTA | 分区表 + `esp_ota_*` 现成 | **没有现成的**，IoT 场景选 WB/带外挂 Flash 自建或上 IAP 方案 | 远程升级是 ESP32 的舒适区 |
| 库生态 | idf 组件注册表 + Arduino 库 | 手动集成 + HAL 中间件 + STM32duino | ESP32 加库"npm 般顺滑"，STM32 更像"自己搭" |

## 3. 换边翻车清单

### ESP32 → STM32（本专栏主线方向）

| 症状 | 病根 | 对应页 |
| --- | --- | --- |
| 写了寄存器/外设毫无反应 | 外设时钟没开（ESP32 没有"外设时钟默认关"概念） | [第一个工程 §4](./first-project) |
| 引脚配不了想要的功能 | 复用表约束，那个信号落不到那个脚 | 本页 §1 |
| 烧一次后调试器失联 | Debug 没配 Serial Wire，SWD 脚被复用 | [第一个工程常见坑](./first-project) |
| I2C 全线搜不到设备 | HAL 地址要 `<<1`；总线没外接上拉 | [外设实战 §5](./peripherals) |
| 任务里 `HAL_Delay` 卡顿 | SysTick 归 RTOS 后 HAL_Delay 变忙等，换 `osDelay` | [进阶 §2](./rtos-dma-power) |
| 数组一开就 OOM | 没有 PSRAM 兜底，20KB SRAM 按字节规划 | [进阶 §2](./rtos-dma-power) |
| Stop 唤醒后串口乱码 | 唤醒后时钟回落 8MHz，要重配时钟树 | [进阶 §3](./rtos-dma-power) |
| printf 没输出 | 没重定向 `fputc/__io_putchar` | [外设实战 §2](./peripherals) |

### STM32 → ESP32（反向也有，常见于老同事）

| 症状 | 病根 |
| --- | --- |
| 找不到"开 GPIO 时钟"的函数 | ESP32 没有这层，直接 `gpio_config` |
| 想把串口 TX 固定"复用"到某脚被 API 混淆 | GPIO 矩阵任意映射，随便指 |
| Flash 不够的焦虑不适用 | 外挂 16MB Flash + 分区表，程序可以很大 |
| `delay(500)` 编译不过/变忙等 | ESP32 默认带 RTOS，用 `vTaskDelay(pdMS_TO_TICKS(500))` |
| 中断服务函数里做了太多事 | ESP32 推荐 ISR 入队、任务处理（`xQueueSendFromISR`），STM32 习惯同样适用 |

## 4. 收束：学完两颗之后

到这里你已经踩过两个大厂的完整体系，可以抽象出**"任何 MCU 通用学习模板"**：

1. **背资源预算**：内核/主频/RAM/Flash——决定项目上限
2. **搞懂时钟树**：主频从哪来、每个外设挂在哪条总线上限多少
3. **读引脚约束表**：strapping/复用/专用脚——硬件设计不返工
4. **走通启动流程**：从复位到 main 的每一步——出事知道往哪查
5. **配一圆形外设**：GPIO → UART → 定时器 → 总线 → ADC
6. **上 RTOS 与 DMA**：并发与数据流是"玩具项目"和"产品"的分水岭
7. **吃透调试与烧录**：断点调试能力 = 学习速度倍增器

第三颗芯片（无论 GD32、RP2040 还是 nRF52）套这个模板，通常一两天就能上手——这就是"通用嵌入式"的本义，也是本专栏存在的目的。
