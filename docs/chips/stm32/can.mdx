# 13 CAN 总线

**本课目标**：会算波特率、会配过滤器、知道 CAN 为什么可靠。

## 为什么汽车都用 CAN

:::info[CAN 的三个硬实力]
| 特性 | 说明 |
| --- | --- |
| **差分传输** | CAN_H / CAN_L 一对双绞线，共模干扰被抵消 |
| **非破坏性仲裁** | 多节点同时发，ID 小的自动优先，**没有任何数据被破坏** |
| **硬件级错误处理** | CRC、位填充、应答、错误计数、自动重发，全在硬件完成 |

**代价**：最高 1 Mbps（CAN 2.0），一帧最多 8 字节数据。
:::

## 硬件接线

```text
节点A ────┬──────────────┬──── 节点B
          │              │
        120Ω           120Ω       ← 只在总线两端各一个
          │              │
        CAN_H ────────────
        CAN_L ────────────
```

:::danger[终端电阻：必须两个，不多不少]
- **只在总线最两端各接一个 120Ω**
- 中间节点**不接**
- 只接一个 → 反射严重，长距离通信失败
- 接多了 → 总线负载过重，幅值变小

**测量方法**：断电后用万用表量 CAN_H 到 CAN_L 的电阻，**应该是 60Ω**（两个 120Ω 并联）。
:::

:::warning[不要用普通杜邦线做 CAN]
CAN 是差分信号，**必须用双绞线**（CAN_H 和 CAN_L 绞在一起）。

用两根平行杜邦线时，干扰无法抵消，**1 Mbps 下几十厘米就开始出错**。

**短距离（`<30cm`）实验可以凑合，产品必须用双绞线。**
:::

## 非破坏性仲裁

:::tip[核心规则：显性（0）压过隐性（1）]
```text
节点A 要发 ID = 0x123  (二进制 ...001 0010 0011)
节点B 要发 ID = 0x456  (二进制 ...100 0101 0110)

逐位比较（从高位开始）：
  A: 0 0 1 0 0 1 0 0 0 1 1
  B: 1 0 0 0 1 0 1 0 1 1 0
     ↑
  第一位 A 发 0（显性），B 发 1（隐性）
  → 总线呈现显性 0
  → B 检测到自己发的是 1 但总线是 0 → 知道有人优先级更高 → 主动退出
  → A 继续发完，B 下一轮再试
```

**关键**：B 退出时**总线上的数据完全没被破坏**，A 甚至不知道发生过竞争。
:::

:::danger[所以 CAN ID 越小优先级越高]
**这是硬件决定的，不是软件约定。**

设计 CAN 协议时：

- **安全/实时性要求高的消息用小编号**（如急停、碰撞信号）
- **大数据量、不着急的用大编号**（如诊断日志）

**不要用"平均分配"的思路编 ID**，否则关键消息可能被日志消息堵住。
:::

## 位时序与波特率

:::info[CAN 的一个位被分成三段]
```text
|<---------------- 1 bit -------------->|
| SYNC_SEG |   BS1（相位缓冲1）  | BS2 |  
|  1 Tq    |      N Tq          | M Tq|
                    ↑
                 采样点（一般放在 87.5% 处）
```

**Tq = 时间份额 = CAN 时钟分频后的一拍**
:::

**波特率公式**：

```text
CAN 时钟 = PCLK1（APB1，F103 上通常 36 MHz）
波特率 = CAN时钟 / (Prescaler × (1 + BS1 + BS2))
```

:::tip[算一个 500 kbps 的例子]
```text
目标：500 kbps，PCLK1 = 36 MHz

36 MHz / 500 kHz = 72  →  Prescaler × (1 + BS1 + BS2) = 72

选 Prescaler = 9：
  1 + BS1 + BS2 = 8
  采样点放在 87.5% → BS1 = 87.5% × 8 - 1 = 6，BS2 = 1

验证：36MHz / (9 × (1+6+1)) = 36M / 72 = 500 kHz  ✅
```

**CubeMX 里填 500 kbps 和 87.5% 采样点，它自动算好。**
:::

:::warning[采样点的经验值]
| 场景 | 推荐采样点 |
| --- | --- |
| 一般应用 | **87.5%** |
| 长距离 / 多节点 | 75~80%（留更多余量给传播延迟） |
| 短距离高速 | 87.5% |

**采样点配错会表现为"距离一长就丢帧"，而短距离测试完全正常** —— 很难查。
:::

## 过滤器：CAN 最容易卡住的部分

:::danger[F103 有 14 个过滤器组，不是"14 个过滤器"]
**每个过滤器组可以配成不同模式**：

| 模式 | 作用 |
| --- | --- |
| **屏蔽位模式（Mask）** | 一位掩码 + 一位值，**一组覆盖一批 ID** |
| **标识符列表模式（List）** | 一组存 2 或 4 个精确 ID |

**另有 `FIFO0` / `FIFO1` 两个接收队列可分配。**
:::

```c
/* 屏蔽位模式：接收 0x123 和 0x12x（低 4 位任意） */
CAN_FilterTypeDef f = {0};

f.FilterBank           = 0;                      /* 用第 0 组 */
f.FilterMode           = CAN_FILTERMODE_IDMASK;
f.FilterScale          = CAN_FILTERSCALE_32BIT;  /* 32 位模式能覆盖 11/29 位 ID */
f.FilterIdHigh         = (0x123 << 5);           /* 标准 ID 左移 5 位 */
f.FilterIdLow          = 0;
f.FilterMaskIdHigh     = (0x7F0 << 5);           /* 掩码：这几位必须匹配 */
f.FilterMaskIdLow      = 0;
f.FilterFIFOAssignment = CAN_FILTER_FIFO0;
f.FilterActivation     = ENABLE;

HAL_CAN_ConfigFilter(&hcan, &f);
```

:::danger[标准 ID 必须左移 5 位]
```c
f.FilterIdHigh = (0x123 << 5);
```

**因为寄存器里 ID 字段不是从 bit0 开始的**（bit15~bit5 存 11 位标准 ID）。

**不左移的话过滤器永远不匹配**，表现是"发出来的帧收不到，但示波器上明明有波形"。

**CubeMX 会自动左移，手写代码要注意。**
:::

:::tip[过滤器配不对的排查方法]
**先配一个"全通"过滤器确认链路正常**：

```c
f.FilterIdHigh     = 0;
f.FilterIdLow      = 0;
f.FilterMaskIdHigh = 0;
f.FilterMaskIdLow  = 0;      /* 掩码全 0 = 全部接收 */
```

**能收到所有帧 → 链路正常，问题在过滤器配置。**
:::

### 接收中断

```c
/* 使能 FIFO0 消息挂起中断 */
HAL_CAN_ActivateNotification(&hcan, CAN_IT_RX_FIFO0_MSG_PENDING);

void HAL_CAN_RxFifo0MsgPendingCallback(CAN_HandleTypeDef *h)
{
    CAN_RxHeaderTypeDef rx;
    uint8_t data[8];

    if (HAL_CAN_GetRxMessage(h, CAN_FIFO0, &rx, data) != HAL_OK) return;

    uint32_t id = rx.StdId;      /* 标准 ID 在这 */
    uint8_t  len = rx.DLC;       /* 数据长度 0~8 */
    /* 处理 data[0..len-1] */
}
```

## 发送

```c
CAN_TxHeaderTypeDef tx = {0};
tx.StdId   = 0x123;
tx.IDE     = CAN_ID_STD;
tx.RTR     = CAN_RTR_DATA;
tx.DLC     = 8;

uint8_t data[8] = {0};
uint32_t mailbox;

if (HAL_CAN_AddTxMessage(&hcan, &tx, data, &mailbox) != HAL_OK) {
    /* 三个邮箱都满了，稍后重试 */
}
```

:::warning[发送邮箱只有 3 个]
F103 的 CAN 有 **3 个发送邮箱**。三个都占着时 `HAL_CAN_AddTxMessage` 返回 `HAL_ERROR`。

**连续发多帧时必须处理这个返回值**，否则会静默丢帧。

**典型场景**：一次要发 10 帧数据，必须等前面的发完再发（或者用队列 + 中断驱动）。
:::

## 常见坑

| 现象 | 原因 | 解决 |
| --- | --- | --- |
| 完全收不到任何帧 | 终端电阻不对 / 没接 | 断电量 CAN_H-CAN_L 应为 60Ω |
| 示波器有波形但收不到 | 过滤器不匹配 | 先配全通过滤器验证 |
| 过滤器永不匹配 | 标准 ID 没左移 5 位 | `(id << 5)` |
| 短距离正常，长距离丢帧 | 采样点或终端电阻错 | 调采样点、检查两端 120Ω |
| **一旦有错就全总线瘫痪** | 某个节点持续发错误帧 | 查那个节点的供电和接地 |
| 只能收到一帧 | 没清接收标志 | 用中断方式，别用轮询 |
| 发送返回 HAL_ERROR | 3 个邮箱满了 | 等 `HAL_CAN_GetTxMailboxesFreeLevel` |
| 波特率算出来不对 | 忘了 `1 + BS1 + BS2` | 公式里那个 1 是 SYNC_SEG |
| 进入 init 模式失败 | `HAL_CAN_Start` 前没 `HAL_CAN_Init` | 顺序问题 |

:::danger[CAN 总线"一坏全坏"的排查]
**CAN 的一个节点如果硬件故障（收发器坏、供电异常），它可能持续输出错误帧，把整条总线拖垮** —— 因为 CAN 的错误帧会覆盖正常数据。

**排查方法**：**逐个拔节点**，拔到总线恢复就找到元凶了。

**预防**：用带隔离的 CAN 收发器（如 TJA1050 + 光耦，或 ISO1050），故障不会扩散。
:::

:::tip[CAN 的四种错误类型（看错误计数器）]
| 错误 | 含义 |
| --- | --- |
| 位错误 | 发出的位和读回的不一致 |
| 填充错误 | 6 个相同电平连续出现（违反位填充规则） |
| CRC 错误 | 校验不对 |
| 格式错误 | 固定格式字段不符 |

**读 `CAN_ESR` 寄存器能看到错误计数**：

- 计数 < 96：正常
- 96 ~ 127：警告
- **> 127：节点进入被动错误状态**（只能发隐性位，等于残废）
- **> 255：总线关闭（Bus-Off）**，节点完全脱离总线，需要恢复流程
:::
