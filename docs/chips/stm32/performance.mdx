# 12 性能优化与代码尺寸

**本课目标**：能测出代码到底多慢，知道优化往哪儿使劲。

## 先测，再优化

:::danger[没有测量就没有优化]
**"我觉得这段慢"** 是最常见的错误出发点。

**在 72MHz 的 F103 上，很多人以为慢的地方其实只要几微秒，真正慢的地方（比如 `printf` 里的浮点格式化）却被忽略了。**

**必须先测。**
:::

### 用 DWT 周期计数器精确测量

:::tip[Cortex-M3 内置的免费秒表]
```c
void dwt_init(void)
{
    CoreDebug->DEMCR |= CoreDebug_DEMCR_TRCENA_Msk;   /* 使能跟踪 */
    DWT->CYCCNT = 0;
    DWT->CTRL |= DWT_CTRL_CYCCNTENA_Msk;              /* 启动计数器 */
}

static inline uint32_t dwt_get(void)
{
    return DWT->CYCCNT;                                /* 32 位，72MHz 下约 59 秒溢出 */
}
```

**用法**：

```c
dwt_init();

uint32_t t0 = dwt_get();
do_something();
uint32_t cycles = dwt_get() - t0;

/* 换算成微秒：cycles / 72 */
printf("耗时 %lu 周期，约 %lu us\r\n", cycles, cycles / 72);
```
:::

:::warning[DWT 的三个注意点]
**① 溢出**：32 位计数器在 72MHz 下约 59 秒回绕一次。测超过 59 秒要自己累计。

**② 测量本身有开销**：`dwt_get()` 是几条指令（约 5~10 周期）。测极短的代码要减掉。

**③ 别在中断里测**：中断会插进来，测出的时间包含中断耗时。
:::

### 用 GPIO 翻转 + 示波器

```c
GPIOC->BSRR = GPIO_BSRR_BS13;      /* 拉高 */
do_something();
GPIOC->BSRR = GPIO_BSRR_BR13;      /* 拉低 */
```

**示波器直接看脉宽**——比任何软件计时都直观，而且不干扰被测代码的时序（只多两条 IO 指令）。

:::tip[这是嵌入式最经典的性能测量手段]
**优点**：

- 不影响被测代码的执行（除了两条 IO 写）
- 能看出抖动和分布（不只是一个平均值）
- 能同时测多段代码（用不同引脚）

**缺点**：需要示波器或逻辑分析仪。
:::

## 优化级别怎么选

| 级别 | 速度 | 体积 | 适合 |
| --- | --- | --- | --- |
| `-O0` | 最慢 | 最大 | **调试**（变量可完整查看，单步符合直觉） |
| `-O1` | 中 | 中 | 一般开发 |
| **`-O2`** | **快** | 中大 | **发布默认** |
| `-Os` | 中 | **最小** | **Flash 紧张时** |
| `-O3` | 最快 | 大 | 计算密集（可能反而变大变慢） |
| `-Ofast` | 最快 | 大 | **会改变浮点语义，嵌入式慎用** |

:::danger[`-O0` 和 `-O2` 的行为差异会让你怀疑人生]
**典型现象**：

```c
/* -O0 下能跑，-O2 下死循环 */
while (!(USART1->SR & USART_SR_TXE)) { }
```

**原因**：`-O2` 下编译器把 `USART1->SR` 缓存在寄存器里，只读一次。

**解决**：寄存器定义本身带 `volatile`（CMSIS 头文件已处理），所以这条一般没问题；**但自己定义的延时循环变量忘了 `volatile` 就会被优化掉**。

```c
for (uint32_t i = 0; i < 72000; i++) { }        /* ❌ 被删掉 */
for (volatile uint32_t i = 0; i < 72000; i++) { }  /* ✅ 保留（但仍不精确） */
```
:::

:::warning[调试断言也要跟着优化级别走]
```c
#ifdef DEBUG
    #define ASSERT(x)  do { if (!(x)) { while(1); } } while(0)
#else
    #define ASSERT(x)  ((void)0)      /* 发布版彻底去掉 */
#endif
```

**发布版留着大量 `assert` 会白白吃掉几 KB Flash。**
:::

## Flash 等待周期与预取

![STM32 Flash 等待周期与预取缓冲：72MHz 需 2 个等待周期，开启预取后顺序代码速度提升接近一倍](/img/diagrams/stm32-flash-wait.svg)


:::info[72MHz 下 CPU 比 Flash 快]
```text
Flash 读取速度跟不上 72MHz 的 CPU
  → 必须插入 2 个等待周期（FLASH_LATENCY_2）
  → 每条取指要等
```

**STM32F1 的 Flash 有一个"预取缓冲"（Prefetch Buffer）**：

```c
FLASH->ACR |= FLASH_ACR_PRFTBE;      /* 使能预取 */
```

**作用**：取指时一次读 64 位（2 条指令），下一条直接从缓冲拿，不用再等。

**效果**：**顺序执行的代码速度能提升接近一倍**；跳转频繁的代码收益小。
:::

:::tip[由此得出的两条优化直觉]
**① 循环比展开好**（循环体是顺序执行，预取命中率高）

**② 减少函数调用和分支**（跳转会打断预取）

**③ 把热点循环放到 RAM 里跑**（RAM 没有等待周期）

```c
/* 把函数拷到 RAM 执行（F1 需要链接脚本配合） */
__attribute__((section(".ramfunc"))) void hot_loop(void) { /* ... */ }
```

**F1 的 RAM 只有 20KB，要省着用。**
:::

## 查表 vs 实时计算

:::tip[什么时候查表值得]
```c
/* 实时算 sin（浮点）*/
float slow(float x) { return sinf(x); }

/* 查表 + 线性插值 */
static const int16_t sin_table[91] = { 0, 286, 572, ... };   /* 0~90 度，步长 1 度 */

int16_t fast_sin(uint16_t deg)
{
    deg %= 360;
    if (deg <= 90)  return sin_table[deg];
    if (deg <= 180) return sin_table[180 - deg];
    if (deg <= 270) return -sin_table[deg - 180];
    return -sin_table[360 - deg];
}
```

**判断标准**：

| 情况 | 查表 |
| --- | --- |
| 输入范围有限、精度要求中等（如 1° 分辨率） | ✅ **查表快几十倍** |
| 输入范围很大、精度要求高 | ❌ 表太大，还是算吧 |
| Flash 已经吃紧 | ❌ 表很占 Flash |

**91 个 int16 = 182 字节，换来几十倍速度——这在 F103 上几乎总是划算的。**
:::

## 定点运算代替浮点

:::danger[F103 没有 FPU，浮点靠软件模拟]
**STM32F103 是 Cortex-M3，没有硬件浮点单元。**

```text
一次 float 加法：约 50~100 周期（软件模拟）
一次 int32 加法：1 周期
```

**差 50~100 倍。**
:::

:::tip[定点数的做法]
用"放大若干倍存成整数"来表示小数：

```c
/* 表示电压，精度 1mV，用 int32 存"毫伏" */
int32_t voltage_mv = 3300;                  /* 3.300 V */

/* 乘法：结果要除回放大倍数 */
int32_t power_mw(int32_t mv, int32_t ma)
{
    return (mv / 1000) * ma;                /* 先除后乘，避免溢出 */
}

/* 需要更高精度时用 int64 中转 */
int32_t scale(int32_t a, int32_t b, int32_t div)
{
    return (int32_t)(((int64_t)a * b) / div);
}
```

**要点**：

- **先乘后除**能保住精度，但要注意溢出 → 用 `int64_t` 中转
- **放大倍数用 2 的幂**（如 1024、65536）时，乘除可以变成移位
:::

:::tip[什么时候必须用浮点]
- 需要极宽的动态范围（如 1e-9 ~ 1e9）
- 算法本身对数值稳定性敏感（如矩阵求逆）
- 开发时间 > 运行时间（原型阶段）

**F4 以上有 FPU，浮点开销小得多**——如果你的项目真的需要浮点，换 F4 比硬写定点更划算。
:::

## 减小固件体积

:::info[先看体积花在哪]
```bash
arm-none-eabi-size -A build/app.elf        # 按段列出
arm-none-eabi-nm --size-sort -S build/app.elf | tail -30   # 最大的符号
```

**先找出最大的几个符号**，往往能发现意外：一个没用的大数组、一个带格式化的 `printf`、一份重复的字符串表。
:::

| 手段 | 典型收益 | 代价 |
| --- | --- | --- |
| **关掉 `printf` 浮点支持** | **几 KB** | 不能 `%f` |
| **用 `-Os`** | 10~20% | 稍慢 |
| **`--gc-sections`**（默认开） | 删掉未用函数 | 无 |
| **`-ffunction-sections -fdata-sections`** | 配合上一条，效果更好 | 无 |
| **用 `puts` 代替 `printf`** | 几百字节 | 无格式能力 |
| **去掉 `assert`** | 视数量 | 少了检查 |
| 查表代替计算 | **增加**体积 | 换速度 |

:::danger[`printf` 是 Flash 杀手]
```c
printf("temp = %f\r\n", t);      /* 引入浮点格式化，几 KB */
printf("temp = %d\r\n", (int)t); /* 只用整数格式化，小得多 */
```

**newlib-nano 已经精简过，但浮点格式化仍然很贵。**

**如果 Flash 紧张，先查 `printf` 用了多少。**
:::

:::tip[完全不要 `printf` 的替代方案]
```c
/* 自己写一个极简输出 */
void uart_puts(const char *s)
{
    while (*s) {
        while (!(USART1->SR & USART_SR_TXE)) { }
        USART1->DR = *s++;
    }
}

/* 整数转字符串 */
void uart_put_u32(uint32_t v)
{
    char buf[11];
    int i = 10;
    buf[i] = 0;
    do { buf[--i] = '0' + (v % 10); v /= 10; } while (v);
    uart_puts(&buf[i]);
}
```

**几十字节就能替代 `printf` 的常用部分**。
:::

## 一个优化的实际顺序

:::tip[按这个顺序做，收益最大]
**① 先测量**——找出真正的热点（往往是中断和循环）

**② 降级热点到寄存器/LL**——见[第 01 课](./hal-ll-register)，收益 2~10 倍

**③ 把热点数据放 RAM / 把热点函数拷到 RAM**

**④ 查表代替计算**（三角函数、对数、CRC）

**⑤ 定点代替浮点**（没有 FPU 时）

**⑥ 减少函数调用**（`static inline`）

**⑦ 最后才动优化级别**——`-O2` → `-O3` 的收益通常小于前六项
:::

:::warning[不要过早优化]
**先让代码正确、可读，再优化。**

**优化后的代码往往丑陋且难维护**——只在"确实测量出是热点"的地方做，并且**在代码里写清楚为什么这么写**：

```c
/* 这里用查表而不是 sinf()：
 * 每 100us 调用一次，sinf() 需约 800 周期，
 * 查表只需约 20 周期，实测让主循环周期从 130us 降到 45us。
 */
```

**没有注释的优化，半年后连你自己都不敢改。**
:::

## 常见坑

| 现象 | 原因 | 解决 |
| --- | --- | --- |
| `-O2` 下延时变短 | 循环变量被优化 | 加 `volatile`（但仍不精确） |
| 优化后行为变了 | 依赖了未定义行为（如溢出、乱序访问） | 检查 `volatile` 和严格别名 |
| DWT 测出 0 | 没使能 TRCENA 或 CYCCNTENA | 检查初始化 |
| 测出的时间不稳定 | 被中断打断 | 关中断测或减去中断时间 |
| Flash 快满了 | `printf` 浮点 / 大数组 | `-Os`、去浮点、查符号表 |
| 换 `-Os` 后反而变慢很多 | 关键循环被展开后又收缩 | 只对该文件用 `-O2` |
| 查表反而更慢 | 表太大导致 Flash 缺页/等待 | 表放 RAM 或缩小表 |

:::danger[严格别名（strict aliasing）会咬人]
```c
float f = 1.0f;
uint32_t u = *(uint32_t *)&f;      /* ❌ 违反严格别名，-O2 下可能出错 */
```

**正确做法**：

```c
uint32_t u;
memcpy(&u, &f, sizeof(u));         /* ✅ 编译器会优化成一条指令 */
```

**或者用 `union`**（C 标准允许，C++ 里也有明确的规则）。
:::
