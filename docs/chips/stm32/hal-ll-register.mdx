# 01 HAL / LL / 寄存器：三种抽象层

**本课目标**：知道自己在用哪一层、代价多少、什么时候该降级。

## 三层的关系

```text
你的代码
   ↓
┌──────────────────────────────┐
│ HAL  硬件抽象层                │  ← 最厚：状态机、超时、回调
├──────────────────────────────┤
│ LL   轻量层                    │  ← 中间：静态内联，接近寄存器
├──────────────────────────────┤
│ CMSIS / 寄存器定义             │  ← 最薄：结构体映射到地址
├──────────────────────────────┤
│ 硬件                           │
└──────────────────────────────┘
```

:::info[三层不是互斥的]
**同一个工程里可以混用**：

```c
/* 初始化用 HAL（省事不易错） */
HAL_Init();
MX_GPIO_Init();

/* 高频路径用寄存器（省时间） */
GPIOC->BSRR = GPIO_BSRR_BS13;

/* 两者操作的是同一个硬件，不会冲突 */
```

**关键是要知道每一行代码走的是哪一层。**
:::

## 同一个功能，三份实现

### 点灯

```c
/* HAL：最厚 */
HAL_GPIO_WritePin(GPIOC, GPIO_PIN_13, GPIO_PIN_RESET);

/* LL */
LL_GPIO_ResetOutputPin(GPIOC, LL_GPIO_PIN_13);

/* 寄存器：直接写 BSRR */
GPIOC->BSRR = GPIO_BSRR_BR13;      /* BR = Bit Reset */
```

:::tip[BSRR 为什么比 ODR 好]
| 写法 | 实际动作 | 是否原子 |
| --- | --- | --- |
| `GPIOx->ODR = value` | **读-改-写整个端口** | ❌ 影响同端口其他引脚 |
| `GPIOx->ODR ^= mask` | 读-改-写 | ❌ 非原子，中断里危险 |
| **`GPIOx->BSRR = mask`** | **只写，硬件自动置位/复位** | ✅ **单次写，原子** |

**BSRR 高 16 位是复位（BR），低 16 位是置位（BS）。**

**规矩：改单个引脚一律用 BSRR，不要碰 ODR。**
:::

### 翻转引脚

```c
/* HAL 内部实现（F1 系列）大致是： */
uint32_t odr = GPIOx->ODR;
GPIOx->BSRR = ((odr & pin) << 16u) | (~odr & pin);

/* LL */
LL_GPIO_TogglePin(GPIOx, pin);      /* 等价于 GPIOx->ODR ^= pin */

/* 寄存器：没有"翻转"指令，只能用 BSRR 拼 */
GPIOC->BSRR = (GPIOC->ODR & GPIO_BSRR_BS13) ? GPIO_BSRR_BR13 : GPIO_BSRR_BS13;
```

:::warning[翻转不是原子操作]
**没有任何寄存器能一次完成"翻转"** —— 必须"先读当前状态，再决定置位还是复位"。

所以翻转操作**在中断和主循环同时改同一引脚时会有竞争**。

**要原子的翻转，只能靠软件保证同一时刻只有一处操作它。**
:::

### 延时

```c
/* HAL */
HAL_Delay(100);                     /* 依赖 SysTick，精度 1ms */

/* LL + 自定义循环 */
LL_mDelay(100);                     /* 依赖 SysTick */

/* 寄存器：忙等循环（不精确，受编译优化影响） */
for (volatile uint32_t i = 0; i < 72000; i++) { }
```

:::danger[忙等循环不能当延时用]
```c
for (uint32_t i = 0; i < 72000; i++) { }    /* ❌ 可能被优化掉 */
```

**两个问题**：

1. **`-O2` 下没副作用，可能整个被删掉**（加 `volatile` 能挡，但编译器仍可能调整）
2. **实际耗时随流水线、Flash 等待周期、中断而变化**，完全不精确

**要精确延时用定时器，要毫秒级用 `HAL_Delay`。**
:::

## 三层的真实代价

:::warning[以下代码体积是量级估计，不是本机实测]
本站没有 ARM 工具链，无法给出精确字节数。下面的数量级来自 ST 官方文档与广泛引用的实测数据，**你可以在自己的工程里用 `arm-none-eabi-size` 验证**。

```bash
arm-none-eabi-size build/your_project.elf
#    text    data     bss     dec     hex filename
#   xxxxx     xxx    xxxx   xxxxx   xxxxx build/your_project.elf
```
:::

| 维度 | HAL | LL | 寄存器 |
| --- | --- | --- | --- |
| **代码体积** | 大（每外设几 KB） | 小（内联展开） | **最小** |
| **执行速度** | 慢（函数调用 + 参数检查 + 状态机） | **快**（内联，无调用） | **最快** |
| **可读性** | 高（函数名自解释） | 中 | 低（要查手册） |
| **可移植性** | **高**（换型号基本不用改） | 中（同系列可移植） | 低（换型号要重写） |
| **错误处理** | 有超时、返回码 | 基本没有 | 完全没有 |
| **配置正确性** | CubeMX 保证 | 要自己填对 | 容易漏位 |

:::tip[HAL 慢在哪]
一次 `HAL_GPIO_WritePin` 的调用链大致是：

```text
HAL_GPIO_WritePin(GPIOx, pin, state)
  → 参数检查（GPIOx 是否合法、pin 是否非零）
  → 分支判断（state 是 SET 还是 RESET）
  → 算 BSRR 掩码
  → 写寄存器
  → return HAL_OK
```

**真正的硬件动作只有最后一行**，前面都是开销。

**对 LED 这种应用完全无所谓**（一次调用多花几十纳秒）；**但对 10 kHz 以上的信号翻转就有影响了**。
:::

## 什么时候该降级

:::tip[四个明确的降级信号]
**① 在中断里做高频操作**

```c
void TIM2_IRQHandler(void) {
    /* 中断里用 HAL 会明显增加中断响应时间 */
    GPIOC->BSRR = GPIO_BSRR_BS13;      /* 用寄存器 */
}
```

**② 代码空间不够**

Flash 从 64KB 缩到 32KB 时，HAL 常常就放不下了。

**③ 需要确定性的时序**

HAL 内部有分支和查表，**执行周期不固定**。做软件 PWM、位操作时序（如 WS2812）时不行。

**④ 要用 HAL 没封装的位**

某些寄存器的细节位 HAL 没有暴露，只能自己写。
:::

:::danger[不要整体降级到寄存器]
**新手最容易犯的错**：觉得 HAL 慢，就把整个工程改成寄存器操作。

**结果**：

- 时钟没配对（某个外设忘了使能）
- 引脚复用号填错
- 某个保留位写了非默认值 → 行为诡异
- 出问题时没有返回码可查

**正确做法：初始化继续用 CubeMX + HAL，只把热点路径（中断、高频循环）换成寄存器或 LL。**

**收益 95%，风险 5%。**
:::

## 混用要注意什么

:::warning[三条规矩]
**① 不要绕过 HAL 改它正在管理的状态**

```c
HAL_UART_Transmit(&huart1, buf, len, 100);   /* HAL 在管理状态机 */
USART1->DR = 'x';                             /* ❌ 绕过 HAL 写数据寄存器 */
```

HAL 的内部状态（`huart1.gState`）会和你实际做的操作不一致，后续调用可能直接返回 `HAL_BUSY`。

**② 用 LL 时必须 `#include "stm32f1xx_ll_gpio.h"` 等对应头文件**

LL 是**按外设分文件**的，不像 HAL 有统一的 `hal.h`。

**③ 寄存器操作前确认时钟已使能**

```c
__HAL_RCC_GPIOC_CLK_ENABLE();       /* 先用 HAL 开时钟（不易错） */
GPIOC->BSRR = GPIO_BSRR_BS13;        /* 再用寄存器操作 */
```

**这是最划算的组合**：开时钟容易漏，交给 HAL；高频操作要快，用寄存器。
:::

## 一个实用的封装

```c
/* 把常用操作封装成静态内联，兼得可读性与速度 */
static inline void led_on(void)
{
    GPIOC->BSRR = GPIO_BSRR_BR13;      /* PC13 低电平点亮 */
}

static inline void led_off(void)
{
    GPIOC->BSRR = GPIO_BSRR_BS13;
}

static inline void led_toggle(void)
{
    GPIOC->BSRR = (GPIOC->ODR & GPIO_BSRR_BS13)
                ? GPIO_BSRR_BR13 : GPIO_BSRR_BS13;
}
```

:::tip[`static inline` 是关键的组合]
- **`static`**：只在本文件可见，编译器能放心内联
- **`inline`**：建议内联（`-O1` 以上基本一定内联）

**结果：代码里写 `led_on()` 像函数一样清晰，编译后和手写寄存器一样快。**
:::
