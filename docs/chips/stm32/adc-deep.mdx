# 06 ADC 精度与高级模式

**本课目标**：知道为什么 12 位 ADC 测出来会跳，以及怎么把精度提上去。

## 先说结论

:::danger[12 位 ADC 的实际有效精度通常只有 9~11 位]
标称 12 位 = 4096 个刻度（3.3V 下约 0.8mV/LSB）。

**但实际能稳定分辨的往往只有 10 位左右**（约 3mV）。

**不是芯片坏了**——这是 SAR ADC + 板级噪声的正常表现。**能不能用好，取决于你抑制误差的手段。**
:::

## 误差的六个来源

| 来源 | 影响 | 能否改善 |
| --- | --- | --- |
| **参考电压不稳** | 直接按比例影响所有读数 | ✅ 用外部基准 |
| **电源噪声** | 读数随机跳 | ✅ 去耦、独立供电 |
| **输入阻抗不匹配** | 采样不足，读数偏低 | ✅ 降源阻抗或加长采样时间 |
| **ADC 时钟太快** | 转换不完整，精度掉 | ✅ 降 ADC 时钟 |
| **PCB 布线** | 串扰、地弹 | ✅ 改板 |
| **量化误差** | ±0.5 LSB，原理性 | ❌ 只能过采样 |

:::tip[判断你的误差来自哪一类]
**测一个已知的稳定电压**（比如用 TL431 产生 2.500V），看读数分布：

- **读数稳定但偏了一个固定值** → 参考电压或增益误差（可校准）
- **读数随机跳 ±5 个 LSB 以上** → 噪声（电源或地）
- **读数偏低且随源阻抗变化** → 采样时间不够
:::

## 硬限制：ADC 时钟不能超过 14MHz

:::danger[F103 的 ADC 时钟上限是 14 MHz]
ADC 时钟来自 **PCLK2 再分频**：

```text
PCLK2 = 72 MHz
  /2 = 36 MHz   ❌ 超了
  /4 = 18 MHz   ❌ 超了
  /6 = 12 MHz   ✅ 可以用（推荐）
  /8 = 9 MHz    ✅ 更稳
```

**超了会怎样**：转换结果不准、通道间串扰、甚至卡死。

**CubeMX 会自动挡，手写寄存器时要自己算。**
:::

:::warning[降时钟能提升精度]
虽然 12MHz 是合法值，**但很多实测表明 9MHz 时噪声更小**（转换更从容）。

**如果你对精度要求高，试试把 ADC 时钟降到 9MHz 看有没有改善**——这是零成本的尝试。
:::

## 采样时间必须匹配源阻抗

:::info[SAR ADC 的工作原理决定了这一点]
```text
采样阶段：内部采样电容（约 8pF）通过源阻抗充电
    ↓
充电到接近输入电压需要时间 = R_source × C
    ↓
转换阶段：比较器逐位逼近
```

**源阻抗越大，充电越慢，需要越长的采样时间。**
:::

**经验对应关系**（F103，ADC 时钟 14MHz）：

| 源阻抗 | 最小采样周期 | 宏 |
| --- | --- | --- |
| < 10 kΩ | 1.5 周期 | `ADC_SAMPLETIME_1CYCLE_5` |
| 10 ~ 50 kΩ | 7.5 周期 | `ADC_SAMPLETIME_7CYCLES_5` |
| 50 ~ 100 kΩ | 41.5 周期 | `ADC_SAMPLETIME_41CYCLES_5` |
| **> 100 kΩ** | **239.5 周期** | `ADC_SAMPLETIME_239CYCLES_5` |

:::danger[这是"读数偏低"的最常见原因]
```c
/* 用 100kΩ 分压测电池电压，但采样时间配了 1.5 周期 */
sConfig.SamplingTime = ADC_SAMPLETIME_1CYCLE_5;    /* ❌ 充不满，读数偏低 */
```

**现象**：读数比万用表低 5%~20%，而且**内阻越大偏得越多**。

**解决**：加长采样时间，或在 ADC 输入前加一级运放缓冲（跟随器）。
:::

## 参考电压：精度的天花板

:::warning[用 VDDA 当参考，精度就被电源决定了]
F103 的 ADC 参考电压是 **VDDA**（模拟电源）。

```text
如果 VDDA 实际是 3.28V，而你按 3.30V 算：
  误差 = (3.30 - 3.28) / 3.30 ≈ 0.6%
  在 4096 刻度下 ≈ 25 个 LSB
```

**这比 ADC 本身的误差还大。**
:::

:::tip[三个改善办法]
**① 用外部精密基准**

接一个 REF3033（3.300V ±0.05%）到 VREF+ 引脚（部分型号有独立 VREF+ 引脚，F103 小容量型号没有，只能靠 VDDA）。

**② 用内部参考电压校准**

F103 内部有一个 **1.20V 基准（VREFINT）**，可以在 ADC 的通道 17 读到：

```c
/* 先读 VREFINT 通道，反推实际 VDDA */
uint16_t vrefint_raw = read_adc(ADC_CHANNEL_VREFINT);
float vdda_actual = 1.20f * 4096 / vrefint_raw;

/* 用实际 VDDA 换算其他通道 */
float voltage = raw * vdda_actual / 4096;
```

**这个办法能消除电源波动的影响**，非常实用。

**③ 用内部温度传感器（通道 16）测温度**
:::

:::danger[VREFINT 和温度传感器的读数关系不精确]
内部 1.20V 基准的**实际值每片不同**（数据手册给的典型值 1.20V，但范围约 1.16~1.24V）。

**严格做法**：出厂时校准一次，把实测值存在 Flash 或选项字节里。

**不校准的话，用 1.20V 反推 VDDA 会有 ±3% 的残余误差**——但**仍然比不校准好得多**（能消掉电源波动这一项）。
:::

## 三种转换模式

| 模式 | 触发方式 | 适合 |
| --- | --- | --- |
| **单次** | 软件调用一次转一次 | 偶尔采样 |
| **连续** | 转完立刻再转 | 需要持续最新值 |
| **扫描 + DMA** | 一次扫多个通道 | 多路采集（最常用） |

:::tip[多通道采集的标准做法：扫描 + DMA + 循环]
```c
/* 配 3 个通道，DMA 循环搬运，CPU 完全不参与 */
uint16_t adc_buf[3];

HAL_ADC_Start_DMA(&hadc1, (uint32_t *)adc_buf, 3);

/* 之后随时读 adc_buf[0..2] 就是三个通道的最新值 */
```

**注意**：DMA 是 Circular 模式时，`adc_buf` 会被硬件持续刷新。

**读的时候要注意原子性**——多字节变量可能读到"一半旧一半新"：

```c
uint16_t v;
__disable_irq();
v = adc_buf[0];
__enable_irq();
```
:::

## 注入通道：打断规则通道

:::info[ADC 有两组通道：规则组和注入组]
| 组 | 通道数 | 特点 |
| --- | --- | --- |
| **规则组（Regular）** | 最多 16 | 正常采集 |
| **注入组（Injected）** | 最多 4 | **可以打断正在进行的规则转换** |

**这是硬件级的中断优先级**——注入组优先级高于规则组。
:::

**典型用法**：规则组在连续采集电流，注入组被定时器触发去采电压（需要严格同步的时刻）。

```c
/* 注入组由 TIM1 的 TRGO 触发 */
HAL_ADCEx_InjectedStart_IT(&hadc1);

void HAL_ADCEx_InjectedConvCpltCallback(ADC_HandleTypeDef *h)
{
    uint16_t v = HAL_ADCEx_InjectedGetValue(h, ADC_INJECTED_RANK_1);
}
```

:::warning[注入通道的坑]
- 注入组的转换结果寄存器是**独立的**（`JDR1`~`JDR4`），和规则组的 `DR` 不冲突
- 注入组转换会**丢弃当前规则组的转换结果**（被打断的那次没用了）
- 注入组最多 4 个通道
:::

## 多重采样提高有效位数

:::tip[过采样：用 4 次采样换 1 位精度]
理论：**采样 4ⁿ 次求平均，可以提升 n 位有效位数**（前提是噪声是随机的）。

```c
/* 采 16 次求平均 → 理论提升 2 位（12 位 → 14 位） */
uint32_t sum = 0;
for (int i = 0; i < 16; i++) {
    HAL_ADC_Start(&hadc1);
    HAL_ADC_PollForConversion(&hadc1, 10);
    sum += HAL_ADC_GetValue(&hadc1);
}
uint16_t avg = sum / 16;
```

**实际能提升多少**：如果噪声是白噪声，16 次能提升约 2 位；如果噪声是电源纹波（有规律），提升很有限。
:::

:::danger[F103 没有硬件过采样]
F3/F4/H7 有硬件过采样单元（配一下就行），**F103 只能软件做**。

**软件做的代价**：16 次采样耗时是 1 次的 16 倍（还要加上函数调用开销）。

**更好的办法是"滑动平均"**：维护一个环形缓冲，每次采一个新值，输出最近 N 次的平均——**运算量恒定，响应也快**。
:::

```c
#define N 16
static uint16_t buf[N];
static uint8_t idx = 0;
static uint32_t sum = 0;

uint16_t moving_average(uint16_t new_val)
{
    sum -= buf[idx];          /* 减掉最旧的 */
    buf[idx] = new_val;
    sum += new_val;
    idx = (idx + 1) % N;
    return sum / N;
}
```

## 常见坑

| 现象 | 原因 | 解决 |
| --- | --- | --- |
| 读数偏低且内阻大时更严重 | 采样时间不足 | 加长采样时间或加缓冲 |
| 读数随机跳 ±20 LSB | 电源噪声 | 加去耦、独立供电 |
| 读数整体偏高/偏低 | 参考电压不准 | 用 VREFINT 校准 |
| 某几个通道互相干扰 | ADC 时钟太快 | 降到 9MHz |
| ADC2 完全不能用 | **WiFi 占用 ADC2** | 这是 ESP32 的问题，不是 STM32 |
| 转换永远不完成 | 时钟没使能 | `__HAL_RCC_ADC1_CLK_ENABLE()` |
| DMA 数据不更新 | Normal 模式搬一次就停 | 改 Circular |
| 注入通道读不到 | 没启动注入转换 | `HAL_ADCEx_InjectedStart_IT` |

:::warning[F103 的 ADC 和 DMA 有一点特殊]
F103 的 ADC1 只有一个 DMA 请求通道（DMA1_CH1），**多通道扫描时 DMA 会自动按顺序搬**，不需要你配多个通道。
:::
