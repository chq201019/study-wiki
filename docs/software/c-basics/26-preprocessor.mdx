# 26 预处理器与宏

**本课目标**：看懂宏，理解它的陷阱，知道什么时候不该用宏。

## 预处理器是什么

**编译的第一步**（第 3 课讲过）。它只做**纯文本替换**，不懂语法。

所有 `#` 开头的都是预处理指令：

| 指令 | 作用 |
| --- | --- |
| `#include` | 复制头文件内容 |
| `#define` | 定义宏 |
| `#undef` | 取消宏 |
| `#if` / `#ifdef` / `#else` / `#endif` | 条件编译 |
| `#error` | 主动报错 |
| `#pragma` | 编译器相关指令 |

**关键认知：预处理发生在编译之前，宏不是变量，是文本。**

## `#define` 定义常量

```c
#define MAX_SIZE 100
#define PI 3.14159
#define APP_NAME "MyApp"

int arr[MAX_SIZE];        /* 预处理后变成 int arr[100]; */
```

:::tip[为什么用宏定义数组大小]
```c
const int n = 100;
int arr[n];               /* ⚠️ C 里这不是编译期常量 */

#define N 100
int arr[N];               /* ✅ 编译期常量 */
```

C 里 `const int` **不算**常量表达式（这是 C 和 C++ 的区别）。数组大小、`case` 标签这些需要编译期常量的地方，得用 `#define`。

（也可以用 `enum { N = 100 };` 这个技巧。）
:::

## 宏没有类型检查

```c
#define MAX 100
double d = MAX;           /* 能用，int 隐式转 double */
char c = MAX;             /* ⚠️ 100 超出 char 范围，会截断，无警告 */
```

**宏是文本替换，没有类型概念。**

:::tip[优先用 `const` 或 `enum`]
```c
/* 宏（无类型） */
#define MAX 100

/* 有类型（推荐） */
const int MAX = 100;              /* 有类型检查 */
enum { MAX = 100 };               /* 编译期常量，有类型 */
```

**能不用宏就不用**——宏不参与作用域、不参与调试、没有类型。
:::

## 函数式宏：括号陷阱

:::danger[这是宏最经典的坑]
```c
#define SQUARE(x)  x * x

printf("%d\n", SQUARE(1 + 2));      /* 你以为 9，实际 5 */
```

**本机实测**：

```text
SQUARE_BAD(1+2)  = 5 (期望 9)
SQUARE_BAD(3)    = 9
```

**为什么**：宏是文本替换！

```c
SQUARE(1 + 2)
→ 1 + 2 * 1 + 2        /* 不是 (1+2)*(1+2)！ */
→ 1 + 2 + 2 = 5
```

乘法优先级高于加法，所以变成 `1 + (2*1) + 2 = 5`。
:::

### 正确写法：每个参数和整体都加括号

```c
#define SQUARE(x)  ((x) * (x))

printf("%d\n", SQUARE(1 + 2));      /* 9 ✅ */
```

本机实测：`SQUARE_GOOD(1+2) = 9`

:::tip[函数式宏的三条铁律]
1. **每个参数都加括号**：`(x)`
2. **整个表达式加括号**：`((x) * (x))`
3. **尽量不要用宏写函数**——用真正的函数

```c
#define MAX(a, b)  ((a) > (b) ? (a) : (b))
```

漏任何一层括号都可能出问题。
:::

## 副作用：宏会重复求值

:::danger[这比括号问题更隐蔽]
```c
#define MAX(a, b)  ((a) > (b) ? (a) : (b))

int i = 5;
printf("%d\n", MAX(i++, 10));
printf("i = %d\n", i);
```

**本机实测**：

```text
MAX(i++, 10) = 10, i 变成 6
```

**这次 `i++` 只执行了一次**——因为条件为假，走的是 `(10)` 分支。把 `i` 换成 20，条件为真，`i++` 就会执行两次！

因为展开后：

```c
((i++) > (10) ? (i++) : (10))
```

条件判断会执行一次 `i++`；**条件为真时，被选中的分支还会再执行一次 `i++`**。
:::

### 函数没有这个问题

```c
int max_int(int a, int b) {
    return a > b ? a : b;
}

max_int(i++, 10);       /* i++ 只执行一次 */
```

**因为函数参数是"先求值再传参"，只算一次。**

:::tip[结论：能用函数就别用宏]
| | 宏 | 函数 |
| --- | --- | --- |
| 求值次数 | 可能多次 | 一次 |
| 类型检查 | 无 | 有 |
| 调试 | 看不到 | 能断点 |
| 作用域 | 无 | 遵守 |
| 性能 | 无调用开销 | 有开销（通常可忽略） |

**只有在「确实需要零开销 + 且必须接受文本替换语义」时才用宏。**

现代编译器对**小函数**会自动内联，性能和宏差不多——**所以大部分场景直接用函数**。
:::

## 宏里常见的有用技巧

### 1. `do { ... } while (0)` 包裹多语句

```c
#define SWAP(a, b)  do { \
    int tmp = (a);       \
    (a) = (b);           \
    (b) = tmp;           \
} while (0)
```

:::warning[为什么用 `do{}while(0)`]
```c
/* ❌ 只用花括号 */
#define SWAP(a,b) { int t=(a); (a)=(b); (b)=t; }

if (x)
    SWAP(a, b);        /* 展开后变成 if (x) { ... }; 多一个分号 */
else
    ...                /* ❌ 编译错误：else 没有对应的 if */
```

**`do{}while(0)` 让宏在语法上变成"一条语句"**，能安全地放在 `if` 后面。

```c
#define SWAP(a,b) do { ... } while (0)

if (x)
    SWAP(a, b);        /* ✅ 安全 */
else
    ...
```

这是 C 社区的标准写法。
:::

### 2. 字符串化 `#`

```c
#define STR(x)  #x

printf("%s\n", STR(hello));      /* hello */
printf("%s\n", STR(1 + 2));      /* 1+2 */
```

本机实测：`STR(hello) = hello`、`STR(1+2) = 1+2`

**用途**：调试打印变量名

```c
#define PRINT_INT(x)  printf(#x " = %d\n", (x))

int count = 42;
PRINT_INT(count);        /* 输出：count = 42 */
```

### 3. 记号连接 `##`

```c
#define CAT(a, b)  a##b

int CAT(var, 1) = 100;           /* 变成 int var1 = 100; */
printf("%d\n", var1);            /* 100 */
```

本机实测：`var1 = 100`

**用途**：自动生成变量名、函数名（比如批量定义寄存器访问宏）。

## 条件编译

```c
#define DEBUG 1

#if DEBUG
    printf("调试信息\n");
#else
    printf("发布版本\n");
#endif
```

本机实测：`DEBUG 模式已启用`

### `#ifdef` / `#ifndef`

```c
#ifdef _WIN32
    #include <windows.h>
#else
    #include <unistd.h>
#endif
```

`#ifdef X` 等价于 `#if defined(X)`。

### 头文件保护（最常用）

```c
#ifndef MYHEADER_H
#define MYHEADER_H

/* 头文件内容 */

#endif
```

:::danger[头文件不保护会重复定义]
```c
/* a.h */
struct Point { int x, y; };

/* main.c */
#include "a.h"
#include "a.h"        /* 重复包含 → struct Point 定义了两次 → 编译错误 */
```

**头文件保护让同一文件只被包含一次。**

现代写法可以用：

```c
#pragma once
```

更简洁，但不是标准 C（所有主流编译器都支持）。
:::

### `#error`：主动报错

```c
#ifndef __STDC__
    #error "需要标准 C 编译器"
#endif
```

编译时直接报错并停下，适合检查环境。

## 预定义宏

```c
printf("__FILE__ = %s\n", __FILE__);      /* 当前文件名 */
printf("__LINE__ = %d\n", __LINE__);      /* 当前行号 */
printf("__DATE__ = %s\n", __DATE__);      /* 编译日期 */
printf("__TIME__ = %s\n", __TIME__);      /* 编译时间 */
printf("__func__ = %s\n", __func__);      /* 当前函数名（C99） */
```

本机实测：

```text
__FILE__ = s26.c
__LINE__ = 33
__DATE__ = Oct 18 2026
__STDC__ = 1
```

:::tip[调试日志的经典写法]
```c
#define LOG(fmt, ...) \
    fprintf(stderr, "[%s:%d] " fmt "\n", __FILE__, __LINE__, ##__VA_ARGS__)
```

用起来：

```c
LOG("用户 %s 登录失败", name);
/* 输出：[main.c:42] 用户 小明 登录失败 */
```

**自动带上文件名和行号**，排查问题非常方便。

（`##__VA_ARGS__` 是 GCC 扩展，处理可变参数为空的情况。）
:::

## 常见错误

| 错误 | 现象 | 原因 | 解决 |
| --- | --- | --- | --- |
| 宏参数不括起来 | 运算优先级错 | 文本替换 | `((x)*(x))` |
| 宏参数有副作用 | 值被多次修改 | 多次求值 | 改用函数 |
| 宏定义末尾加分号 | 展开后多分号 | `#define N 100;` | 不要加分号 |
| 多语句宏没 `do-while` | if 后编译错 | 语法断裂 | `do{}while(0)` |
| 头文件没保护 | 重复定义 | 多次包含 | `#ifndef` / `#pragma once` |
| `#define` 与变量同名 | 意外替换 | 预处理先做 | 改名或 `#undef` |

:::danger[`#define` 后面不要加分号]
```c
#define MAX 100;             /* ❌ 带了分号 */

int a = MAX;                 /* 展开成 int a = 100;;  多一个空语句 */
if (a > MAX) ...             /* 展开成 if (a > 100;) ...  语法错 */
```

**宏定义不是语句，不要加分号。**
:::
