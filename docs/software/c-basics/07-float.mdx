# 07 浮点数

**本课目标**：会算小数，理解为什么不精确，避开浮点比较的经典错误。

## 两种浮点类型

| 类型 | 字节 | 有效位数 | 用在哪 |
| --- | --- | --- | --- |
| `float` | 4 | 约 6~7 位 | 省内存（嵌入式常用） |
| `double` | 8 | 约 15~16 位 | **默认选它** |

```c
float f = 3.14f;        /* 注意后缀 f */
double d = 3.14;        /* 默认就是 double */
```

:::warning[`float` 字面量必须加 `f` 后缀]
```c
float f = 3.14;         /* 3.14 是 double，赋给 float 会丢精度（可能警告） */
float f2 = 3.14f;       /* ✅ 明确表示 float */
```

不加 `f` 的话，字面量是 `double`，转换时会警告 `conversion from 'double' to 'float'`（开 `-Wconversion` 时）。

**规矩：`float` 变量赋值时数字后面加 `f`。**
:::

## 为什么小数不精确

:::danger[这个结果会让所有初学者震惊]
```c
printf("%.20f\n", 0.1 + 0.2);
printf("%d\n", (0.1 + 0.2) == 0.3);
```

本机实测输出：

```text
0.30000000000000004441
0
```

**`0.1 + 0.2` 不等于 `0.3`！**
:::

:::tip[深入一点：二进制表示不了 0.1]
计算机用二进制存数字。整数能精确表示，但**大部分小数不能**——就像十进制写不出 1/3。

`0.1` 转成二进制是无限循环小数 `0.0001100110011...`，存进 32/64 位时被**截断**了。

两个被截断的数相加，误差就暴露出来。

**这不是 C 的 bug**，所有用 IEEE 754 浮点的语言（Python、Java、JavaScript）都一样。第一遍不懂可跳过，记住结论即可。
:::

### 精度差异实测

```c
printf("float:  %.10f\n", (float)1.0 / 3.0);
printf("double: %.15f\n", 1.0 / 3.0);
```

输出：

```text
float:  0.3333333333
double: 0.333333333333333
```

`float` 到第 7 位左右就不准了，`double` 能到 15 位。

### float 连大整数都存不准

```c
float f = 16777217.0f;      /* 2^24 + 1 */
printf("%.1f\n", f);
```

输出：

```text
16777216.0
```

**`16777217` 变成了 `16777216`！**

:::warning[float 的整数精度只有 24 位]
`float` 的尾数只有 23 位（加隐含位共 24 位），所以**大于 2²⁴ = 16777216 的整数无法精确表示**。

**这意味着：**

- 别用 `float` 存超过 1677 万的整数
- 别用 `float` 存时间戳（Unix 时间戳早就超了）
- 别用 `float` 存金额

**需要精度就用 `double`，需要绝对精确就用整数。**
:::

## 浮点数绝对不能直接用 `==`

:::danger[这是最常见的浮点错误]
```c
double a = 0.1 + 0.2;
if (a == 0.3) {
    printf("相等\n");      /* 永远不会执行 */
}
```

**永远不会相等**，因为 `a` 是 `0.30000000000000004`。
:::

### 正确做法：比较误差范围

```c
#include <math.h>
#include <stdio.h>

int main(void) {
    double a = 0.1 + 0.2;

    if (fabs(a - 0.3) < 1e-9) {
        printf("近似相等\n");
    }
    return 0;
}
```

输出：

```text
近似相等
```

`fabs()` 取绝对值（在 `<math.h>`，Linux 上编译要加 `-lm`）。

**`1e-9` 是容差**，根据精度需求调整（`double` 常用 `1e-9`，`float` 用 `1e-5`）。

:::tip[更严谨的写法：相对误差]
数值很大时，绝对误差不够用。比如比较 `1e20 + 1` 和 `1e20`，差 1 但相对误差极小。

```c
int nearly_equal(double a, double b, double eps) {
    double diff = fabs(a - b);
    if (diff < eps) return 1;                    /* 都接近 0 的情况 */
    return diff / (fabs(a) + fabs(b)) < eps;     /* 相对误差 */
}
```

日常用简单版就够，做科学计算时再考虑相对误差。
:::

## 特殊值：inf 和 nan

浮点数有几个特殊值。本机实测：

```c
printf("%f\n", 1.0 / 0.0);      /* inf */
printf("%f\n", -1.0 / 0.0);     /* -inf */
printf("%f\n", 0.0 / 0.0);      /* nan */
```

输出：

```text
inf
-inf
nan
```

:::danger[浮点除零不崩溃！]
```c
double d = 1.0 / 0.0;       /* 得到 inf，不崩 */
int i = 1 / 0;              /* ❌ 整数除零会崩溃 */
```

**浮点除零得到 `inf`，整数除零直接崩溃**（signal SIGFPE）。这是两者的重大区别。
:::

### nan 的诡异特性

```c
double z = 0.0 / 0.0;       /* nan */
printf("%d\n", z == z);      /* 0 —— nan 不等于自己！ */
```

本机实测：`nan == nan` 结果是 **0（假）**。

**判断 nan 必须用 `isnan()`：**

```c
#include <math.h>

if (isnan(z)) {
    printf("这是 nan\n");
}
```

同理判断无穷用 `isinf()`。

:::tip[nan 从哪里来]
除了 `0.0/0.0`，还有：

- `sqrt(-1)`（负数开平方）
- `log(-1)`
- `inf - inf`

**排查数值 bug 时，先用 `isnan()` 检查中间结果**——nan 会传染，一旦产生，后面全是 nan。
:::

## 浮点的字面量写法

```c
double a = 3.14;
double b = 3.14e10;         /* 科学计数法：3.14 × 10^10 */
double c = .5;              /* 0.5，前导 0 可省 */
double d = 5.;              /* 5.0，小数部分可省 */
double e = 1E-9;            /* 0.000000001 */
```

**注意 `1e9` 是浮点数，不是整数**。

## 浮点运算的性能与内存

| 类型 | 大小 | 速度 |
| --- | --- | --- |
| `float` | 4 字节 | 快 |
| `double` | 8 字节 | 稍慢（但现代 CPU 差距很小） |

:::tip[嵌入式选哪个]
| 场景 | 选择 |
| --- | --- |
| 传感器数据、简单计算 | `float`（省内存） |
| 复杂算法、需要精度 | `double` |
| **芯片没有 FPU** | 尽量用整数运算 |

**ESP32-S3 有硬件浮点单元（FPU）**，`float` 运算很快。但很多低端 MCU（如 Cortex-M0）**没有 FPU**，浮点运算要靠软件模拟，慢几十倍。

**没有 FPU 时**：把小数乘以 100 或 1000 转成整数运算（定点数）。
:::

## `printf` 打印浮点

```c
double pi = 3.14159265;

printf("%f\n", pi);         /* 3.141593  默认 6 位小数 */
printf("%.2f\n", pi);       /* 3.14      2 位小数 */
printf("%.10f\n", pi);      /* 3.1415926500 */
printf("%e\n", pi);         /* 3.141593e+00  科学计数 */
printf("%g\n", pi);         /* 3.14159   自动选择 */
```

:::warning[`%f` 和 `%lf` 的区别]
- `printf` 里 `%f` 对 `float` 和 `double` **都可以**（因为 `float` 会自动提升为 `double`）
- `scanf` 里**必须用 `%lf`** 读 `double`，`%f` 读 `float`

**这是 `scanf` 的特殊规则**，第 08 课会讲。
:::

## 完整示例

```c
#include <stdio.h>
#include <math.h>

int main(void) {
    double price = 19.99;
    int count = 3;
    double total = price * count;

    printf("单价：%.2f\n", price);
    printf("数量：%d\n", count);
    printf("总计：%.2f\n", total);

    /* 正确比较 */
    double a = 0.1 + 0.2;
    if (fabs(a - 0.3) < 1e-9) {
        printf("a 约等于 0.3\n");
    }

    /* 检查 nan */
    double z = 0.0 / 0.0;
    if (isnan(z)) {
        printf("检测到 nan\n");
    }

    return 0;
}
```

输出：

```text
单价：19.99
数量：3
总计：59.97
a 约等于 0.3
检测到 nan
```

## 常见错误

| 错误 | 现象 | 原因 | 解决 |
| --- | --- | --- | --- |
| `if (a == b)` 比较浮点 | 永远不成立 | 精度误差 | 用 `fabs(a-b) < eps` |
| `float f = 3.14;` | 精度警告 | 3.14 是 double | 写 `3.14f` |
| 用 `float` 存金额 | 算错几分钱 | 精度不够 | 用整数（分为单位） |
| 用 `float` 存大整数 | 值变了 | 只有 24 位精度 | 用 `double` 或整数 |
| `nan == nan` 判断 | 结果是假 | nan 不等于自己 | 用 `isnan()` |
| `1/2` 想得 0.5 | 得到 0 | 整数除法 | `1.0/2` |
| 忘加 `-lm` | undefined reference to sqrt | 没链接数学库 | 编译加 `-lm` |

:::danger[涉及金额千万别用浮点]
```c
double price = 0.1;
double total = price * 3;
printf("%.20f\n", total);    /* 0.30000000000000004 */
```

**银行系统、电商结算一律用整数（以"分"为单位）**：

```c
int price_fen = 10;          /* 0.10 元 */
int total_fen = price_fen * 3;   /* 30 分 = 0.30 元 */
printf("%d.%02d\n", total_fen / 100, total_fen % 100);
```
:::
