# 06 整数：范围与溢出

**本课目标**：知道整数的边界在哪，理解溢出行为，避开由此引发的 bug。

## 整数类型有多大

本机实测（Windows x86-64）：

```text
char=1 short=2 int=4 long=4 long long=8
```

对应的范围：

| 类型 | 字节 | 有符号范围 | 无符号范围 |
| --- | --- | --- | --- |
| `char` | 1 | -128 ~ 127 | 0 ~ 255 |
| `short` | 2 | -32,768 ~ 32,767 | 0 ~ 65,535 |
| `int` | 4 | **-2,147,483,648 ~ 2,147,483,647** | 0 ~ 4,294,967,295 |
| `long long` | 8 | 约 ±9.2×10¹⁸ | 0 ~ 1.8×10¹⁹ |

**`int` 的上限是 2147483647**（约 21 亿）——这个数字要记住。

## 用代码确认边界

```c
#include <stdio.h>
#include <limits.h>

int main(void) {
    printf("INT_MAX = %d\n", INT_MAX);
    printf("INT_MIN = %d\n", INT_MIN);
    printf("UINT_MAX = %u\n", UINT_MAX);
    printf("SHRT_MAX = %d\n", SHRT_MAX);
    return 0;
}
```

本机实测输出：

```text
INT_MAX = 2147483647
INT_MIN = -2147483648
UINT_MAX = 4294967295
SHRT_MAX = 32767
```

`<limits.h>` 里定义了各类型的边界，**不要自己硬编码这些魔数**。

## 溢出会发生什么

:::danger[有符号溢出是未定义行为]
```c
int x = INT_MAX;      /* 2147483647 */
x = x + 1;
printf("%d\n", x);
```

本机实测输出：

```text
-2147483648
```

**从最大值一下跳到最小值。**
:::

### 为什么是负数

:::tip[深入一点：补码表示]
整数用**二进制补码**存储。`INT_MAX` 是：

```text
0111 1111 1111 1111 1111 1111 1111 1111
```

加 1 变成：

```text
1000 0000 0000 0000 0000 0000 0000 0000
```

在补码里，最高位是 1 表示负数，这个值正好是 `INT_MIN`。

**所以溢出不是"变成无限大"，而是"绕回去了"。** 第一遍不懂可以跳过，记住结论就行。
:::

:::danger[标准说这是「未定义行为」]
C 标准明确规定：**有符号整数溢出是未定义行为（undefined behavior）**。

意思是编译器**可以做任何事**：

- 得到负数（常见）
- 得到看似正常的错误结果
- 程序崩溃
- 优化器直接删掉这段代码

**不要依赖"溢出后会变成负数"这个具体行为**——换个编译器/优化等级就可能不同。

**正确做法：运算前先检查会不会溢出。**
:::

### 无符号溢出：明确定义为回绕

```c
unsigned int u = 0;
u = u - 1;
printf("%u\n", u);
```

本机实测：

```text
4294967295
```

**无符号溢出是明确定义的**：按 2³² 取模，从 0 减 1 变成最大值。

| 类型 | 溢出行为 |
| --- | --- |
| 有符号 | **未定义行为**（危险） |
| 无符号 | 明确定义为回绕（可控） |

## 怎么判断会不会溢出

```c
#include <stdio.h>
#include <limits.h>

int main(void) {
    int a = INT_MAX;

    /* 加之前先检查 */
    if (a > INT_MAX - 1) {
        printf("会溢出，拒绝执行\n");
    } else {
        a = a + 1;
        printf("结果：%d\n", a);
    }
    return 0;
}
```

输出：

```text
会溢出，拒绝执行
```

:::tip[检查的通用思路]
`a + b` 会不会溢出？改写判断条件：

```c
/* 想算 a + b，检查是否 a > INT_MAX - b */
if (b > 0 && a > INT_MAX - b) {
    /* 会溢出 */
}
```

**不要写成 `if (a + b > INT_MAX)`**——那本身就已经溢出过了。
:::

## 有符号与无符号

```c
int a = -1;               /* 有符号，可以是负数 */
unsigned int b = 1;       /* 无符号，只能非负 */
```

声明时可以简写：

```c
signed int x;             /* 等价于 int */
unsigned int y;           /* 或简写 unsigned */
unsigned char c;          /* 0~255 */
```

### 有符号 vs 无符号混用的陷阱

:::danger[这是 C 最阴险的坑之一]
```c
int a = -1;
unsigned int b = 1;

if (a < b) {
    printf("a 小于 b\n");
} else {
    printf("a 不小于 b\n");
}
```

**输出是 `a 不小于 b`！**
:::

**原因**：有符号和无符号一起运算时，**有符号会被转换成无符号**。

`-1` 转成无符号是 `4294967295`，当然比 1 大。

```c
printf("%u\n", (unsigned int)-1);   /* 4294967295 */
```

:::warning[编译器其实会警告]
开了 `-Wall -Wextra` 会提示：

```text
warning: comparison of integers of different signs
```

**看到这个警告一定要处理**——很可能是真 bug。
:::

### 实际踩坑场景：`sizeof` 返回无符号

```c
int n = 5;
if (n < sizeof(int)) {        /* sizeof 返回 size_t（无符号） */
    printf("n 小于 4\n");
}
```

`n` 会被转成无符号再比较。如果 `n` 是负数，就会变成巨大的正数。

**对策**：把类型统一，或者显式转换：

```c
if ((size_t)n < sizeof(int))    /* 明确表示 n 是非负的 */
```

## 该用哪种整数

| 场景 | 推荐 |
| --- | --- |
| 普通计数、循环 | `int` |
| 需要保证大小（跨平台/嵌入式） | `int32_t`、`uint8_t` 等 |
| 数组下标、缓冲区大小 | `size_t`（`sizeof` 的返回类型） |
| 只会是非负数 | 无符号类型 |
| 极大数值 | `long long` 或 `int64_t` |

:::tip[嵌入式里几乎都用定宽类型]
```c
#include <stdint.h>

uint8_t  buffer[256];      /* 明确是 1 字节 */
uint16_t sensor_value;     /* 明确是 2 字节 */
int32_t  counter;          /* 明确是 4 字节 */
```

**为什么**：寄存器宽度是固定的（比如 8 位、16 位），用 `int` 这种"平台相关"的类型会出问题。

**而且 `uint8_t` 一眼就能看出是多少位。**
:::

## 整数除法与取余

```c
printf("%d\n", 7 / 2);      /* 3，不是 3.5 */
printf("%d\n", 7 % 2);      /* 1 */
printf("%d\n", -7 / 2);     /* -3（向零截断） */
printf("%d\n", -7 % 2);     /* -1 */
```

:::warning[C 和 Python 的负数除法不同]
| 表达式 | Python | C |
| --- | --- | --- |
| `-7 // 2` | **-4**（向下取整） | **-3**（向零截断） |
| `-7 % 2` | **1** | **-1** |

C99 起规定：除法**向零截断**，余数的符号跟着被除数。

**从 Python 转过来的人这里一定会踩坑。**
:::

### 要小数必须有一边是浮点

```c
int a = 7, b = 2;
printf("%d\n", a / b);            /* 3，整数除法 */
printf("%f\n", (double)a / b);    /* 3.500000，转成浮点 */
```

**只写 `a / b` 永远是整数除法**，哪怕赋给 `double` 变量——除法在赋值前就已经算完了。

## 常见错误

| 错误 | 现象 | 原因 | 解决 |
| --- | --- | --- | --- |
| 累加到溢出 | 变负数 | 超过 INT_MAX | 用 `long long` 或先检查 |
| 有符号/无符号比较 | 结果反直觉 | 隐式转换 | 类型统一 |
| `n < sizeof(x)` | 负数时判断错 | sizeof 是无符号 | 显式转换 |
| `int avg = sum / count` | 丢失小数 | 整数除法 | 用 `double` |
| 循环变量用 `uint8_t` | 死循环 | 255+1 回绕成 0 | 用 `int` |
| 硬编码 2147483647 | 难读易错 | 魔数 | 用 `INT_MAX` |

:::danger[用 `uint8_t` 做循环变量会死循环]
```c
for (uint8_t i = 0; i < 256; i++) {
    /* ... */
}
```

`i` 最大 255，加 1 变成 0，条件 `0 < 256` 永远成立 → **无限循环**。

**循环变量用 `int`**，除非你非常确定边界。
:::
