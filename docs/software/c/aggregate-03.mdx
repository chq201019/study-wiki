# 03 结构体赋值与比较
### 赋值是值拷贝

```c
struct Point a = {1, 2}, b;
b = a;    /* 合法！整个结构体按成员拷贝 */
```

标准保证结构体赋值会拷贝**所有成员**（包括 padding 里的字节？——不，padding 的内容是**未指定**的，可能不拷贝）。

:::warning[不能用 `==` 比较结构体]
```c
if (a == b) { }   /* 语法错误 */
```
C 没有结构体比较运算符。要自己写比较函数，或用 `memcmp`（**但 padding 字节内容未指定，`memcmp` 可能给出错误结果**——两个逻辑相等的结构体，padding 里可能是垃圾）。

**正确做法：逐成员比较。**
:::

### 结构体传参

```c
void f(struct Big s);     /* 值传递：整个结构体被拷贝到栈上 */
void f(struct Big *s);    /* 指针传递：只拷 8 字节 */
```

实测：

```c
struct Big { char buf[64]; };
printf("sizeof(struct Big)=%zu\n", sizeof(struct Big));
```

```text
sizeof(struct Big)=64
```

值传递一个 64 字节的结构体会拷贝 64 字节到栈上——**嵌入式上通常用 `const struct Big *` 代替**，除非结构体很小。

## 常见坑

| 陷阱 | 现象 | 原因 | 正确做法 |
| --- | --- | --- | --- |
| 结构体比预期大 | 内存浪费 | padding | 按对齐从大到小重排成员 |
| 以为结构体布局固定 | 换编译器后错位 | 布局实现定义 | 需要确定布局时用 packed + 定宽类型 + `_Static_assert` |
| 取 packed 成员地址 | 某些架构 HardFault | 非对齐访问 | 用 `memcpy` |
| 用位域映射硬件寄存器 | 生成错误的访问宽度 | 布局实现定义 + 编译器自由 | 用位掩码 |
| 依赖位域的位序 | 换编译器/平台位序变 | 实现定义 | 不要跨编译器依赖 |
| `int x:1` 以为能存 1 | 只能存 0 和 -1 | 有符号位域 | 用 `unsigned x:1` 或 `uint32_t` |
| 取位域地址 | 语法错误 | 位没有地址 | 无法取地址，改用掩码 |
| 用 `memcmp` 比结构体 | padding 字节不同导致误判 | padding 内容未指定 | 逐成员比较 |
| `typedef` 指针后加 `const` | 语义变成常量指针 | typedef 是文本别名 | 不要 typedef 指针（除句柄） |
| 依赖 `sizeof(enum)` | 换编译器后变 | 底层类型实现定义 | 需要固定大小用 `uint32_t` 承载 |
| union 读未写入的成员 | 值无意义 / UB | union 不记录有效成员 | 用标签字段记录 |
| 大结构体值传递 | 栈消耗大、慢 | 值拷贝 | 用 `const struct *` |
| C89 的 `data[1]` hack | 非标准 | C99 之前的变通 | 用柔性数组成员 `data[]` |
| 忘记柔性数组必须是最后成员 | 编译错误 | 标准规定 | 放最后 |
