# 03 `_Static_assert`：编译期断言
C11 引入（**注意下划线**）。本机在 `-std=c17` 下实测通过：

```c
_Static_assert(sizeof(int) == 4, "int must be 4 bytes");
```

```text
_Static_assert passed (C11, __STDC_VERSION__=201710)
```

`__STDC_VERSION__` 的值：`199901L`(C99) / `201112L`(C11) / `201710L`(C17)。可以用它做条件编译。

:::caution[`_Static_assert` vs `static_assert`]
- **`_Static_assert`** 是 **C11** 引入的关键字
- **`static_assert`**（不带下划线）是 **C23** 才成为关键字的；在 C11/C17 里它只是 `<assert.h>` 提供的一个宏

写代码时用 `_Static_assert` 最稳妥，在所有 C11+ 工具链都能用。
:::

典型用途——**守住你对平台的假设**：

```c
_Static_assert(sizeof(int) == 4, "this driver assumes 32-bit int");
_Static_assert(CHAR_BIT == 8, "byte must be 8 bits");
_Static_assert(sizeof(void *) == 4, "32-bit MCU only");
```

这是把"我以为"变成"编译期证明"的最有效手段，**在嵌入式里应该大量使用**。

## 九、常量与字面量后缀

| 后缀 | 含义 | 例子 |
| --- | --- | --- |
| `u` / `U` | unsigned | `42u` |
| `l` / `L` | long | `42L` |
| `ll` / `LL` | long long | `42LL` |
| `ul` / `UL` | unsigned long | `42UL` |
| `ull` | unsigned long long | `42ULL` |
| `f` / `F` | float（默认是 double） | `3.14f` |
| 无 | double | `3.14` |

整数前缀：`0x` 十六进制、`0` 八进制、`0b` 二进制（**C23 标准；gcc/clang 作为扩展早已支持**）。

:::tip[十六进制常量默认是"能装下的最小有符号类型"链的起点]
`0x80000000` 在 32 位 `int` 平台上会尝试 `int` → 装不下 → `unsigned int` → `long` → `unsigned long`。所以它的类型可能不是你以为的那个。加 `u` 后缀明确意图。

嵌入式里写寄存器掩码**一律加 `u`**：`0x80000000u`。
:::

## 常见坑

| 陷阱 | 现象 | 原因 | 正确做法 |
| --- | --- | --- | --- |
| 用 `long` 表示 64 位 | Windows 上溢出 | LLP64 vs LP64 | 用 `int64_t` / `uint64_t` |
| `char` 当数值用 | 200 变成 -56 | `char` 符号性实现定义 | 显式 `signed char` / `unsigned char` / `uint8_t` |
| `-1 < 1u` 为假 | 比较结果反直觉 | 有符号被转成无符号 | 避免混用；需要时显式转换并先验证非负 |
| `sizeof(x) > n`（n 为负）| 恒为假 | `n` 转成 `size_t` | 保证 `n` 非负，或显式转换 |
| `flags & MASK == MASK` | 判断恒错 | `==` 优先级高于 `&` | 写 `(flags & MASK) == MASK` |
| `1 << 31` | UB / 负数 | 有符号左移溢出 | 用 `1u << 31` |
| 右移负数 | 得到负值 | 算术右移（实现定义） | 先转无符号再右移 |
| `i++ + i++` | 结果不可预测 | 序列点违规 UB | 拆成多条语句 |
| `printf("%d %d", i++, i++)` | 输出顺序奇怪 | 实参求值顺序未指定 + UB | 拆开写 |
| `switch` 忘 `break` | 多个 case 都执行 | fallthrough | 每个 case 加 `break` |
| `case` 后直接声明变量 | 编译错误 | 跳过初始化 | 加 `{}` |
| `if (x = 5)` | 赋值当比较，恒真 | 手误 | 写 `if (x == 5)`，开 `-Wparentheses` |
| 悬空 `else` | 绑定到错误的 if | 最近未配对原则 | 永远加花括号 |
| `uint8_t a = 200 + 100;` | 得 44 不是 300 | 整数提升后截断 | 用足够宽的类型接收结果 |
| 以为 `sizeof` 是函数 | 语法困惑 | 它是运算符 | `sizeof x` 合法，`sizeof(int)` 的括号属于类型名 |
