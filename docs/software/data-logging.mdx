# 数据记录与分析

采集类项目的成败不在传感器精度，而在**数据到得了、认得清、对得上时间**。

## 采样周期：从需求倒推，不要凭感觉

先问三个问题：被测物理量最快的变化有多快？一次采集记多少字节？存储介质每秒能吞多少字节？

按 Nyquist，采样率至少是被测信号最高频率的 2 倍，工程上取 5–10 倍：

| 被测对象 | 有效带宽 | 采样周期 | 理由 |
|---|---|---|---|
| 室温 / 湿度 | < 0.01 Hz | 30 s | 空气热惯性以分钟计 |
| 土壤湿度 | < 0.01 Hz | 60 s | 更慢 |
| 人体走动、门开关 | ~5 Hz | 100 ms | 只要"发生了"，不求波形 |
| 电机转速（霍尔） | ~50 Hz | 10 ms | 需要测脉宽 |
| 振动、敲击 | ~500 Hz | 1 ms | 需要波形，属于高频采集 |
| 音频 | 8 kHz+ | 125 µs | ESP32 上要上 I2S + DMA |

**过度采样的代价是双向的**：存储爆掉，后处理时 99% 的数据是冗余的。
30 秒周期的温湿度，一年才 100 万行；1ms 周期的加速度，一小时就是 360 万行、按 CSV 算 100MB。

## 为什么不能每毫秒写一次 SD

单次写盘操作的实测耗时：

| 操作 | 耗时 |
|---|---|
| 写入到 FAT 缓存（扇区未满） | 10–40 µs |
| 撑满一个扇区触发实际写卡 | 5–30 ms |
| fflush() 强制落盘 | 20–250 ms（卡内 GC 时可到 300ms） |
| fclose() | 30–300 ms |

一次真正写卡动作的耗时，比 1ms 的采样周期长几十倍。每毫秒写一次的后果：

- 采样任务被 I/O 阻塞，实际周期变成 30ms 且抖动极大 —— 时间戳全乱；
- 如果跑在高优先级任务里，看门狗直接复位（默认 5 秒）；
- SD 卡被写放大打爆，几个月就坏。

**正确做法是 RAM 里攒够一个块再写**：

```c
#define BUF_ROWS 64
static char s_buf[BUF_ROWS][96];
static int  s_n = 0;

void log_row(float t, float h, int64_t ts_ms)
{
    snprintf(s_buf[s_n], sizeof(s_buf[0]), "%lld,%.2f,%.2f\n",
             (long long)ts_ms, t, h);
    if (++s_n >= BUF_ROWS) flush_buf();
}

void flush_buf(void)
{
    if (s_n == 0) return;
    FILE *f = fopen("/sdcard/log.csv", "a");
    if (!f) { s_n = 0; return; }        /* 卡掉了就丢这一批，别死等 */
    for (int i = 0; i < s_n; i++) fputs(s_buf[i], f);
    fflush(f);
    fclose(f);
    s_n = 0;
}
```

64 行 × 96 字节 ≈ 6KB，写一次。写入频率从 1000 次/秒降到 0.015 次/秒。

关键设计是**保持"打开-写-关"而不是长期持有句柄**。长期开着的文件，卡被拔掉或掉电时
FAT 表里的长度字段不会更新，文件在电脑上显示 0 字节。

## 格式选择：CSV / JSON / 二进制

同一条记录（时间戳、温度、湿度、电压）：

| 格式 | 单行字节 | 100 万行体积 | 解析成本 | 人可读 |
|---|---|---|---|---|
| CSV | 38 | 38 MB | 极低（split 逗号） | ✅ |
| JSON Lines | 96 | 96 MB | 中（要 parser） | ✅ |
| 定长文本（定点小数） | 28 | 28 MB | 低 | ✅ |
| 二进制 struct | 16 | 16 MB | 需知道布局 | ❌ |
| 二进制 + 差分编码 | 6 | 6 MB | 需解码程序 | ❌ |

```text
CSV       : 1715666400000,23.45,56.78,3.92
JSON Lines: {"ts":1715666400000,"t":23.45,"h":56.78,"v":3.92}
二进制    : <8B int64 ts><2B int16 t*100><2B int16 h*100><2B uint16 v*1000>
```

**选择规则**：

- 学生要自己用 Excel 打开看 → **CSV**，没有第二选择。
- 接 MQTT / HTTP 上报 → **JSON**，线上传输不需要省那几个字节。
- 高频（> 100Hz）或存储紧张 → **二进制定长 struct**，但收发两端必须用同一个
  `#pragma pack` 布局，否则解析全错。
- 长期归档、要跨设备合并 → CSV 加一列 `device_id`，比什么都省事。

**CSV 的三个隐性成本**：

1. 小数位数决定体积。`%.6f` 记温度是浪费 —— 传感器有效位只有 0.01。按精度定位数。
2. 分隔符冲突。字段里出现逗号（备注、设备名）整行就解析错。禁止逗号或用分号分隔。
3. 换行符。Windows 的 Excel 更认 `\r\n`，统一用它，两边都不出错。

## 浮点数：精度换体积

ESP32 是单精度浮点，`float` 只有 23 位尾数、约 7 位十进制有效数字。`double` 慢且占空间。

| 写法 | 单值字节 | 温度 23.4567 存成 | 误差 |
|---|---|---|---|
| `%.4f` 文本 | 7 | 23.4567 | 无（文本精确） |
| `%.2f` 文本 | 5 | 23.46 | 0.01 |
| `float` 二进制 | 4 | 位模式 | ~1e-6 相对 |
| `int16` 定点 ×100 | 2 | 2346 | 0.005 |

**定点数是最实用的折中**：`int16_t x100` 覆盖 −327.68 ~ +327.67，分辨率 0.01，
正好匹配 DHT22 / SHT30 的精度，体积只有 float 的一半。

```c
typedef struct __attribute__((packed)) {
    int64_t  ts_ms;
    int16_t  temp_x100;    /* 23.45°C  → 2345  */
    int16_t  humi_x100;    /* 56.78%RH → 5678  */
    uint16_t volt_mv;      /* 3920mV   → 3920  */
} record_t;                /* 共 14 字节 */
```

两个必须注意的点：

- **绝不直接比较浮点数**：`if (t == 25.0)` 可能永远为假。用定点数或 `fabs(a-b) < 0.01`。
- **不用 float 存累计值**。累加一万次之后单精度已经丢掉末几位；
  累计电量、累计步数必须用 `int64_t` / `uint32_t`。

## 时间戳：没有 RTC 或 NTP 就没有时间

`millis()` / `esp_timer_get_time()` 是**开机以来**的时间，断电归零。
数据里只有这种时间戳，合并两台设备的数据时就彻底没救了。

| 方案 | 精度 | 掉电保持 | 成本 |
|---|---|---|---|
| `esp_timer_get_time()` | µs | ❌ 归零 | 免费 |
| NTP 校准（开机联网一次） | ±50 ms | ❌ 但可恢复绝对时间 | 需 WiFi |
| 外部 RTC 芯片（DS3231 / PCF8563） | ±2 ppm（DS3231） | ✅ 纽扣电池 | 3–5 元 |

**推荐组合**：DS3231 提供绝对时间基准 + `esp_timer` 做间隔测量。每次开机从 RTC 读一次，
之后用 `esp_timer` 累加 —— 不要每行都读 I2C，一次 I2C 读要 300µs，比采样本身还贵。

DS3231 的三个坑：

- 模块上的 CR1220 只给 RTC 供电，**不是给主控**。没电池断电就归零，不是模块坏了。
- I2C 地址固定 `0x68`，和 MPU6050 冲突。同总线时只能分时供电或换引脚。
- 存的是 **BCD 码**不是二进制。读出来 `0x25` 是 25 秒，直接当整数用会得到完全错误的时间。

NTP 校准：联网后 `esp_sntp_setoperatingmode(ESP_SNTP_OPMODE_POLL)` 启一次，
等 `sntp_get_sync_status() == SNTP_SYNC_STATUS_COMPLETED` 再写 RTC。
**不要假设联网就有时间**：DHCP 拿到 IP 之后可能还要 1–3 秒 DNS 才通。

断电重启后时间戳会跳变，生产做法是记录「本次开机的 boot_id」，事后按 boot_id 分段。

## 断网重试与本地缓存

联网上报的固件必须假设**网一定断**。三段式：

1. **采样本机落盘**，不管有没有网。本地缓存是唯一的真相来源。
2. **上报异步**，成功一条删一条（或记 offset）。
3. **重试带退避**，不能死循环重连。

```c
#define RETRY_BASE_MS  2000
#define RETRY_MAX_MS   60000

static uint32_t s_backoff = RETRY_BASE_MS;

bool upload_one(const record_t *r)
{
    esp_err_t err = http_post_record(r);
    if (err == ESP_OK) {
        s_backoff = RETRY_BASE_MS;      /* 成功就重置退避 */
        return true;
    }
    ESP_LOGW(TAG, "上报失败 %s, %lu ms 后重试",
             esp_err_to_name(err), (unsigned long)s_backoff);
    vTaskDelay(pdMS_TO_TICKS(s_backoff));
    s_backoff = s_backoff * 2 > RETRY_MAX_MS ? RETRY_MAX_MS : s_backoff * 2;
    return false;
}
```

指数退避 + 60 秒上限。没有上限时，一次长时间断网会把退避推到几小时，网络恢复了也传不上去。

**本地缓存排队策略**：

| 策略 | 优点 | 缺点 | 适用 |
|---|---|---|---|
| 环形覆盖（定长文件） | 空间可控，永不写满 | 老数据被覆盖 | 长期监测，最新数据最重要 |
| 先进先出（传完删） | 一条不丢 | 空间满了停止采集 | 离线日志，完整性优先 |
| 分片归档（每天一文件） | 天然分段，好清理 | 文件多，mount 开销 | 需要按天查询 |

环形覆盖的实现要点：不要真的搬移数据。用定长文件 + NVS 里的写指针，
写到末尾回绕到开头，每次写都是顺序的，**没有擦除放大**：

```c
/* /sdcard/ring.bin 固定 8MB，每批 100 条 × 14 字节 */
#define RING_SLOTS  (8 * 1024 * 1024 / (100 * 14))
#define BATCH       100

void ring_append(const record_t *rows)
{
    uint32_t slot = 0;
    nvs_get_u32(s_h, "slot", &slot);
    FILE *f = fopen("/sdcard/ring.bin", "r+b");
    fseek(f, (long)slot * BATCH * sizeof(record_t), SEEK_SET);
    fwrite(rows, sizeof(record_t), BATCH, f);
    fclose(f);

    slot = (slot + 1) % RING_SLOTS;
    nvs_set_u32(s_h, "slot", slot);        /* 每批更新一次，不是每条 */
    nvs_commit(s_h);
}
```

写指针放 NVS 意味着每次更新都消耗 NVS 寿命，所以**按批更新指针**，不要每条记录都改。

## 异常检测：四种规则，一个都别省

原始数据一定会出现离谱值。不处理，一年的记录里几个坏点就能让整张图表报废。

| 规则 | 判据 | 典型阈值 | 处理 |
|---|---|---|---|
| 超量程 | 超出传感器手册范围 | DHT22: −40~80°C，0~100%RH | 丢弃 |
| 跳变 | 与上一有效值差超过物理上限 | 1Hz 采样时 > 2°C/s | 丢弃或标记 |
| 卡死 | 连续 N 次完全相同 | N=10（真实温度不会完全不变） | 标记设备故障 |
| 通信错误 | NaN / 0xFFFF / 校验失败 | 传感器返回状态位 | 丢弃 |

```c
typedef enum { QC_OK, QC_RANGE, QC_JUMP, QC_STUCK } qc_t;

static float s_last = NAN;
static int   s_same = 0;

qc_t check_temperature(float t)
{
    if (isnan(t) || t < -40.0f || t > 80.0f) return QC_RANGE;

    if (!isnan(s_last)) {
        if (fabsf(t - s_last) > 2.0f) return QC_JUMP;   /* 1Hz 下的物理上限 */
        s_same = (t == s_last) ? s_same + 1 : 0;
        if (s_same > 10) return QC_STUCK;
    }
    s_last = t;
    return QC_OK;
}
```

**标记比丢弃更好。** 把异常值原样写进去，加一列 `qc` 状态码（0 正常 / 1 超量程 / 2 跳变 / 3 卡死），
事后能看到「几点开始传感器坏了」，而不是数据凭空少了一段。

滤除策略要分场景：

- 温度这种慢变量用**滑动中位数**（5 点即可）—— 中位数不被单个尖刺带偏，平均会被。
- 加速度、电流这种本来就有噪声的，用**滑动平均**或一阶低通。
- **永远不要把滤波后的值当原始值存**。滤波参数一旦错了，原始数据就再也恢复不出来。

## 坑

1. **SD 卡写入阻塞主循环。** 单次 flush 20–250ms，采样放在同一个任务里就会被 I/O 拖死。
   正确做法：采样任务只往 FreeRTOS 队列塞数据，独立的写卡任务消费；
   队列长度按「扛住最坏一次 300ms 卡顿」设计。队列满了丢最旧的，**并且记下丢了多少条**，
   不要悄悄丢。
2. **时间戳必须校准。** 只有 `millis()` 的数据一旦重启就回到 0，和历史数据拼不到一起，
   图上会重叠成一团。
3. **文件不 fclose 就断电，长度是 0。** FAT 的目录项在 close 时才写回。
   日志文件每批写完立即 close，也顺带保证卡被拔掉时最多丢一批。
4. **CSV 表头只能写一次。** 追加模式下先判断 `fseek(f,0,SEEK_END); ftell(f)==0`
   再决定写不写表头，否则会得到几十行重复表头，Excel 里看着像乱码。
5. **float 打印 6 位小数是浪费。** 23.45 后面那四位全是噪声，白占 40% 存储。
6. **批量写时不要每条都 fflush。** 一秒 100 次 fflush 等于 100 次擦写，卡几个月就坏。
7. **写卡时电流翻倍。** SD 卡写入峰值 30–100mA，和 WiFi 同时动作会叠加。
   低电量时优先保证写卡，把 WiFi 关掉。
8. **不要用 Arduino 的 String 拼日志行。** 每次 `+=` 都可能重新分配堆，长时间运行必然碎片化，
   最后 malloc 失败。用固定 `char buf[96]` + `snprintf`。
9. **本地别用 JSON Lines。** 解析成本是 CSV 的 5–10 倍，本地文件不需要 schema 检查。
   JSON 只用在联网上报那一段。
10. **`vTaskDelay` 不等于精确周期。** 它只保证「至少等这么久」，实际周期 = 延时 + 执行时间。
    要精确周期用 `vTaskDelayUntil`，或者记下每次实际时间戳、事后按真实时间对齐。

## 排错对照表

| 现象 | 原因 | 处理 |
|---|---|---|
| 采样周期抖动大 | 写卡阻塞 | 队列 + 独立写任务 |
| 数据文件 0 字节 | 没 close 就断电 | 每批写完整 close |
| 重启后图表时间轴错乱 | 只有相对时间戳 | 加 RTC 或 NTP |
| 图表上出现垂直尖刺 | 未过滤异常值 | 加量程 / 跳变检查 |
| Excel 打开是乱码 | 表头重复 / 编码不对 | 只写一次表头，UTF-8 无 BOM |
| 数据一小时后停止增长 | 队列满被静默丢弃 | 记录丢弃计数，拉长写周期 |
| 内存越跑越少最后死机 | String 拼接碎片化 | 固定缓冲 + snprintf |
| 上报一直失败但网是通的 | 退避涨到几小时 | 加 60 秒上限，成功即重置 |
