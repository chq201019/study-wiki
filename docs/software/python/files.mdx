# 文件与路径处理

**本课目标**：会写健壮的文件读写代码，避免半截文件和编码乱码。

## `pathlib` 取代 `os.path`

```python
from pathlib import Path

p = Path("/var/log") / "app.log"        # 用 / 拼接
p.name          # 'app.log'
p.stem          # 'app'
p.suffix        # '.log'
p.parent        # PosixPath('/var/log')
p.exists()
p.is_file()
p.stat().st_size
```

:::tip[为什么用 `pathlib` 而不是字符串拼接]
```python
path = os.path.join("dir", "file.txt")      # 传统写法
path = Path("dir") / "file.txt"             # pathlib
```

**`pathlib` 的好处**：

- 自动处理分隔符（Windows `\` / POSIX `/`）
- 路径是个对象，能用 `.parent` / `.stem` / `.suffix` 而不是字符串截取
- **`read_text()` / `write_text()` 一行搞定读写并处理编码**
:::

```python
# 读写的现代写法
text = Path("a.txt").read_text(encoding="utf-8")
Path("b.txt").write_text(text, encoding="utf-8")

data = Path("x.bin").read_bytes()
Path("y.bin").write_bytes(data)
```

:::danger[**一定要显式写 `encoding`**]
```python
Path("a.txt").read_text()          # ❌ 用系统默认编码
Path("a.txt").read_text(encoding="utf-8")   # ✅
```

**Windows 上默认是 `gbk`（中文系统），Linux 上是 `utf-8`。**

**不写编码的代码在开发机上正常、到服务器上就乱码** —— 这是最典型的"环境差异 bug"。

**Python 3.15 计划把默认编码改成 UTF-8，但现在还不能依赖。**
:::

## 遍历目录

```python
# 单层
for p in Path("dir").iterdir():
    print(p.name)

# 递归（只文件）
for p in Path("dir").rglob("*.py"):
    print(p)

# 更灵活
for p in Path("dir").glob("**/*.py"):
    print(p)
```

:::warning[`glob` 与 `rglob` 的区别]
- `glob("*.py")` —— 只在**当前层**
- `glob("**/*.py")` —— 递归（`**` 匹配任意层）
- `rglob("*.py")` —— 等价于 `glob("**/*.py")`

**注意 `glob("**/*.py")` 在某些情况下会包含当前层**（`**` 可匹配空路径）。
:::

:::danger[遍历时删除文件会出问题]
```python
for p in Path("dir").iterdir():
    if p.suffix == ".tmp":
        p.unlink()          # ⚠️ 边遍历边删，行为依赖底层实现
```

**安全做法：先收集列表再处理。**

```python
for p in list(Path("dir").iterdir()):
    ...
```

**`os.scandir` 也有同样问题。**
:::

## 原子写入：避免半截文件

:::danger[直接覆写会在崩溃时留下损坏文件]
```python
Path("config.json").write_text(data)      # ❌ 写到一半断电 → 文件损坏
```

**因为 `write_text` 是先截断再写** —— 原内容立刻消失。
:::

```python
import os
import tempfile
from pathlib import Path

def atomic_write(path: Path, data: str, encoding="utf-8"):
    # 在同一目录下建临时文件（保证同一文件系统，rename 才是原子的）
    fd, tmp = tempfile.mkstemp(dir=path.parent, prefix=".tmp_")
    try:
        with os.fdopen(fd, "w", encoding=encoding) as f:
            f.write(data)
            f.flush()
            os.fsync(f.fileno())        # 强制落盘
        os.replace(tmp, path)           # 原子替换（POSIX 和 Windows 都支持）
    except BaseException:
        os.unlink(tmp)
        raise
```

:::tip[三个关键点]
**① 临时文件必须在同一目录**

跨文件系统 `rename` 不是原子的（甚至是"复制+删除"）。

**② 必须 `fsync`**

否则数据还在页缓存里，断电会丢。**`rename` 只保证"目录项切换"原子，不保证数据落盘。**

**③ 用 `os.replace` 而不是 `os.rename`**

`os.rename` 在 Windows 上目标存在时会失败；`os.replace` 两者都覆盖。
:::

:::warning["`fsync` 之后还要 fsync 目录" 这个细节]
**严格来说**（数据库级别）：

```python
os.fsync(f.fileno())                    # 数据落盘
os.replace(tmp, path)                   # 改目录项
dirfd = os.open(path.parent, os.O_DIRECTORY)
os.fsync(dirfd)                         # 目录项也落盘
os.close(dirfd)
```

**不然崩溃时"文件内容对，但目录里还指向旧文件"。**

**普通应用一般不做这一步** —— 但知道它的存在，能解释偶尔的"文件不见了"。
:::

## 大文件：逐行而不是全读

:::danger[不要 `read_text()` 整个大文件]
```python
text = Path("huge.log").read_text()     # ❌ 10GB 直接 OOM
```

**`read_text` 会把整个文件读进内存。**
:::

```python
# ✅ 流式读取
with open("huge.log", encoding="utf-8") as f:
    for line in f:                       # 文件对象是迭代器
        process(line.rstrip("\n"))

# ✅ 分块读取（二进制）
with open("big.bin", "rb") as f:
    while chunk := f.read(65536):
        process(chunk)
```

:::warning[`line.rstrip("\n")` 而不是 `strip()`]
`strip()` 会去掉**所有空白**（包括行首缩进、行尾空格）。

**只想去掉换行符就用 `rstrip("\n")`**。

**注意 `\r\n` 的情况**：用 `newline=""` 或 `rstrip("\r\n")`。
:::

## 临时文件与目录

```python
import tempfile

# 临时文件（用完自动删）
with tempfile.NamedTemporaryFile(mode="w", suffix=".txt",
                                 encoding="utf-8", delete=True) as f:
    f.write("data")
    f.flush()
    use(f.name)          # ⚠️ Windows 上这个文件被占用，别的进程打不开

# 临时目录（退出 with 自动递归删除）
with tempfile.TemporaryDirectory() as d:
    Path(d, "a.txt").write_text("x")
```

:::danger[Windows 上 `NamedTemporaryFile` 默认不能被其他进程打开]
**因为文件以独占方式打开**（`O_TEMPORARY`）。

**需要别的进程访问时**：

```python
# ① 关闭后删除
with tempfile.NamedTemporaryFile(delete=False) as f:
    tmp = f.name
try:
    use(tmp)
finally:
    os.unlink(tmp)

# ② 或者用 TemporaryDirectory + 自己建文件
```
:::

## 编码问题排查

| 现象 | 原因 | 解决 |
| --- | --- | --- |
| `UnicodeDecodeError` | 文件不是声明的编码 | 试 `encoding="gbk"` / `"latin-1"` |
| 开头多出 `\ufeff` | **UTF-8 BOM** | 用 `encoding="utf-8-sig"` 读 |
| 写出的文件别人打开乱码 | 没写 BOM 但对方按 BOM 读 | 明确约定编码 |
| Windows 上正常、Linux 乱码 | 默认编码不同 | **永远显式写 `encoding`** |

:::tip[BOM 的处理]
```python
Path("a.txt").read_text(encoding="utf-8-sig")     # 读时自动去掉 BOM
Path("a.txt").write_text(t, encoding="utf-8")     # 写时不加 BOM
```

**`utf-8-sig` 读时会吞掉 BOM，写时会加上 BOM。**

**Web / Linux 场景一律用 `utf-8`（不带 BOM）；Windows 记事本兼容才用 `utf-8-sig`。**
:::

:::danger[不要用 `errors="ignore"` 掩盖问题]
```python
Path("a.txt").read_text(encoding="utf-8", errors="ignore")    # ❌ 数据静默丢失
```

**`errors="ignore"` 会悄悄丢掉无法解码的字节。**

**要么用正确编码，要么用 `errors="replace"` 并在日志里记录替换了多少**（至少可观测）。
:::

## 常见坑

| 现象 | 原因 | 解决 |
| --- | --- | --- |
| 乱码 | 没写 `encoding` | 永远显式指定 |
| 文件写了一半 | 非原子写 | 临时文件 + `os.replace` |
| 读完大文件 OOM | `read_text()` | 逐行或分块 |
| 行首缩进被吃掉 | 用了 `strip()` | `rstrip("\n")` |
| 遍历时删文件出错 | 边遍历边改 | 先转 `list` |
| Windows 打不开临时文件 | 独占打开 | `delete=False` |
| 相对路径找不到 | 工作目录不同 | 用 `Path(__file__).parent` |
| 路径被当字符串截取 | 用了 `os.path` 字符串 | 用 `pathlib` |

:::tip[相对于"脚本所在目录"的路径]
```python
HERE = Path(__file__).resolve().parent
CONFIG = HERE / "config.json"
```

**这比 `Path("config.json")` 可靠得多** —— 后者相对的是**当前工作目录**，而它取决于你从哪调用脚本。

**这是脚本在 cron / systemd 下"找不到文件"的最常见原因。**
:::
