# 触摸与摄像头

这是 S3「AIoT」定位的落点：触摸交互 + 图像输入 + AI 推理。两样东西都和"模拟量"打交道——触摸靠测量极微小的电容变化，摄像头靠一行行搬运像素数据，所以它们都比 GPIO 复杂，也都对内存规划敏感。

## 1. 电容触摸

### 原理：用"充电时间"测手指

普通按键靠机械触点，**电容触摸**靠的是：任何导体（包括你的手指）靠近导电片时，会让导电片对地的**寄生电容**变大——芯片反复给触摸通道充电放电，测量"充放电特征"的变化，就能判断"有没有手指"。

```
无手指：充放电时间 = T
有手指：充放电时间 = T + ΔT（ΔT 只有人体几 pF 的量级，极微小）
       ↑ 芯片内部的高灵敏度电路把这微小变化放大成可判断的数
```

S3 有 14 个触摸通道，映射在 GPIO1～GPIO14（**触摸外设只在经典 ESP32 / S2 / S3 上有**，C3/C6/H2 没有）。接线极简：**触摸引脚直接接一块导电极（铜箔、焊盘、硬币）即可，不需要任何外部电路**——甚至隔着 2mm 以内的玻璃/塑料面板也能感应（做"防水面板按键"的原理）。

### S3 的新触摸驱动

S3 的触摸驱动在 IDF 5.x 里是新一代驱动（`esp_driver_touch`），API 和老款 ESP32 的 `touch_pad_*` 不同。完整用法以官方示例 `examples/peripherals/touch` 为准，流程骨架：

```c
#include "driver/touch_sens.h"

// 1. 创建触摸控制器（配置充放电参数、内部滤波、灵敏度）
// 2. 在控制器上创建触摸通道（选通道号 = 选 GPIO）
// 3. 两种用法二选一：
//    a) 轮询：定期 touch_channel_read_data() 读测量值，
//       与"基线值"（无触摸时的基准）比较，差值超阈值即判定触摸
//    b) 事件：注册回调，硬件检测到越限时自动通知你（推荐，又是回调模式）
```

### 实战要点

| 参数 | 说明 |
| --- | --- |
| 灵敏度 | 导电片面积越大、导线越短越灵敏；隔面板感应会衰减 |
| 基线漂移 | 温湿度变化会让"无触摸基准"慢慢偏移——新驱动内置自动基线校准，事件模式下不用手工处理 |
| 干扰 | 附近有开关电源、长导线捡拾噪声都会误触发，滤波次数调高可缓解 |
| 独特优势 | 深睡眠时触摸仍可工作（作为唤醒源）——"摸一下就醒"的电池设备标配 |

## 2. 摄像头

### 链路总览：一帧图像怎么进来

S3 通过并行接口（DVP）接 CMOS 摄像头，一帧图像的旅程：

```text
传感器曝光 → 逐行输出像素（8 根数据线并行） → S3 的 DMA 搬进帧缓冲（PSRAM）
→ 你从缓冲池里"取帧"处理 → 用完"还回去"
```

常用驱动是乐鑫维护的 **esp32-camera** 组件：

```bash
idf.py add-dependency "espressif/esp32-camera"
```

| 传感器 | 分辨率 | 备注 |
| --- | --- | --- |
| OV2640 | 640×480 VGA | 最常见、最便宜，首选 |
| OV5640 | 1600×1200 | 更高分辨率，帧率换内存 |
| GC2145 | 1600×1200 | 常见于成品屏板 |

### 初始化（真实字段，逐段讲解）

摄像头一次性占用十几个引脚（8 根数据线 + 时钟 + 同步线），不同厂家板子的引脚分配不同——**下面数值要按你手上的板子丝印改**：

```c
#include "esp_camera.h"

camera_config_t config = {
    // SCCB（I2C 的摄像头版）控制线：读写传感器寄存器
    .pin_sccb_sda = GPIO_NUM_4,
    .pin_sccb_scl = GPIO_NUM_5,
    // 数据线 D0～D7 + 三根同步/时钟线
    .pin_d0 = GPIO_NUM_11, .pin_d1 = GPIO_NUM_12,
    .pin_d2 = GPIO_NUM_13, .pin_d3 = GPIO_NUM_14,
    .pin_d4 = GPIO_NUM_15, .pin_d5 = GPIO_NUM_16,
    .pin_d6 = GPIO_NUM_17, .pin_d7 = GPIO_NUM_18,
    .pin_xclk  = GPIO_NUM_2,        // 芯片给摄像头的基准时钟
    .pin_pclk  = GPIO_NUM_7,        // 摄像头回给的像素时钟
    .pin_vsync = GPIO_NUM_6,        // 帧同步（一帧开始的信号）
    .pin_href  = GPIO_NUM_8,        // 行同步（一行开始的信号）
    .pin_pwdn  = -1, .pin_reset = -1,

    .xclk_freq_hz = 20000000,       // 20MHz 起步，太高会花屏
    .pixel_format = PIXFORMAT_RGB565,  // 或 PIXFORMAT_JPEG（省内存，见下）
    .frame_size   = FRAMESIZE_QVGA,    // 320×240
    .jpeg_quality = 12,                // 仅 JPEG 格式有效，越小越清晰

    .fb_count    = 2,                  // 双缓冲：采集和消费交替
    .fb_location = CAMERA_FB_IN_PSRAM, // ★ 帧缓冲放 PSRAM，必须开
    .grab_mode   = CAMERA_GRAB_LATEST, // 处理不过来时丢弃旧帧、保最新
};
ESP_ERROR_CHECK(esp_camera_init(&config));
```

**关键字段的理解**：

- **帧缓冲池（fb_count）**：DMA 把帧往池子里放，你从池子里取。2 个 = "一边在拍新的，一边在处理旧的"（L2 双缓冲思想）
- **RGB565 vs JPEG**：RGB565 每像素 2 字节（红 5 位 + 绿 6 位 + 蓝 5 位），直接可用；JPEG 压缩几十倍但用前要解码。**显示选 RGB565（省解码），AI/网络传输选 JPEG（省内存带宽）**
- **grab_mode**：`CAMERA_GRAB_LATEST`（处理不过来丢旧帧保最新）适合"看实时画面"；`CAMERA_GRAB_WHEN_EMPTY`（不丢帧排队）适合"一帧都不能少"的录像

### ⚠️ 三个必须注意的点

1. **JPEG 省内存**：RGB565 一帧 320×240 要 150KB（640×480 要 600KB），而 JPEG 只要几十 KB。做 AI 场景强烈建议 JPEG，用之前再解码
2. **帧缓冲必须归还**：`esp_camera_fb_get()` 从有限的缓冲池里拿帧，**用完必须 `esp_camera_fb_return(fb)` 还回去**。不还的话几帧之后 `fb_get` 返回 NULL，表现为"跑几秒图像就卡死"——这是摄像头最常见的 bug
3. **PCLK 别拉太高**：`xclk_freq_hz` 从 20MHz 起步，画面出现斜纹花屏先降频（杜邦线接的摄像头尤其要降）

### 帧率参考

| 分辨率 | RGB565 | JPEG |
| --- | --- | --- |
| 160×120 | 60+ fps | 60+ fps |
| 320×240 | 30～50 fps | 60+ fps |
| VGA 640×480 | 15～25 fps | 30+ fps |
| 1600×1200 | 勉强 | 15～20 fps |

## 3. 帧的正确用法

```c
camera_fb_t *fb = esp_camera_fb_get();
if (fb == NULL) { /* 缓冲耗尽，跳过这帧 */ }

// fb->buf 是像素数据指针，fb->len 是字节数，fb->width/height 是尺寸
// 想送去显示、AI 推理或上传，都在这里处理

esp_camera_fb_return(fb);          // ★ 用完必须还回去
```

如果要接到 LVGL 显示（见 [L6 图形界面](../l6-system/gui-lvgl)），把 `fb->buf` 交给 LVGL 的图片控件即可，注意 LVGL 不复制数据——**显示完成前不能归还 fb**，时序上通常用双缓冲轮转解决。

**处理一帧的耗时预算**：10fps = 每帧 100ms。解码 JPEG ~10ms、推理 30～150ms、显示刷写 20ms——加起来很容易超预算，所以 AI 场景的帧率通常定 5～10fps，别贪 30fps。

## 4. 加一层 AI

```mermaid
flowchart LR
  A[摄像头 JPEG] --> B[解码为 RGB565]
  B --> C[缩放到模型输入尺寸<br/>如 96x96]
  C --> D[量化到 int8]
  D --> E[TensorFlow Lite Micro<br/>或 ESP-DL]
  E --> F[分类结果/置信度]
  F --> G[阈值判断 → GPIO/网络]
```

| 工具 | 特点 |
| --- | --- |
| ESP-DL | 乐鑫官方，开箱即用，含人脸、唤醒词、人体检测模型 |
| TFLM + esp-tflite-micro | 生态最全，自己训练模型导出 quantized tflite |
| esp-video | 3.x 新增，视频编解码流水线 |

**内存预算**：8MB PSRAM 的分配大致是——帧缓冲 300KB、模型 200～500KB、推理中间层 200～500KB、留 2MB 余量。模型加载进 PSRAM 的方法：把 `.tflite` 文件用 `target_add_binary_data` 塞进固件、启动时指针引用。

## 5. 引脚规划的坑

摄像头一次性占掉 15+ 个引脚，很容易和别的模块撞车。规划原则：

1. **先固定摄像头的引脚，再排剩下的**——它是引脚预算的大头
2. **摄像头数据线（D0～D7、PCLK、VSYNC、HREF）不要和 SPI/I2C 混排**，走线远了会有信号完整性问题
3. PCLK 走线尽量短，远离 XCLK
4. 数据线尽量连号分配（D0～D7 用 GPIO11～18 这种连续段），布线整齐也少出错
