# USB

S3 有原生 USB OTG（Full-Speed 12Mbps）——注意这不是"能充电的 USB 口"，而是**芯片自己能扮演 USB 设备**：插上电脑，它可以是键盘、鼠标、U 盘、虚拟串口、MIDI 乐器。配合 TinyUSB（一个业界通用的轻量 USB 协议栈）可以做出各种 USB 设备。

## 1. USB-Serial-JTAG vs TinyUSB：别搞混的两套能力

S3 芯片内置两套 USB 相关的东西：

| | USB-Serial-JTAG | TinyUSB |
| --- | --- | --- |
| 是什么 | 芯片内部固化的"串口+调试"功能 | 软件协议栈，能扮演任意 USB 设备 |
| 你要写代码吗 | 不用，芯片自带 | 要，自己定义"我是谁" |
| 用途 | 烧录、看日志、JTAG 调试 | HID / MIDI / CDC / MSC / DFU |

一个限制：**两套能力共用 GPIO19/20 这对引脚**。跑 TinyUSB 设备时，USB-Serial-JTAG 的串口/调试功能就没了（烧录会退回 ROM 下载模式兜底：按住 BOOT 复位）。开发期建议日志走 UART0 引脚，把 19/20 留给 USB 设备。

## 2. TinyUSB 设备类

"设备类（Device Class）"是 USB 标准里的"设备品种"——电脑看到品种就知道该用哪个驱动：

| 类 | 用途 | 例 |
| --- | --- | --- |
| CDC | 虚拟串口 | 插上电脑出现一个 COM 口 |
| HID | 人机接口 | 键盘、鼠标、摇杆、游戏手柄 |
| MIDI | 音乐控制 | MIDI 键盘、控制器 |
| MSC | 大容量存储 | U 盘 |
| DFU | 固件升级 | 设备固件升级协议 |
| Vendor | 自定义 | 私有协议 |

## 3. 做一块 HID 键盘

以 esp-usb 组件（乐鑫对 TinyUSB 的封装）为例，完整可编译代码在官方仓库 `esp-usb/examples/device/hid`——**本节讲清结构和概念，代码以示例为准**：

```bash
idf.py add-dependency "espressif/esp_tinyusb"
```

做 HID 键盘的三步：

1. **装驱动**：填设备描述符（厂商 ID、产品 ID、名字）后 `tinyusb_driver_install()`
2. **声明报告描述符（Report Descriptor）**：一段特殊的二进制数据，向电脑"自我介绍"——"我是键盘，我有 8 个修饰键 + 6 个按键位"。见下方解释
3. **发报告**：按键时把键值数组通过 HID 接口发给电脑，松开时发全 0

### 报告描述符：HID 的"自我介绍信"

电脑对键盘一无所知，全靠这段描述符了解它。下面是标准键盘描述符的核心部分，逐行注释：

```c
const uint8_t hid_report_desc[] = {
    0x05, 0x01,        // 用途页：通用桌面设备
    0x09, 0x06,        // 用途：键盘
    0xA1, 0x01,        // 开始一个集合（应用层）
    0x05, 0x07,        //   用途页：键码
    0x19, 0xE0,        //   用途最小值：左 Ctrl
    0x29, 0xE7,        //   用途最大值：右 GUI（8 个修饰键）
    0x15, 0x00,        //   逻辑最小值 0
    0x25, 0x01,        //   逻辑最大值 1（每个键位只有按下/没按下）
    0x75, 0x01,        //   每个字段 1 位
    0x95, 0x08,        //   共 8 个字段（8 个修饰键）
    0x81, 0x02,        //   输入项：数据、变量
    // ……省略 6 个普通按键位的字节……
    0xC0,              // 集合结束
};
```

**改自定义设备（摇杆、旋钮、脚踏板）就是改这份描述符**——"我有 2 个轴，每个轴 10 位精度"对应的字段组合在 USB HID 规范文档里都有表可查。描述符写错的表现是"设备被电脑识别但按键没反应"，用在线的 HID 描述符解析工具能直接验证。

按一次"A"键的完整流程：

```c
// 1. 发"A"按下（键码 0x04）
uint8_t report[6] = {0, 0, 0x04, 0, 0, 0};
tud_hid_keyboard_report(REPORT_ID_KEYBOARD, 0, report);
vTaskDelay(pdMS_TO_TICKS(20));                    // 给电脑一点反应时间

// 2. 发全 0（松开）——不松开电脑会以为你在长按
uint8_t empty[6] = {0};
tud_hid_keyboard_report(REPORT_ID_KEYBOARD, 0, empty);
```

## 4. 电池鼠标/键盘的省电

USB 协议有 **Suspend（挂起）**机制：主机（电脑）可以让设备"睡觉"，也可以唤醒它。电池供电的 USB 设备必须实现挂起，否则电脑关机后设备还在傻等（充电口抽干电池）：

```c
// TinyUSB 在挂起/恢复时会回调你注册的函数（又是回调模式）
void tud_mount_cb(void) { /* 插上电脑 */ }
void tud_umount_cb(void) { /* 拔掉 */ }
void tud_suspend_cb(bool remote_wakeup_en) {
    // 电脑让睡了：关外设、进低功耗
}
void tud_resume_cb(void) { /* 被唤醒 */ }
```

同时设备描述符里的 `bMaxPower` 字段声明"我最多要多少毫安"（单位 2mA）——超过 500mA 的请求是不合规的，电脑可以直接拒。

## 5. MIDI

MIDI 设备类把你的芯片变成一件乐器：发一条标准 MIDI 消息（如"Note On，音 C4，力度 100"），电脑上的音乐软件就收到音符。MIDI 消息格式固定三字节：状态字节 + 两个数据字节：

```text
0x90 0x3C 0x64   ← Note On（0x90），C4 音（0x3C），力度 100（0x64）
0x80 0x3C 0x00   ← Note Off
```

esp-usb 仓库的 `examples/device/usb_midi` 有完整实现，包括消息封装和描述符。典型应用：自制 MIDI 控制器（旋钮+滑条+脚踏板）。

## 6. 常见问题

| 现象 | 原因 |
| --- | --- |
| 电脑完全没反应 | 描述符非法；GPIO19/20 被 USB-Serial-JTAG 抢占；用了只能充电的线 |
| 设备认识但功能不对 | 报告描述符与实际发送的报告不匹配 |
| HID 键盘无反应 | 描述符写错；或报告格式和声明的不一致 |
| 长按变成连打 | 忘了发"松开"报告 |
| USB MSC 传输慢 | 缓冲区太小，或没用 DMA 可达内存 |
| 烧录不好使了 | TinyUSB 运行时占用了 USB 口——按住 BOOT 进 ROM 下载模式兜底 |
