# 04 控制流：分支与循环

## 4. 控制流：岔路口（if）和循环（for / while）

上一页说过，操作单只会顺序往下执行。要它"看情况办事"和"重复办事"，靠这两样。

### 4.1 if：看情况办事

```c
#include <stdio.h>

int main(void) {
    int temperature = 32;

    if (temperature > 30) {
        printf("太热了\n");          // 条件成立走这里
    } else if (temperature < 10) {
        printf("太冷了\n");          // 前面不成立、这个成立才走这里
    } else {
        printf("温度适宜\n");        // 全都不成立才走这里
    }

    return 0;
}
```

输出：

```text
太热了
```

执行过程像走岔路，拆开看：

1. 程序执行到 `if`，**先算括号里的条件**（`temperature > 30` → 1，成立）
2. 成立 → 进入后面花括号里的代码，执行完**直接跳过**所有 `else if` / `else`
3. 不成立 → 跳过这个花括号，去看有没有 `else if` / `else`
4. **三条路只会走一条**，走完汇合到 if 块的后面继续

**else if 想接几层接几层**，但自上而下只会命中第一个成立的条件——所以条件顺序有讲究：把最严格的放最前面。反过来想一个经典错误：

```c
if (score >= 60) printf("及格");
else if (score >= 90) printf("优秀");    // ← 永远走不到！90 分在第一个 if 就被"及格"截胡了
```

条件要从严到宽排（先判 `>= 90` 再判 `>= 60`）。

**if 可以嵌套**（if 里面再套 if），层数多了可读性骤降，超过两层通常该用 `&&` 合并条件或拆函数。

**只有一句话时花括号可省**（`if (x > 0) printf("正");`），但**初学阶段永远写花括号**——省括号是著名的"苹果 goto fail 漏洞"的直接原因之一，不省这个便宜。

### 试着改一改

1. 把 `temperature = 32` 改成 `15` 再运行，输出"温度适宜"；再改成 `5`，输出"太冷了"。**用三组输入验证你理解了分支**——这就是程序员的"单元测试"雏形
2. 写一个成绩分档程序：90 以上优秀、80 以上良好、60 以上及格、其余不及格。分别用 95 / 85 / 65 / 40 四个分数验证（注意条件从严到宽）

### 4.2 for：重复办事（最常用）

先看需求：打印 0 到 4。笨写法是写五遍 `printf`；要打 1000 遍呢？正确姿势是循环：

```c
#include <stdio.h>

int main(void) {
    for (int i = 0; i < 5; i++) {
        printf("第 %d 圈\n", i);
    }
    printf("循环结束\n");
    return 0;
}
```

输出：

```text
第 0 圈
第 1 圈
第 2 圈
第 3 圈
第 4 圈
循环结束
```

`for` 括号里三段话，用分号隔开，各司其职：

```text
for (int i = 0;   i < 5;   i++)
     ↑第一段       ↑第二段    ↑第三段
     进圈前做一次   每圈开始    每圈结束时做
     （造计数器）   前检查条件   （i 加 1）
```

**完整执行时序**（背下这张时序图，for 就再无秘密）：

1. 第一段执行（仅一次）：造出 i = 0
2. 第二段检查：i < 5 成立？ → 进圈执行花括号
3. 圈内代码执行完 → 第三段执行（i++）
4. 回到第 2 步再检查……直到条件不成立，跳出去执行循环后面的代码

**逐圈追踪表**（以后分析任何循环，都手画这张表）：

| 圈次 | 进圈前 i 的值 | `i < 5` 成立？ | 打印 | 圈末 i 变成 |
| --- | --- | --- | --- | --- |
| 1 | 0 | 是 | 第 0 圈 | 1 |
| 2 | 1 | 是 | 第 1 圈 | 2 |
| 3 | 2 | 是 | 第 2 圈 | 3 |
| 4 | 3 | 是 | 第 3 圈 | 4 |
| 5 | 4 | 是 | 第 4 圈 | 5 |
| （第 6 次检查） | 5 | **否，退出循环** | — | — |

注意两个反直觉点：**i 从 0 开始**（不是 1）；**打印 5 圈但条件是 `i < 5`**（第 6 次检查时 i=5 不成立才退）。这两个点错了就是"差一错误"（off-by-one），新手 bug 排行榜第二名（第一名是 3 节的 `=`/`==`）。

**计数器变量名惯用 `i`**（index 的缩写），嵌套循环里用 `i`、`j`、`k`。

### 循环的两种典型姿势

**姿势一：计数循环**——明确知道转几圈（打 10 遍、处理 5 个数据）：

```c
for (int i = 0; i < 10; i++) { ... }
```

**姿势二：遍历数组**——挨个处理每个元素（第 6 节主力用法）：

```c
int data[5] = {3, 7, 1, 9, 4};
for (int i = 0; i < 5; i++) {
    printf("%d ", data[i]);
}
```

### 4.3 while：满足条件就一直转

```c
#include <stdio.h>

int main(void) {
    int count = 0;
    while (count < 3) {          // 先检查条件，成立就进入
        printf("count = %d\n", count);
        count++;                 // ⚠️ 没有这行，条件永远成立，程序永远转
    }
    printf("循环结束\n");
    return 0;
}
```

输出：

```text
count = 0
count = 1
count = 2
循环结束
```

while 只有一段条件，"初始化"和"自增"要自己安排在循环外/循环内。适合**事先不知道转几圈**的场景——"一直读传感器，直到读到大于 30 的值"：

```c
while (read_temperature() <= 30) {
    // 还没达标，继续等
}
```

:::caution[死循环在嵌入式里是常态，不是 bug]
在线编译器里死循环会让程序卡住（记得点停止）。但单片机程序**主循环就是一个刻意的死循环**——设备要 7×24 小时反复执行"读传感器、刷显示、处理网络"。要警惕的只是"不该转的死循环"：比如等一个永远不会来的信号（等的方法在 L2 会讲对）。
:::

### break 和 continue：循环的两个逃生口

```c
#include <stdio.h>

int main(void) {
    for (int i = 0; i < 10; i++) {
        if (i == 3) continue;       // 跳过本圈剩余代码，直接进下一圈
        if (i == 7) break;          // 彻底跳出整个循环
        printf("%d ", i);
    }
    printf("\n结束\n");
    return 0;
}
```

输出：

```text
0 1 2 4 5 6 
结束
```

- **`break`**：立刻终止整个循环，跳到循环后面
- **`continue`**：跳过本圈还没执行的代码，直接进入下一圈（第三段 i++ 照常执行）

### 嵌套循环：圈里套圈（九九乘法表）

```c
#include <stdio.h>

int main(void) {
    for (int i = 1; i <= 3; i++) {
        for (int j = 1; j <= 3; j++) {
            printf("%d×%d=%d\t", i, j, i * j);
        }
        printf("\n");      // 内圈跑完一行，换行
    }
    return 0;
}
```

输出：

```text
1×1=1	1×2=2	1×3=3	
2×1=2	2×2=4	2×3=6	
3×1=3	3×2=6	3×3=9	
```

追踪一下：外圈 i=1 时，内圈 j 从 1 跑到 3 完整转三圈；然后 i=2，内圈又完整三圈……**外圈转 1 圈，内圈转满一整轮**。图像处理、键盘扫描、二维数组遍历全是这个结构。
