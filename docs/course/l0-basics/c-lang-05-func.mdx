# 05 函数与数组

## 5. 函数：操作单的"章节"

程序一大，几百行顺序写下来没人看得懂。**函数（Function）**就是把一段常用操作打包，起个名字，以后喊名字就执行——就像书里的章节：写一次，翻无数次。

```c
#include <stdio.h>

// 定义一个函数：接收两个整数，返回它们的和
int add(int a, int b) {
    return a + b;               // return：结束函数，把结果交回去
}

// 定义一个不返回任何东西（void）的函数
void greet(int times) {
    for (int i = 0; i < times; i++) {
        printf("你好！\n");
    }
}

int main(void) {
    int sum = add(3, 5);        // 喊名字 + 递参数，用变量接住返回值
    printf("3 + 5 = %d\n", sum);

    greet(2);                   // 喊了两次名字的活：打两遍
    return 0;
}
```

输出：

```text
3 + 5 = 8
你好！
你好！
```

### 函数定义的解剖图

```text
int   add (int a, int b)
↑     ↑    ↑
返回  名字  参数列表：调用时"递进来"的值
类型
```

- **返回类型**：这个函数"交出来的东西"是什么类型。什么都交就写 `void`（"空"）
- **参数列表**：一排"待填的空位"，每个空位声明类型和名字。可以没有（写 `void` 或空着）
- **函数体**：花括号里的代码，被喊到才执行

### 三个关键概念

**① 参数是"复印件"**

`add(3, 5)` 执行时，3 和 5 被**复制**给函数内部的 `a` 和 `b`。函数里改 `a`，改的是复印件，外面看不见。验证：

```c
#include <stdio.h>

void try_change(int n) {
    n = 999;                    // 改的是复印件
    printf("函数里看到 %d\n", n);
}

int main(void) {
    int value = 10;
    try_change(value);
    printf("函数外还是 %d\n", value);   // 10！函数里改了个寂寞
    return 0;
}
```

输出：

```text
函数里看到 999
函数外还是 10
```

这解释了很多新手疑惑："我在函数里改了变量，出来怎么没变？"——**你改的是复印件**。想让改动传出去，要用第 8 节的指针。

**② 返回值是"递出来的结果"**

`return a + b;` 做两件事：把结果交还给调用处 + **立刻结束函数**（return 之后的代码不执行）。调用处用变量接住：`int sum = add(3, 5);`。也可以直接嵌进表达式：`printf("%d", add(1, 2) * 10);`。

不需要返回就写 `void`，函数体里不用 `return`（或写光秃秃的 `return;` 表示提前收工）。

**③ 从上往下读：先声明后使用**

C 是从上往下读的。想在 `main` 里调用写在它后面的函数，需要在前面先**声明**一行：

```c
#include <stdio.h>

int add(int a, int b);      // 声明（prototype）："存在一个这样的函数，先记下"

int main(void) {
    printf("%d\n", add(1, 2));   // ✓ 编译器看到过声明，放行
    return 0;
}

int add(int a, int b) {      // 定义（真身）在后面，没关系
    return a + b;
}
```

声明 = 定义的第一行加个分号。**头文件里放的就是一大堆这种声明**——第 13 节接上。

### 函数为什么是"最重要的组织工具"

- **复用**：`blink_led()` 写一次，三个地方喊三次
- **命名即注释**：`if (is_too_hot(temp))` 比 `if (temp > 30)` 可读性强十倍
- **隔离调试**：出问题时先怀疑"最近改的那个函数"，范围立刻缩小

看 ESP-IDF 源码的组织：每个 `.c` 文件装一小组相关函数，每个函数 30 行以内、只干一件事。**从现在起写代码就有意识地这么拆**。

## 6. 数组：一排同规格的盒子

要记 5 个传感器读数，造 5 个变量太蠢（要记 1000 个呢？）。**数组（Array）**是**一排编号连号的盒子**——编号从 0 开始连续排列：

```c
#include <stdio.h>

int main(void) {
    int readings[5] = {12, 15, 11, 18, 14};   // 造 5 个盒子，编号 0～4

    printf("第 1 个（编号 0）: %d\n", readings[0]);
    printf("第 5 个（编号 4）: %d\n", readings[4]);

    readings[2] = 99;              // 往编号 2 的盒子里换新值
    printf("改后编号 2: %d\n", readings[2]);

    // 用循环遍历：挨个处理一遍
    for (int i = 0; i < 5; i++) {
        printf("readings[%d] = %d\n", i, readings[i]);
    }
    return 0;
}
```

输出：

```text
第 1 个（编号 0）: 12
第 5 个（编号 4）: 14
改后编号 2: 99
readings[0] = 12
readings[1] = 15
readings[2] = 99
readings[3] = 18
readings[4] = 14
```

### 语法解剖

```c
int readings[5] = {12, 15, 11, 18, 14};
     ↑      ↑     ↑
     类型   名字   [盒子的数量]，右边的花括号是初始值清单
```

- **访问单个盒子**：`readings[编号]`——方括号里的编号叫**下标（Index）**。下标可以是变量（`readings[i]`），这正是数组与循环配合的根基
- **不初始化也行**：`int readings[5];`——5 个盒子全是垃圾值，跟单个变量一样必须小心
- **初始化可以不写数量**：`int readings[] = {12, 15, 11};`——编译器数一遍自动开 3 个

:::danger[编号从 0 开始 + 越界是嵌入式最凶险的 bug]
两个要点焊死在脑子里：

1. **编号（下标）从 0 开始**。5 个盒子的编号是 0,1,2,3,4——`readings[5]` 不存在！它越界了
2. **越界（访问不存在的盒子）在电脑上可能崩溃，在单片机上可能悄悄改坏别的变量的值**，程序带着伤继续跑，某天随机崩溃。为什么这么危险？内存里你的盒子紧挨着别的数据，越界读写踩到的就是邻居的内存——而且编译器**不报错**

写循环时永远盯住：5 个元素就用 `i < 5`，不是 `i <= 5`。数组长度的标准写法：

```c
int len = sizeof(readings) / sizeof(readings[0]);   // 总字节数 ÷ 每盒字节数 = 盒子数
```
:::

### 数组与循环的四板斧

**板斧一：遍历（挨个读）**——上一例的 for 循环。

**板斧二：累加求和、求最大最小值**：

```c
#include <stdio.h>

int main(void) {
    int readings[5] = {12, 15, 11, 18, 14};
    int sum = 0;
    int max = readings[0];          // 打擂台：先让第一个当擂主

    for (int i = 0; i < 5; i++) {
        sum += readings[i];         // 累加
        if (readings[i] > max) {    // 遇到更强的就换擂主
            max = readings[i];
        }
    }
    printf("总和 %d，最大 %d，平均 %.1f\n", sum, max, sum / 5.0f);
    return 0;
}
```

输出：

```text
总和 70，最大 18，平均 14.0
```

**"打擂台求最大值"**是嵌入式最常用的套路之一——传感器每来一个新值，跟当前最大值比一下。这段代码值得抄三遍。

**板斧三：倒着遍历**：

```c
for (int i = 4; i >= 0; i--) {      // 从最大下标开始往下走
    printf("%d ", readings[i]);
}
```

**板斧四：查找**（找到第一个符合条件的就停）：

```c
int found_index = -1;               // -1 表示"没找到"的约定
for (int i = 0; i < 5; i++) {
    if (readings[i] == 18) {
        found_index = i;
        break;                      // 找到了就退出，不浪费圈数
    }
}
```

### 冒泡排序：数组 + 双重循环的实战

学点有分量的——把 5 个乱序数排成从小到大：

```c
#include <stdio.h>

int main(void) {
    int a[5] = {5, 2, 9, 1, 7};

    for (int i = 0; i < 4; i++) {           // 跑 4 轮
        for (int j = 0; j < 4 - i; j++) {   // 每轮两两比较
            if (a[j] > a[j+1]) {            // 前面的比后面的大？
                int t = a[j];               // 交换这对邻居
                a[j] = a[j+1];
                a[j+1] = t;
            }
        }
    }

    for (int i = 0; i < 5; i++) printf("%d ", a[i]);
    printf("\n");
    return 0;
}
```

输出：

```text
1 2 5 7 9 
```

原理：每轮从左到右**两两比较相邻的数**，大的往后换——一轮下来最大的数一定"冒泡"到了末尾；跑 4 轮全部就位。追踪第 1 轮（a = 5 2 9 1 7）：

| 比较 | 交换后 |
| --- | --- |
| 5 和 2 | 2 5 9 1 7 |
| 5 和 9 | 不换 |
| 9 和 1 | 2 5 1 9 7 |
| 9 和 7 | 2 5 1 7 **9** ← 最大的就位 |

2. 把冒泡排序改成"从大到小"（把 `>` 改 `<`）
