# 06 字符串与指针

## 7. 字符串：一排 char 加一个句号

C 没有现成的字符串类型，一串文字用 **char 数组**存，结尾放一个 `\0`（值为 0 的"结束符"）标记文字到哪结束：

```c
#include <stdio.h>
#include <string.h>       // strlen 等字符串工具在这个箱子里

int main(void) {
    char name[] = "ESP32";    // 简写：自动算长度、自动带结束符，实际 6 格

    printf("内容   %s\n", name);
    printf("长度   %d\n", (int)strlen(name));   // 5：结束符不算长度

    name[0] = 'e';            // 字符串也能按下标改（它就是数组！）
    printf("改后   %s\n", name);
    return 0;
}
```

输出：

```text
内容   ESP32
长度   5
改后   eSP32
```

### 内存里到底存了什么

`char name[] = "ESP32";` 在内存里是这样一个数组：

| 下标 | 0 | 1 | 2 | 3 | 4 | 5 |
| --- | --- | --- | --- | --- | --- | --- |
| 内容 | 'E' | 'S' | 'P' | '3' | '2' | '\0' |

`printf("%s")` 的工作方式：从这个地址开始一个字符一个字符往外吐，**遇到 `\0` 停**。这就是字符串的一切规律的根源：

- **必须给结束符留位置**：想存 5 个字符，数组至少开 6 格。装满 5 格的数组没有结束符，`%s` 会一直读到内存深处打印出乱码——这是 C 著名的缓冲区溢出漏洞的雏形
- **长度不用自己记**：想知道多长，从头数到 `\0` 就是了（`strlen` 干的就是这活）
- **比较字符串不能用 `==`**：`==` 比的是"盒子是不是同一个"（第 8 节指针就懂了），不是内容。比内容用 `strcmp(a, b)`——返回 0 表示一样：

```c
if (strcmp(cmd, "start") == 0) {      // 判断收到的命令是不是 "start"
    // 开工
}
```

### 字符串的常用操作（string.h 工具箱）

| 函数 | 干什么 | 例 |
| --- | --- | --- |
| `strlen(s)` | 长度（不含结束符） | `strlen("abc")` → 3 |
| `strcmp(a, b)` | 比较，返回 0 即相等 | 命令匹配 |
| `strcpy(dst, src)` | 把 src 复制进 dst | `strcpy(name, "new");` |
| `strcat(dst, src)` | 把 src 接到 dst 尾巴上 | 拼接 |

**安全提醒**：`strcpy`/`strcat` 不检查目标盒子的容量，装不下就溢出。工程上用带 n 的版本 `strncpy`/`strncat`，或者 `snprintf`：

```c
snprintf(buf, sizeof(buf), "temp=%.1f", t);   // 最多写 sizeof(buf) 个字符，绝不开小差
```

`snprintf` 你会在 ESP32 代码里大量见到——**把数字拼进字符串的标准姿势**（它就是 printf 的"往字符串里打"版本）。

**试着改一改**：

1. `char buf[5] = "abc";` 能装下吗？`"abcde"` 呢？（后者要 6 格，装不进 5 格数组——编译器会报错或警告，体会"结束符要占位"）
2. 用循环遍历字符串，把每个字符按 `%c` 和 `%d` 同时打印出来，亲眼看看字符和编号

## 8. 指针：存"房间号"的盒子

到了 C 最重要、也最劝退的概念。我们分**五小步**走，每步都跑一个程序。慢慢来，这一节值得花一小时——后面几十页 API 全靠它。

### 8.1 第一步：内存是旅馆，变量住房间

把内存想成旅馆：每个字节是一个房间，每个房间有**房间号（地址，Address）**。变量就住在某个房间里。

- `int x = 25;` → 给 x 分配一个房间，里面住着 25
- 以前我们只关心"房间里住着谁"（值）
- **指针（Pointer）是一种新盒子，里面装的不是"值"，而是"某个值的房间号"**——就像一张房卡

```c
#include <stdio.h>

int main(void) {
    int x = 25;
    int *p = &x;          // p 是"指向 int 的指针"；&x 表示"取 x 的房间号"

    printf("x 的值      %d\n", x);          // 直接看房间里的值
    printf("x 的房间号  %p\n", (void*)&x);  // 每台电脑/每次运行都可能不同
    printf("p 装的      %p\n", (void*)p);    // 和上一行一样——p 存的就是它
    printf("顺 p 找值  %d\n", *p);          // *p = 顺房卡找到房间，看里面的值
    return 0;
}
```

输出（地址在你的机器上会是别的数，这正常）：

```text
x 的值      25
x 的房间号  0x7ffc12345678
p 装的      0x7ffc12345678
顺 p 找值  25
```

两个新符号，务必分清：

| 符号 | 读作 | 意思 |
| --- | --- | --- |
| `&x` | "x 的地址" | x 住在几号房（**取房间号**） |
| `*p` | "p 指的东西" | 顺着房卡找房间，看/改里面的值（**顺房卡找值**） |

记忆钩子：**`&` 出现 = 得到地址；`*` 出现 = 顺着地址找值**。

`int *p` 声明里的 `*` 表示"p 是个指针"，用的时候的 `*p` 表示"顺着 p 找值"——同一个符号两处含义，初学容易混。记住：**声明时打星号 = "这是指针类型"；使用时打星号 = "顺进去找值"**。

声明语法还有个历史遗留的坑：`int* p, q;` 里**只有 p 是指针，q 是普通 int**——星号只管它紧邻的那个变量。所以工程上习惯一行一个指针：`int *p; int *q;`。

### 8.2 第二步：用指针改值——改的是同一个房间

指针指向 x 之后，**通过指针改的就是 x 本身**——因为它们指的是同一个房间：

```c
#include <stdio.h>

int main(void) {
    int x = 25;
    int *p = &x;

    *p = 100;                 // 顺房卡进房间，把值换成 100
    printf("x = %d\n", x);    // x 变成 100！不是 p 变了，是 x 本尊变了

    x = 50;                   // 反过来，直接改 x
    printf("*p = %d\n", *p);  // 顺 p 去看，也是 50——同一间房

    return 0;
}
```

输出：

```text
x = 100
*p = 50
```

**一句话：`x`、`&x`、`p`、`*p` 四个名字，说的是同一个东西的不同视角**——x 是"住在 25 号房的值"，`&x` 是"25 号房这个地址"，p 是"装着 25 号房地址的盒子"，`*p` 是"顺着 p 看到的那个值"。

### 8.3 第三步：指针的用途一——让函数真正改到外面的变量

第 5 节埋的伏笔来了：函数参数是复印件，改了白改。**把房间号递进去，函数就能找到原件去改**：

```c
#include <stdio.h>

// 复印件版：改了白改
void add_one_wrong(int n) {
    n = n + 1;                  // 改的是复印件
}

// 房间号版：改到原件
void add_one(int *n) {          // 我收一张"指向 int 的房卡"
    *n = *n + 1;                // 顺房卡找到房间，把里面的值加一
}

int main(void) {
    int value = 10;

    add_one_wrong(value);       // 递的是复印件
    printf("错误版后 value = %d\n", value);   // 还是 10

    add_one(&value);            // 递的是 value 的房间号！
    printf("正确版后 value = %d\n", value);   // 变 11 了
    return 0;
}
```

输出：

```text
错误版后 value = 10
正确版后 value = 11
```

**这就是底层 API 参数里到处是 `&` 和 `*` 的原因**：它们几乎都通过"递房间号"来读写你的数据。以后看到 `read(&buf, &len)` 就懂了："把 buf 那排房间和 len 那个房间的地址递过去，函数往里写结果"。

### 8.4 第四步：指针的用途二——大件货物不复印

一个 1000 字节的结构体，按值传参要**整包复印** 1000 字节；传指针只递一个 4 字节的房间号。追踪一遍 swap（练习册第 4 题）：

```c
void swap(int *x, int *y) {
    int t = *x;      // 抄下 x 房间的值
    *x = *y;         // y 房间的值搬进 x 房间
    *y = t;          // 抄的备份搬进 y 房间
}

// 调用：swap(&a, &b)   ← 必须递房间号
```

| 步骤 | a 的房间 | b 的房间 | t |
| --- | --- | --- | --- |
| 调用前 | 3 | 8 | — |
| `t = *x` | 3 | 8 | 3 |
| `*x = *y` | 8 | 8 | 3 |
| `*y = t` | 8 | **3** | 3 |

调用时漏写 `&`（写成 `swap(a, b)`）编译器会报类型不匹配——指针参数就是要收地址，**这反而是 C 帮你把关的地方**。

### 8.5 第五步：指针为什么危险——空房卡和垃圾房卡

```c
#include <stdio.h>

int main(void) {
    int *p = NULL;              // NULL = "这张房卡是空的，不指向任何房间"
    if (p != NULL) {            // 用之前先检查——好习惯
        printf("%d\n", *p);
    } else {
        printf("p 是空的，不能顺它找值\n");
    }

    int *q;                     // ✗ 没初始化：里面是随机的垃圾"房间号"
    // printf("%d\n", *q);     // ✗ 打开注释就会闯进陌生房间——崩溃或悄悄出错
    return 0;
}
```

输出：

```text
p 是空的，不能顺它找值
```

**NULL** 是一个约定的"空地址"常量，专门用来表示"这张卡不指向任何房间"。它什么都指不了，所以拿 `*NULL` 找值，程序会当场崩溃（这其实是好事——把错误亮出来，好过悄悄搞坏数据）。

:::danger[指针三条安全守则]
1. 声明指针时**立刻**初始化（`NULL` 或真实地址），绝不留"垃圾房卡"（野指针）
2. 顺房卡找值（`*p`）之前，确认它不是 `NULL`
3. 函数收指针参数时，第一件事常常是 `if (p == NULL) return -1;`——ESP-IDF 的源码全是这么写的
:::

### 8.6 补充：指针和数组是一家、`->` 箭头

两个常用事实，见到不慌即可：

```c
int a[5] = {1,2,3,4,5};
int *p = a;              // 数组名传参时自动变成"0 号盒子的房间号"，不用写 &
p[2]                     // 等价于 a[2]
*(p + 2)                 // 也等价于 a[2]：从 0 号房间往后数 2 个 int 的位置
float average(int *arr, int len);   // 函数收数组 = 收指针；长度得另外传（指针不知道数组多长）
```

"数组名 = 首元素地址"解释了"函数收数组为什么还要收长度"：递过去的只是一张 0 号房卡，**数组有多长这个信息没跟着走**，所以要另传一个 len。

还有结构体指针的字段访问简写：

```c
d->temperature          // 等价于 (*d).temperature
                        // "顺房间号 d 找到包裹，取里面的 temperature 字段"
```

箭头 `->` 在结构体指针场景天天见（下一节实战）。另外 `sizeof(p)` 得到的是**指针本身的大小**（4 字节），不是数组长度——想知道数组长度永远在"数组名退化成指针之前"用 `sizeof(数组名) / sizeof(数组名[0])`。

**过关自测**：不看上文，说出 `&value`、`*p`、`p->field`、`sizeof(a)/sizeof(a[0])` 各是什么意思。说得出，指针这关就算过了。
