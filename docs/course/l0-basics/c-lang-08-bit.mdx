# 08 位运算与函数指针

## 11. 位运算：直接操纵 0 和 1

先热身二进制。回忆铺垫页：一个字节 = 8 个比特，每比特 0 或 1。十进制 10 的二进制是 `0000 1010`（8+2）。**十六进制（0x 开头）是二进制的缩写**——每 4 个比特折成 1 个十六进制位：`0xAB` = `1010 1011`（A=10=1010，B=11=1011）。嵌入式代码里十六进制满天飞，就是因为**它和二进制一眼能对上**。

### 移位：左移乘 2，右移除 2

```c
1 << 3        // 1 左移 3 位：0000 0001 → 0000 1000 = 8
12 >> 2       // 12 右移 2 位：0000 1100 → 0000 0011 = 3
```

**手册里的 `BIT(3)` 就是 `1 << 3` 的宏**："第 3 位是 1、其他位是 0 的数"。"第 n 位"从 0 开始数，和数组下标一样。

### 掩码操作：两个模板走天下

**掩码（Mask）**= 一个精心设计的 0/1 图案，用来"遮住"某些位、操作另一些位。两个必须背熟的模板（以"操作 reg 的第 3 位"为例）：

```c
reg |=  (1 << 3);         // 置 1：或上"只有第 3 位是 1 的数"，其他位不动
reg &= ~(1 << 3);         // 清 0：与上"只有第 3 位是 0 的数"（掩码取反）
```

为什么这样行？先弄懂两个位运算：

**按位或 `|`**：两边有任一 1 就得 1。用它**无伤置位**——把第 3 位置 1，其他位保持：

```text
    reg    = 1010 0011
    掩码   = 0000 1000     ← (1 << 3)
    或起来 = 1010 1011     ← 第 3 位变 1，其他位原样保留
```

**按位与 `&`**：两边都是 1 才得 1。用它**无伤清位**——掩码取反后第 3 位是 0、其他位是 1：

```text
    reg    = 1010 1011
    ~掩码  = 1111 0111     ← ~(1 << 3)：只有第 3 位是 0
    与起来 = 1010 0011     ← 第 3 位变 0，其他位原样保留
```

**读某一位**：

```c
bool bit = (reg >> 3) & 1;            // 先右移 3 位把目标位送到最右边，再 & 1 孤立它
uint32_t field = (reg >> 8) & 0x1F;   // 取第 8～12 位共 5 个比特：先右移 8 对齐，再用 0x1F（0001 1111）掩出 5 位
```

完整验证程序：

```c
#include <stdio.h>

int main(void) {
    unsigned char reg = 0b10100011;     // 二进制字面量写法（在线编译器一般支持）
    printf("原始      %02X\n", reg);
    reg |= (1 << 3);
    printf("第3位置1  %02X\n", reg);     // 0xAB
    reg &= (unsigned char)~(1 << 3);
    printf("第3位清0  %02X\n", reg);     // 0xA3
    printf("第1位是   %d\n", (reg >> 1) & 1);
    return 0;
}
```

### 理解了这些意味着什么

`gpio_set_level(GPIO_NUM_4, 1)` 的底层本质是"把 0x10（第 4 位是 1）写进 GPIO 输出寄存器"——`digitalWrite` 之类的函数从此不是黑盒。寄存器手册里写"bit 7: TX enable"，你就能写出 `uart_reg |= (1 << 7);`。

**试着改一改**：

1. 把 0xF0 的高 4 位和低 4 位互换（提示：`(b >> 4) | ((b & 0x0F) << 4)`，练习册第 5 题详解）
2. 写"切换"操作：第 3 位是 0 变 1、是 1 变 0（提示：异或 `reg ^= (1 << 3);`——两边不同得 1）

## 12. 函数指针与回调：把"操作单章节"当参数传

函数也有地址（它也是存在内存里的数据！），所以函数也能装进指针、当参数传。这在嵌入式里叫**回调（Callback）**：

```c
#include <stdio.h>

typedef void (*event_cb_t)(int event);    // 类型："指向收一个 int、不返回值的函数的指针"

void on_wifi_ready(int event) {
    printf("WiFi 就绪，事件=%d\n", event);
}

static event_cb_t s_callback = NULL;      // 存"到时候要喊的函数"

void register_callback(event_cb_t cb) {   // 别人把函数"注册"进来
    s_callback = cb;
}

void wifi_ready_happens(void) {           // 假设系统某刻发现 WiFi 好了
    if (s_callback != NULL) {
        s_callback(1);                    // 通过指针"回调"你的函数
    }
}

int main(void) {
    register_callback(on_wifi_ready);     // 登记
    wifi_ready_happens();                 // 到点了，系统喊你
    return 0;
}
```

输出：

```text
WiFi 就绪，事件=1
```

### 逐层拆解

**typedef 那行的读法**（最难的一行，慢点）：

```c
typedef void (*event_cb_t)(int event);
//        ↑    ↑          ↑
//        无    叫这样名字   这样的函数：
//        返回  的指针类型    收一个 int、无返回
```

整个意思是："造一个新类型叫 `event_cb_t`，它是'函数指针'，能指向任何'收一个 int、不返回值'的函数"。

**使用流程四步**：

1. 系统定义回调类型 + 提供 `register` 函数
2. 你写一个**签名匹配**的函数（参数、返回值类型都对上）
3. 把你的函数名传给 register（函数名本身就是地址，像数组名）
4. 事件发生时系统顺指针调用你的函数

**为什么要这么绕？** 因为写系统的人不知道你想在 WiFi 就绪时干什么——有人点灯，有人联网。系统只负责"到时候喊你"，你把想干的事打包成函数登记进去。这就是**控制反转**：平时你调系统，此刻系统调你。

**WiFi 事件、按键中断、MQTT 消息，全是这个模式**。读代码看到 `register...` / `..._handler` / `..._callback`，就往这里想。

**试着改一改**：

1. 再写一个 `void on_other_event(int event)`，注册它代替第一个，运行看谁被喊
2. 注册后把 `s_callback` 置回 NULL 再触发事件——没事发生。这就是第 8 节"用指针前查 NULL"的实际意义
