# 09 头文件、宏与速查表

## 13. 头文件与宏：代码的"目录"和"缩写"

### 头文件：工具箱清单

C 的代码按文件组织。随着项目变大，你会拆出 `sensor.c`、`net.c`、`display.c`……每个 `.c` 文件放实现（函数真身），配一个 `.h` 文件（**头文件，Header**）放"清单"——函数声明、类型定义、常量。想用别人模块里的函数：

```c
#include "driver/gpio.h"       // 双引号：先在项目内找（自己/组件的头文件）
#include <stdint.h>            // 尖括号：在系统/标准库里找
```

`#include` 的本质是**复制粘贴**：编译前，把头文件内容原样贴进这一行。所以头文件里放声明（函数长什么样），`.c` 里放定义（函数真身）——所有文件 include 同一个头文件，就都"认识"这些函数了。

**头文件保护罩**：头文件会被很多文件 include，而 include 是复制粘贴，同一个头文件可能被贴两次（A 包含 B 和 C，B 和 C 又都包含 D）——重复定义直接报错。解法是"保护罩"：

```c
#ifndef MY_DRIVER_H          // 如果还没定义过这个标记
#define MY_DRIVER_H          // 就定义它，并让下面的内容生效
// ... 头文件内容 ...
#endif                       // 第二次被 include 时，标记已存在，内容自动跳过
```

（工程上常见 `#pragma once` 一行版，效果相同。）

**查 API 的最佳路径不是搜索引擎，是头文件**：IDF 所有 API 都有对应头文件，开头通常直接写着用法说明和官方文档链接。方法见"怎么学"一页。

### 宏：编译前的文字替换

```c
#define LED_PIN 4        // 编译前，把代码里所有 LED_PIN 文字替换成 4
```

**宏（Macro）在编译之前就完成了替换**，所以没有类型检查、也不占运行时间。`LED_PIN` 为什么好过裸写 4？——板子改版 LED 挪到 5 号脚，只改一行；裸写的话 20 处 4 要挨个找，漏一处就是诡异 bug。

带参数的宏（"文字级别的函数"）：

```c
#define SQUARE(x) ((x) * (x))

int a = SQUARE(5);       // 展开成 ((5) * (x)) 里的 x 换成 5 → ((5) * (5)) = 25
```

注意外层括号——宏是纯文字替换，`SQUARE(1+2)` 不加括号会展开成 `1+2*1+2 = 5`（错的！），加括号是 `((1+2)*(1+2)) = 9`。**这就是为什么宏定义里括号成灾**。

IDF 里大量配置开关是宏，条件编译也是宏：

```c
#if CONFIG_MY_DRIVER_DEBUG_LOG
    ESP_LOGI(TAG, "详细日志开着");     // 只有配置打开时，这几行才参与编译
#endif
```

## 14. 错误处理：ESP-IDF 的 `esp_err_t`

前面说过"返回值能把结果递出来"。IDF 把这个约定标准化了：**几乎每个 API 都返回 `esp_err_t`（本质是个 int），0 = 成功（`ESP_OK`），非 0 = 各种错误码。**

```c
esp_err_t err = some_api();
if (err != ESP_OK) {
    ESP_LOGE(TAG, "失败: %s (0x%x)", esp_err_to_name(err), err);
    return err;      // 向上传递，不要吞掉
}
```

**惯例的解读**：

- `ESP_OK` = 0 = 成功；每个错误码是一个负数或特定值，如 `ESP_ERR_NO_MEM`（内存不够）、`ESP_ERR_INVALID_ARG`（参数不合法）
- `esp_err_to_name(err)` 把错误码翻译成人话（"OUT_OF_MEMORY"），打日志时带上
- **错误要向上传递**：低层函数失败，把错误码 return 给调用者，一层层传到能做决策的地方。**绝不能"吞掉"**（收到错误码装没事发生）——吞掉的错误会在很久以后以诡异的方式爆炸

:::caution[为什么不能写 `if (err)`]
第 2.1 节说过"非 0 即真"。但 `ESP_OK` 是 0、错误码都非 0，和这个惯例刚好**相反**：`if (err)` 在这里会把"成功"（0）判成"失败"、把"失败"（非 0）判成"成功"，完全颠倒。必须显式写 `if (err != ESP_OK)`。
:::

常用快捷宏（遇到再查，先混个脸熟）：

```c
ESP_ERROR_CHECK(err);                          // 失败就打印并立即停止程序（调试期用）
ESP_RETURN_ON_ERROR(err, tag, "msg");          // 失败打日志并 return
ESP_RETURN_ON_FALSE(cond, ret, tag, "msg");    // 条件不满足就 return
```

## 15. 语法速查表（打印贴墙上）

| 想做什么 | 写法 |
| --- | --- |
| 整数 / 小数 / 真假 | `int n = 0;` / `float f = 0.5f;` / `bool ok = true;` |
| 无符号定宽 | `uint8_t` `uint16_t` `uint32_t` |
| 打印 | `printf("%d %f %s\n", n, f, s);` |
| 条件分支 | `if (x > 0) {...} else if (...) {...} else {...}` |
| 循环 10 次 | `for (int i = 0; i < 10; i++) {...}` |
| 条件循环 | `while (cond) {...}` |
| 逃生口 | `break`（跳出循环）/ `continue`（跳过本圈） |
| 打包函数 | `int add(int a, int b) { return a + b; }` |
| 数组 | `int a[5] = {1,2,3,4,5};` 下标 0～4 |
| 数组长度 | `sizeof(a) / sizeof(a[0])` |
| 字符串比较 | `if (strcmp(a, b) == 0)` |
| 拼进字符串 | `snprintf(buf, sizeof(buf), "t=%d", n);` |
| 取地址 / 顺指针找值 | `&x` / `*p` |
| 指针访问字段 | `p->field` |
| 造新类型 | `typedef struct {...} name_t;` |
| 只读 / 有记忆 / 借用 / 易变 | `const` / `static` / `extern` / `volatile` |
| 第 n 位置 1 / 清 0 | `reg \|= (1 << n);` / `reg &= ~(1 << n);` |
| 判断错误 | `if (err != ESP_OK) {...}` |

## 16. 三个新手必踩的坑（复习）

| 坑 | 错误写法 | 正确做法 |
| --- | --- | --- |
| `=` 和 `==` 混用 | `if (x = 5)` | `if (x == 5)` |
| 整数除法丢小数 | `float v = raw / 4095;` | `float v = raw / 4095.0f;` |
| 数组越界 / 差一错误 | `a[5]`（只有 0～4）、`i <= 5` | 下标最大 4、`i < 5` |

外加三条纪律（不踩以上坑的保险丝）：

1. **变量声明时就初始化**（不给垃圾值机会）
2. **if/for/while 永远写花括号**（哪怕只有一句）
3. **每个例子都亲手跑过再往下读**（看懂 ≠ 会写）

全部可以在在线编译器完成，不需要板子。**做完去练习册对答案**：

- [ ] 写一个程序：定义一个 `float` 变量存摄氏温度，换算成华氏度并打印（公式 F = C × 9/5 + 32）
- [ ] 用 `for` 循环打印 1～100 里所有 3 的倍数（两种写法都试）

- [ ] 写一个带 `static` 局部变量的函数，连续调用 3 次，观察值是否延续
