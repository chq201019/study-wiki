## 从按下复位到 app_main：先建立这条主线

在讲多任务之前，先要知道**程序是怎么起来的**。很多人调不通程序，根本原因是不知道代码跑到哪一步了：

![ESP32-S3 启动链：上电 → Bootloader → 校验加载 app → 运行时初始化 → 应用运行](/img/diagrams/esp32-boot-chain.svg)

记住这条链的实用价值：**串口在第 ④ 步之前完全没有 printf 输出**。所以"串口一片空白"往往说明问题出在 ①②③，而不是你的 `app_main` 写错了。

## 核心心智模型

```mermaid
flowchart TB
  subgraph 启动阶段
    A[app_main] --> B[创建各种子系统]
  end
  subgraph 运行时
    C[Main Task<br/>app_main 所在] 
    D[其他应用任务<br/>你自己创建]
    E[WiFi 任务]
    F[蓝牙任务]
    G[Idle 任务<br/>系统所有任务都空闲时才跑]
    H[Tick 任务<br/>时间片轮转调度]
  end
  subgraph 通信机制
    I[队列 Queue]
    J[信号量 Semaphore]
    K[事件组 EventGroup]
    L[ESP 事件循环 esp_event]
  end
  C --> I
  D --> I
  E --> L
  L --> D
```

三条必须建立的认知：

1. `app_main` 只是启动代码，它返回后程序不会结束，而是进入 FreeRTOS 调度。真正的逻辑要放在你自己创建的任务里
2. 事件驱动优于轮询。ESP-IDF 里 WiFi、蓝牙都以事件形式广播，系统事件循环帮你分发
3. 阻塞等待不消耗 CPU。这是低功耗设计的地基
