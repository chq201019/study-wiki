# QS-1 装米思齐，跑通第一个图形化程序

**时长 40 分钟 · 产出：拖几块积木，点上传，板载灯闪起来**

这套教程全程用米思齐图形化，不需要你写任何代码。

## 为什么用米思齐

米思齐离线客户端把「编译 + 烧录 + 看串口」全包了，你只要拖积木和点按钮。积木有颜色和形状，拼错很难发生。

## 下载

去 [mixly.cn](https://mixly.cn) 下载 **Mixly 离线版**并安装。本教程的截图基于 Mixly 3.0，更高版本的界面大同小异。

:::danger[安装路径这一关，必须先过]
下载、解压、安装三步里，**任何一步把米思齐放进了带中文、带空格、层级太深的目录，后面就会莫名其妙报错**——而且报错信息通常只写着编译失败或找不到文件，根本看不出是路径的锅。

按这个规矩放：

| ✅ 可以 | ❌ 不可以 |
| --- | --- |
| `D:\mixly` | `C:\Users\张三\Desktop\新建文件夹\mixly-3.0` |
| `D:\Mixly3` | `C:\Program Files\Mixly 3.0` |
| 盘符根目录下、纯英文、不要空格 | 桌面、下载文件夹、中文用户名下、压缩包原名 |

**具体操作：**

1. 下载得到的是**压缩包**，先解压
2. 把解压出来的文件夹**整个**移到 `D:\` 下，重命名成 `mixly`
3. 最终路径就是 `D:\mixly`（文件夹里面的 `Mixly.exe` 不动）

> 路径总长度**控制在 60 个字符以内**最稳。Windows 有一条历史遗留的 260 字符路径上限，米思齐编译时会生成很深的临时目录，起点路径越长越容易撞上，报错往往发生在编译阶段而不是安装阶段。

已经装错位置了？把整个文件夹移到 `D:\mixly` 就行，米思齐是绿色免安装的，移动后重新打开即可。（少数版本需要再运行一次文件夹里的「一键更新」脚本。）
:::

:::info[在线版和离线版选哪个]
| | 在线版 | 离线版（推荐） |
| --- | --- | --- |
| 要不要安装 | 打开网页就能用 | 要下载安装 |
| 能不能接实物板子 | ❌ 只有 MicroPython 模式，板子上得先有固件 | ✅ 能选板卡、能直接上传 |
| 断网能用 | ❌ | ✅ |

要接实物板子，就用离线客户端。
:::

## 打开米思齐：先选板卡

打开后是一个板卡选择页，翻到第二页，点 **Arduino ESP32**（编程语言 C/C++）：

![板卡选择页第二页，点 Arduino ESP32](/img/mixly/home-arduino-arrow.png)

进入编辑器后先别急着拖积木——右上角显示的默认板卡是 `ESP32 Dev Module`，那是老款 ESP32，不是你的板子。要先改两处设置。

### ① 右上角选开发板 → 选 `ESP32S3 Dev Module`

点右上角的板卡名称，弹出列表后在搜索框输入 `s3`，点选 **ESP32S3 Dev Module**：

![板卡下拉里搜索 s3，选 ESP32S3 Dev Module](/img/mixly/board-select.png)

:::danger[最容易踩的坑]
默认的 `ESP32 Dev Module` 是老款 ESP32 的板子，选错了轻则烧不进去，重则烧进去了行为莫名其妙。选完记得看一眼右上角显示的是 `ESP32S3 Dev M…`。
:::

### ② 点串口按钮，波特率选 `9600`

串口按钮在**左上角**（不是右上角）。点它，下方会展开串口窗口；波特率下拉框在**串口窗口的右下角**（下图红色箭头指的位置），选 `9600`：

![串口窗口，红色箭头处是波特率，选 9600](/img/mixly/serial-baud-arrow.png)

:::warning[为什么必须是 9600]
米思齐的默认波特率就是 9600，后面所有示例程序里串口初始化的值也都是 9600。两边不一致，串口里就全是乱码。
:::

> 没插板子的时候，串口窗口会提示 `Error: Opening COMx: Access denied`，这不是坏了——等板子插上、③ 选对 COM 口就正常了。

### ③ 选 COM 口

**COM 口是 Windows 给串口设备编的号**（COM1、COM3……），米思齐就是通过它跟板子说话的。选口之前，先把数据线插在板子**丝印 `COM`** 的那个 Type-C 口上（两个口怎么分，见 [QS-0](./board)）。

选的地方有两个，任选一个：

- **右上角工具栏**：板卡名称旁边就有 COM 下拉框
- **串口窗口**：点 **＋** → **打开串口**，在子菜单里选

![点串口窗口的 ＋ → 打开串口，子菜单里列出所有 COM 口；右上角工具栏也有一个 COM 下拉框](/img/mixly/serial-com-arrow.png)

下拉框里选哪个？一个百试百灵的办法：

1. 板子**没插上**时先点开看一眼——上图里只剩 `COM1` 就是这种情况。`COM1` 是电脑主板自带的，**别选它**
2. 插上板子，再点开下拉框，**多出来的那个**就是你的板子（通常是 `COM3`、`COM4` 这样的号）

两个常见状况：

- **插上后列表里没多出新口**：十有八九是数据线只能充电不能传数据，换根线再试
- **不确定选哪个**：随便选一个试上传，报错就换下一个——选错了顶多传不进去，不会损坏板子

选对之后，窗口最底部的状态栏会显示 `ESP32S3 Dev Module 在 COMx`，xx 对应你选的号，看到它就说明米思齐已经找到板子了。

## 拖第一个程序

板载灯是一颗 **WS2812 RGB 灯**，不能用普通的「数字输出」积木点亮，要用「RGB灯」积木。在中间的程序区，按下面的顺序从上到下拼。**程序区里直接摆的积木，默认就在主循环里反复执行**，不用再包一层循环积木：

```text
RGB灯初始化 管脚# 48 类型为 NEO_GRB 灯数 1     ← 板载灯所在引脚；新批次板子在 38，就选 38
RGB灯 管脚# 48 灯号 1 颜色 R 255 G 0 B 0      ← 点亮，红色
延时 500 毫秒                                 ← 「控制」分类
RGB灯 管脚# 48 灯号 1 颜色 R 0 G 0 B 0        ← 熄灭
Serial 打印 自动换行 "ESP32-S3 运行中"         ← 「串口」分类
延时 500 毫秒
```

:::tip[类型选 NEO_GRB，别动默认值]
「RGB灯初始化」的类型下拉有三个选项，板载这种 WS2812 灯选 **NEO_GRB**（默认就是它，不用改）——WS2812 内部是三通道，但数据字节顺序是绿-红-蓝。快速验证：设成红色点亮，亮出红色就对了；亮出绿色/蓝色说明字节序不匹配，换 `NEO_RGB` 再试。`NEO_RGBW` 是给带白灯珠的四通道灯用的（比如 SK6812-RGBW），别用在板载灯上。

另外注意积木默认值是**管脚 0、灯数 4**，要手动改成：管脚 48（v1.1 板是 38）、灯数 1。灯数填多了不报错，但 `灯号` 只有第 1 颗有效。
:::

:::danger[别用「数字输出」点板载灯]
WS2812 是可寻址 RGB 灯，靠特定时序的脉冲通信，普通高低电平点不亮——「数字输出 管脚# 48」怎么做灯都不亮，不是板子坏了。必须用「RGB灯」积木（板载资源分类里，积木名带 RGB；生成的是 Adafruit_NeoPixel 代码）。
:::

:::danger[积木必须从上到下依次摆放]
米思齐是把积木按你摆放的顺序，从上到下一层层翻译成代码的。所以：

- 积木之间会咬合，塞不进就说明位置不对，别硬拽
- 换顺序 = 换执行顺序，代码也会跟着变
- 想改逻辑，把积木拖出来重新摆，不要试图往中间插一块

摆错了的表现：积木之间有缝隙、粘不上去，或者积木上的字被画了一道横线——那是米思齐在标记"这个位置不匹配"，把它拖走重摆就好。
:::

### 这几块积木在哪

| 分类 | 要用的积木 |
| --- | --- |
| **板载资源** | RGB灯初始化、RGB灯（找不到就在「执行器」「输入/输出」里翻，积木名带 RGB） |
| **控制** | 延时 … 毫秒 |
| **串口** | Serial 打印（自动换行） |

![米思齐里的「RGB灯」积木（截图里管脚是 0、灯数 4，本教程选 48 或 38、灯数 1）](/img/mixly/blocks-rgb.png)

灯的引脚号不用记：v1.0 板载灯在 **GPIO48**，v1.1 板在 **GPIO38**，选一个不亮就换另一个，见[引脚速查](../reference/pinout)。

## 上传

点左上角的 **上传** 按钮。第一次会先编译，等十几秒到一分钟，出现「上传成功」就完成了。

:::tip[「编译」和「上传」的区别]
| | 干什么 |
| --- | --- |
| **编译** | 只检查积木能不能生成代码，不碰板子 |
| **上传** | 编译通过后把固件烧进板子，板子开始跑 |

只点编译，板子是没有任何反应的。要让板子动，必须点「上传」。
:::

## 看串口

串口窗口（第 ② 步已经打开）里应该开始滚动：

```text
ESP32-S3 运行中
ESP32-S3 运行中
ESP32-S3 运行中
```

板载 RGB 灯同时在红色亮灭交替地闪。

:::warning[串口全是乱码？]
检查两边的波特率：

1. 程序里 `Serial` 积木的波特率是 9600（本教程示例都写死了 9600）
2. 串口窗口右下角的下拉框也是 9600

两边必须一致，否则就是乱码。
:::

## 想看积木变成了什么代码？点「混合」

顶部中间有三个模式：**模块**（只看积木）、**混合**（积木 + 代码并排）、**代码**（只看代码）。点 **混合**，右边就是当前积木生成的 Arduino C++ 代码：

![混合模式：左边积木，右边生成的代码](/img/mixly/mixed-mode.png)

这段代码你完全不需要看懂也不用改。它只是告诉你这些积木在底下干了什么，出问题时心里有数。（想搞懂的话，完整教程里有专门章节，不学也完全不影响做出东西。）

## 检查清单

- [ ] 板卡选了 `ESP32S3 Dev Module`（右上角能看到）
- [ ] COM 口选的是插上板子后**多出来的那个**（状态栏显示 `… 在 COMx`）
- [ ] 串口窗口右下角波特率是 `9600`，串口输出不乱码
- [ ] 拖好积木，点上传，灯在闪
- [ ] 知道点「混合」能看到积木对应的代码
