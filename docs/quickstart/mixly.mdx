# QS-2 米思齐入门：界面和常用积木

**时长 45 分钟 · 产出：能自己拼出「按键控制灯 + 串口打印」的程序**

不需要系统学编程，只需要认清积木分了几类、每类管什么、以及积木是怎么变成代码的。

## 界面上就这几块

![米思齐编辑器界面：左侧积木分类、中间程序区、顶部工具栏](/img/mixly/editor.png)

| 位置 | 干什么 | 要记得的事 |
| --- | --- | --- |
| 左边一竖条 | 积木分类 | 按名字分类，点开把积木拖到中间 |
| 中间空白 | 程序区 | 积木在这里**从上往下**拼 |
| 左上角 | 编译 / 上传 / 串口 | 让板子动起来的是「上传」 |
| 右上角 | 板卡、COM 口 | 板卡要是 `ESP32S3 Dev Module` |
| 串口窗口右下角 | 波特率 | 选 `9600` |

## 最重要的一条规则：积木从上到下，代码也一样

米思齐不是"实时"的，它不做实时解释执行。你拼好一整块积木之后，它会按积木摆放的顺序，从上到下一层层翻译成代码，再编译成固件烧进板子。

这带来几个必须知道的结论：

| 现象 | 原因 |
| --- | --- |
| 改积木顺序 = 改执行顺序 | 代码是照着摆放顺序生成的 |
| 积木之间有咬合形状，塞不进去就是位置不对 | 语法结构由积木形状固定，不能乱插 |
| 上下两块对不上 | 你少了一块关键的（比如缺「延时」） |
| 同一段逻辑摆两次，代码就是两份 | 不会自动合并 |

所以：想改逻辑，正确做法是把积木拖出来、从上往下重新摆好，而不是试图往中间塞一块。积木摆不对，生成的代码一定是错的。

:::tip[一个判断方法]
摆完之后从上往下扫一眼，每一层积木都要么单独成一个完整语句，要么正好咬进上一层的缺口。有缝隙就是没摆对。
:::

## 积木有哪些分类

积木按名字分类，左边那一竖条从上到下排着这些：

| # | 分类 | 管什么 | 什么时候用得到 |
| --- | --- | --- | --- |
| 1 | **输入/输出** | 数字输出、数字输入、模拟输入 | 几乎每节都要用 |
| 2 | **控制** | 重复执行、如果/否则、延时 | 几乎每节都要用 |
| 3 | **数学** | 加减乘除、取余、随机数 | 算距离、算角度 |
| 4 | **逻辑** | 并且、或者、比大小 | 组合判断条件 |
| 5 | **文本** | 拼接字符串 | 打印中文提示 |
| 6 | **数组** | 一串数据 | 存一组读数 |
| 7 | **变量** | 存一个数或一段文字 | 到处都是 |
| 8 | **函数** | 把常用的一段打包 | 重复逻辑 |
| 9 | **串口** | Serial 打印、串口初始化 | 调试必用 |
| 10 | **板载资源** | 板子自带的东西 | 按键、灯（视板卡而定） |
| 11 | **传感器** | 温湿度、光照、人体… | 装了扩展之后才有 |
| 12 | **执行器** | 舵机、电机、继电器 | 装了扩展之后才有 |
| 13 | **显示器** | OLED、数码管、TFT | 装了扩展之后才有 |
| 14 | **通信** | 蓝牙、串口透传 | 装了扩展之后才有 |
| 15 | **存储** | 读写 SD 卡/Flash | 装了扩展之后才有 |
| 16 | **网络** | WiFi、MQTT | 装了扩展之后才有 |
| 17 | **自定义模块** | 你自己封装的积木 | 自己做东西时才用 |
| 18 | **工具** | 杂项 | 很少用到 |

:::tip[记不住就记住三个]
刚上手只需要认准 **输入/输出**、**控制**、**串口** 这三个分类，够写完本教程 90% 的东西。

打印内容用的积木叫 **Serial 打印**，在「串口」分类里——别在「输入/输出」里白找半天。
:::

## 六个必会积木

整套教程其实就反复用这几个：

| 积木 | 在哪个分类 | 干什么 |
| --- | --- | --- |
| **重复 执行（满足条件 …）** | 控制 | 条件循环：条件成立才转一圈，配「跳出循环」用。主程序不用它——程序区的积木默认就在循环里 |
| **延时 … 毫秒** | 控制 | 停一下。太快会看不清、会乱跳 |
| **数字输出 管脚# X 设为 高/低** | 输入/输出 | 控制灯、继电器、舵机信号脚 |
| **数字输入 管脚# X** | 输入/输出 | 读按键 |
| **如果…执行…（否则）** | 控制 | 判断，比如按键按下；「否则」要靠小齿轮加出来 |
| **Serial 打印（自动换行）** | 串口 | 最重要，你的程序在想什么全靠它 |

:::tip[最重要的一条习惯]
每加一个功能，就加一行 Serial 打印。板子不出问题时你能看到它在干嘛，出问题时也能立刻看出停在哪一步。这是新手和熟手的最大差别。
:::

## 有些积木带小齿轮，能"加分支"

注意到有些积木左上角有个**小齿轮**了吗？点它可以给积木加仓位。最常用的是「如果」：默认只有"如果…执行…"，点一下小齿轮，把「否则」拖进右边，它就变成"如果…执行…否则…"；再拖一个「否则如果」上去，还能加好几个判断分支：

![点「如果」上的小齿轮，可以加「否则如果」和「否则」分支](/img/mixly/gear-else.png)

所以**「否则」不是单独一块积木**，别在积木栏里找它——它是从「如果」的小齿轮里加出来的。带齿轮的积木还有不少（比如循环能加跳出条件、函数能加参数），看到齿轮就点开看看，不咬坏，试了才知道。

## 完整例子：按键控制灯

在程序区从上到下这样摆：

```text
初始化                                    ← 「控制」分类，只跑一次
  ├─ Serial 打印 自动换行 "按键控制灯"
  └─ 管脚模式 5 设为 上拉输入              ← 「输入/输出」分类，往下翻才找得到
如果 <数字输入 管脚# 5 的值 = 0> 执行
│    └─ 数字输出 管脚# 4 设为 低     （按下 → 灭）
否则
│    └─ 数字输出 管脚# 4 设为 高     （松开 → 亮）
延时 50 毫秒
```

:::danger[「管脚模式」积木不能少]
按键那脚必须设成上拉输入（上面初始化里的「管脚模式 5 设为 上拉输入」）。漏了它，引脚悬空，读数会乱跳，灯跟着乱闪——这正是"松开读到 1"能成立的唯一前提。
:::

关键点：

| 积木 | 为什么这么设 |
| --- | --- |
| 按键接 GPIO5，另一端接 GND，引脚用**上拉输入** | 按下读到 `0`，松开读到 `1`（上拉模式在 [QS-4](./arduino-basics) 细讲） |
| 最后一块必须是「延时」 | 缺了它，循环末尾的积木会咬不进「如果」的缺口，代码就错了 |
| 延时 **50 毫秒** 而不是 10 毫秒 | 太短按键会重复响应，看着像"按一下跳好几格" |

:::danger[拼接顺序别搞反]
先放「如果」，用小齿轮把「否则」分支加出来，最后「延时」放在最外层。

顺序错了的话，积木会显示成"塞不进去"的状态——这就是积木形状在帮你检查语法。
:::

## 装扩展（接传感器必备）

米思齐自带的积木不够用时要装扩展：

1. 点右上角 **设置 → 管理库**
2. 切到 **导入库** 标签
3. 点"打开"，选择你下载的 `.zip` 或 `.xml` 扩展文件
4. 点确定，界面会自动刷新，左边多出新分类

:::caution[装扩展前先确认]
扩展必须明确支持 ESP32-S3。老扩展只支持经典 ESP32，装了会报错或者积木是空的。

装完之后把板卡删掉再重新选一次 `ESP32S3 Dev Module`，扩展才会正确加载。
:::

## 混合模式：想看代码时点它

顶部中间有三个模式：**模块**（只看积木）、**混合**（积木和代码并排）、**代码**（只看代码）。点 **混合**，右边就是当前积木对应的 Arduino C++ 代码：

![混合模式：左边积木，右边生成的代码](/img/mixly/mixed-mode.png)

上面那个按键控制灯的例子，混合模式里大致是这样：

```cpp
void setup() {
  Serial.begin(9600);
  Serial.println("按键控制灯");
  pinMode(4, OUTPUT);
  pinMode(5, INPUT_PULLUP);   // 上拉输入：松开是 1，按下是 0
}

void loop() {
  if (digitalRead(5) == LOW) {
    digitalWrite(4, LOW);
  } else {
    digitalWrite(4, HIGH);
  }
  delay(50);
}
```

注意代码的大括号层级——**积木套了几层，代码就嵌套几层，一一对应**。

这段代码只读、不能编辑，也不需要看懂。它的用途就一个：出问题时你能知道板子到底在执行什么，而不是面对一个黑盒。

## 检查清单

- [ ] 右上角开发板是 `ESP32S3 Dev Module`，串口窗口右下角波特率是 `9600`
- [ ] 能在左边找到「输入/输出」「控制」「串口」这三个分类
- [ ] 能独立拼出「按键控制灯」并上传成功，灯不会乱闪
- [ ] 知道积木是从上往下翻译成代码的，摆不对代码就一定错
