# QS-6 ADC 与 DAC

**时长 60 分钟 · 产出：旋电位器改变 PWM 蜂鸣器音调，串口实时曲线**

## ADC 是什么

ADC（模数转换器）把电压变成数字。ESP32-S3 的 ADC 是 12 位，量程对应读数 `0 ~ 4095`。

| 项目 | 值 |
| --- | --- |
| 分辨率 | 12 bit（4096 级） |
| 可用通道 | ADC1_CH0～CH9（GPIO1～10）、ADC2_CH0～CH9（GPIO11～20） |
| 衰减档位 | 默认 11dB 档满量程约 **3.1V**（超过会被截断成 4095）；小量程档位读数更细，精确范围见乐鑫 ADC 文档 |

```cpp
int raw = analogRead(1);          // 0 ~ 4095
float volt = raw * 3.3 / 4095.0;  // 粗略换算
```

## ⚠️ 三个必踩的坑

### 坑 1：WiFi 开着时 ADC2 不能用

这是 ESP32 系列的经典问题：ADC2 与 WiFi 共用硬件，一开 WiFi 读 ADC2 就会失败或返回 0。

对策：**永远优先用 ADC1（GPIO1～GPIO10）**。如果非要用 ADC2，必须在操作时 `esp_wifi_internal_pause`/恢复，或者干脆换脚。

### 坑 2：读数不是线性的

ADC 有增益误差和偏置，esp32 Arduino 3.x 已经内置了校准补偿（`analogSetPinAttenuation` + 自动校准），但不同电压点误差仍然存在。做精确测量（比如测电池电压）需要多点校准。

### 坑 3：没加延时会读到毛刺

采样和电压稳定需要时间。快速连读会跳变。

## 积木实战：电位器调亮度（先做这个）

从上到下这样拼，旋电位器，LED 亮度跟着变：

```text
Serial 打印 自动换行 <模拟输入 管脚# 1>          ← 读数直接嵌进打印
模拟输出 管脚# 5 赋值为 <映射 整数 <模拟输入 管脚# 1> 从 [0, 4095] 到 [0, 255]>
延时 100 毫秒
```

| 积木 | 在哪个分类 | 说明 |
| --- | --- | --- |
| 模拟输入 管脚# 1 | 输入/输出 | 接电位器中点（ADC1 从 GPIO1 开始，避开 WiFi 冲突） |
| 模拟输出 管脚# 5 赋值为 | 输入/输出 | 这就是 PWM 调光，0～255 |
| 映射 整数 … 从 … 到 … | 数学 | 把 0～4095 的读数压到 0～255 |

:::warning[接线]
电位器两边脚接 3.3V 和 GND，中间脚（输出）接 GPIO1。LED 还是 GPIO4 → 220Ω → LED → GND，把上面拓扑里的模拟输出管脚改成 4。
:::

## 进阶对照：无源蜂鸣器调音调

调音调 = 改 PWM 频率，比调亮度多一步换算。积木里用「执行器 → 播放声音」把频率槽接上映射结果也能做；对照代码是这么写的（不用抄）：

```cpp
#include <Arduino.h>

const int POT_PIN = 1;    // ADC1_CH0 → 电位器中点
const int BUZZ_PIN = 5;   // PWM 输出 → 无源蜂鸣器

void setup() {
  Serial.begin(9600);

  // 关键：设置采样精度和衰减范围
  analogReadResolution(12);         // 12 位（Arduino 3.x 默认就是 12 位，写出来更明确）
  analogSetPinAttenuation(POT_PIN, ADC_11db);   // 满量程放到 ~3.1V

  ledcAttach(BUZZ_PIN, 2000, 10);   // 一步绑定引脚：初始 2kHz，10 位分辨率（core 3.x API）

  Serial.println("旋转电位器，听蜂鸣器音调变化");
}

void loop() {
  static unsigned long last = 0;
  if (millis() - last < 100) return;   // 10Hz 刷新，别刷太快
  last = millis();

  int raw = analogRead(POT_PIN);
  float volt = raw * 3.3f / 4095.0f;

  // 把 0~4095 映射到 200Hz~5000Hz 的音调
  int freq = map(raw, 0, 4095, 200, 5000);
  ledcWriteTone(BUZZ_PIN, freq);    // 按引脚改频率，让蜂鸣器变调

  Serial.printf("raw=%4d  volt=%.2fV  freq=%4dHz\n", raw, volt, freq);
}
```

:::warning[有源 vs 无源蜂鸣器]
- **无源蜂鸣器**：只有给它方波才响，需要 PWM/LEDC 驱动（上面的代码）
- **有源蜂鸣器**：给高电平就响，`digitalWrite(HIGH)` 即可，但**不能调音调**

搞混了的表现：无源蜂鸣器接 `digitalWrite` 完全不响；有源蜂鸣器接 PWM 会发出难听的"咔咔"声。
:::

## 滤波：让读数稳定下来

原始读数抖动是正常的。积木里最简单的办法是用「数学 → 约束」把读数限在一个合理区间，抖动就影响不了输出：

```text
模拟输出 管脚# 4 赋值为 <映射 整数 <约束 <模拟输入 管脚# 1> 介于最小值 200 和最大值 3800> 从 [0, 4095] 到 [0, 255]>
```

代码里用滑动平均或中值滤波，写法见 [L4 · ADC](../course/l4-peripherals/adc-dac)。DHT11 这类数字传感器不需要滤波，它们的协议已经处理好了。

## 「DAC」：先泼一盆冷水

:::danger[ESP32-S3 没有 DAC]
真正的数模转换器（DAC）是**经典 ESP32** 才有的硬件（在 GPIO25/26）。**ESP32-S3 上没有**——`dacWrite()` 和米思齐里的「DAC输出」积木在 S3 上都不会有输出，别浪费半天排查。
:::

S3 上要"输出模拟电压"，两条路：

| 方案 | 怎么做 | 适合 |
| --- | --- | --- |
| PWM + 低通滤波 | 「模拟输出」积木输出 PWM，后面接电阻+电容滤成平滑电压 | 调光、调速这类对波形不敏感的场合 |
| 外接 DAC 模块 | MCP4725 之类，走 I2C（见 [QS-8](./bus)） | 需要真模拟输出的场合 |

经典 ESP32 板子上的 `dacWrite(25, 128)`（0～255 ≈ 0～3.3V）才有用；即便那样它也是 8 位、驱动能力弱、频率上不去，要真波形走 [I2S](../course/l4-peripherals/audio)。

## 常见坑

| 现象 | 原因 |
| --- | --- |
| 读数一直是 0 | 接错到 ADC2 且 WiFi 已开；或引脚没接对 |
| 读数一直是 4095 | 引脚悬空，或超量程被截断 |
| 读数跳变严重 | 没滤波，或采样太快，或电源不稳 |
| 蜂鸣器不响 | 接了有源蜂鸣器却用 PWM；或没接驱动电路 |
| 读数范围只有一半 | 衰减档位设成了 `ADC_2_5db` 之类的小量程 |
