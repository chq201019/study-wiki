# QS-8 总线：I2C / UART

**时长 60 分钟 · 产出：OLED 上显示数据**

:::tip[串口波特率]
所有示例程序里的串口都初始化成 9600（米思齐的默认值）。
在米思齐里点开串口窗口，把右下角的波特率也选成 `9600`，两边不一致串口就是乱码。
:::

模块之间说话靠总线。快速上手只教两个最常用的：**I2C**（接屏幕、传感器，两根线）和 **UART**（接 GPS、读卡器这类串口模块）。SPI 和 SD 卡这些写代码才用得多，去 [L4 · 总线](../course/l4-peripherals/i2c-spi-uart) 再学。

| 总线 | 线数 | 典型用途 |
| --- | --- | --- |
| **I2C** | 2（SDA/SCL）+ GND | OLED、RTC、温湿度、IMU，可挂多个设备 |
| **UART** | 2（TX/RX）+ GND | GPS、读卡器、串口屏，点对点 |

## I2C

### 默认引脚（S3）

| 信号 | GPIO |
| --- | --- |
| SDA | 8 |
| SCL | 9 |

### 实战：OLED 显示屏（积木版）

OLED 用积木反而比代码省事——不用装任何库，米思齐内置了：

```text
初始化
  └─ 初始化 SSD1306(128×64) 屏幕 SCL 9 SDA 8 设备地址 0x3C    ← 「显示器 → OLED显示屏」子分类
新建 page1 页面（紫色帽子积木，要显示的内容都在它里面）
  └─ 显示 文本 内容 "ESP32-S3" 起点x 0 起点y 0
显示 刷新页面（执行 page1）
延时 3000 毫秒
```

| 积木 | 在哪个分类 | 说明 |
| --- | --- | --- |
| 初始化 SSD1306 | 显示器 → OLED显示屏 | SCL=9、SDA=8 就是上面的默认引脚，地址一般是 0x3C |
| page1 帽子积木 | 显示器 → OLED显示屏 | 相当于"一页画面"，文本/数字积木往里摆 |
| 显示 刷新页面 | 显示器 → OLED显示屏 | 每次刷新执行一页 |

接线四根：VCC→3.3V，GND→GND，SCL→GPIO9，SDA→GPIO8。

想显示传感器读数，把 page1 里的文本内容换成拼接积木咬上「模拟输入」就行。

### I2C 排错：地址不对是 90% 的原因

设备不响应时**别猜地址**：模块丝印或卖家页面一般写着；常见值速查——

| 设备 | 地址 |
| --- | --- |
| SSD1306 OLED | `0x3C`（少数 `0x3D`） |
| AHT10/AHT20 温湿度 | `0x38` |
| BME280 | `0x76` 或 `0x77` |
| MPU6050 IMU | `0x68` 或 `0x69` |
| DS3231 RTC | `0x68` |

还不行就按顺序查：① SDA/SCL 有没有接反 ② 3.3V 供电 ③ 有的模块需要自己加上拉电阻（4.7kΩ）。写代码时可以跑一次"地址扫描器"把所有设备扫出来，代码见 [L4 · 总线](../course/l4-peripherals/i2c-spi-uart)。

## UART：接 GPS 这类串口模块

调试用的 `Serial`（GPIO43/44）永远留着看日志；接外部模块用 Serial1，**引脚自己指定**，避开 35/36/37 和 43/44：

```text
<Serial1 有数据可读吗？> 执行 → 读出来打到 Serial 打印     ← 把模块的数据转上看
延时 10 毫秒
```

:::danger[两个"串口"别搞混]
`Serial` 是调试日志口（GPIO43/44），永远用这个看日志；Serial1/2 是接外部模块的。混用的表现：日志打不出来，或者模块数据里全是乱码。
:::
